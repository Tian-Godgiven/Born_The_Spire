# 状态实现场景手册

面向 AI 与 Mod 开发者的场景式教程。想实现某种状态（buff / debuff / 计数标记），先在本手册找相似场景，复制模板，改数值和描述。

本手册与《状态系统开发指南》的分工：
    状态系统开发指南 — StateData 字段完整语义、stackChange 详细行为
    本手册 — 我要做出「XX 类型的状态」，具体数据怎么写

---

## 使用方法

每个场景包含：
    目标 — 一句话说清楚要实现什么
    涉及机制 — 用到哪些系统
    数据模板 — 完整可复制的 StateData 定义
    常见变体 — 数值/条件小改
    相关文档 — 需要延伸阅读时的入口

场景可自由组合：turnEnd 衰减 + turnEnd 造成伤害 + allowNegative = 会变负数的中毒。

## 场景 1：简单增减伤 debuff（虚弱 / 易伤）

目标
    施加时不产生一次性效果，只影响持有者后续伤害计算。回合结束自动 -1 层。

涉及机制
    interaction.possess.triggers — 在事件的伤害修饰阶段介入
    reaction 段 — 用 `modifyDamageByPercent` / `modifyDamageValue` 改数值
    stackChange — 自动衰减

数据模板

```typescript
{
    label: "虚弱",
    key: "weak",
    category: "debuff",
    describe: ["造成的伤害减少 25%"],
    showType: "number",
    repeate: "stack",
    stackChange: [
        { timing: "turnEnd", delta: -1 }
    ],
    interaction: {
        possess: {
            triggers: [{
                when: "before",
                how: "make",
                key: "damage",
                action: "weakDebuff"
            }],
            reaction: {
                weakDebuff: [{
                    key: "weakDebuff",
                    label: "虚弱减伤",
                    targetType: "triggerEffect",
                    effect: [{
                        key: "modifyDamageByPercent",
                        params: { percent: -0.25 }
                    }]
                }]
            }
        }
    }
}
```

常见变体

    易伤（受到伤害 +50%）：`how` 改 `"take"`，`percent` 改 `+0.5`
    绝对值减伤：`modifyDamageByPercent` 换成 `modifyDamageValue`，`params: { delta: -2 }`
    不衰减：删掉 stackChange
    每回合衰减 2 层：`delta: -2`

要点
    `how: "make"` 表示持有者是攻击方（自己造成伤害时触发）
    `how: "take"` 表示持有者是承受方
    `targetType: "triggerEffect"` 表示修改触发事件本身的效果参数

## 场景 2：每回合造成伤害（中毒 / 燃烧）

目标
    回合结束时对持有者造成等于层数的伤害。

涉及机制
    turnEnd 事件触发
    `$source.stateStack()` 引用当前状态层数

数据模板

```typescript
{
    label: "中毒",
    key: "poison",
    category: "debuff",
    describe: ["回合结束时受到等量伤害"],
    showType: "number",
    repeate: "stack",
    stackChange: [
        { timing: "turnEnd", delta: -1 }
    ],
    interaction: {
        possess: {
            triggers: [{
                when: "before",
                how: "take",
                key: "turnEnd",
                action: "poisonDamage"
            }],
            reaction: {
                poisonDamage: [{
                    key: "poisonDamage",
                    label: "中毒伤害",
                    targetType: "triggerOwner",
                    effect: [{
                        key: "damage",
                        params: { value: "$source.stateStack()" }
                    }]
                }]
            }
        }
    }
}
```

常见变体

    燃烧（无视护甲）：`damage` 换成 `loseHp`
    不衰减：删掉 stackChange，层数固定
    衰减为 -2：慢性毒（每回合减 2 层）
    造成伤害后消耗自身：reaction 里再加一条 `{ key: "removeState", params: { stateKey: "poison" } }`

要点
    先衰减还是先造成伤害由 `when: "before" | "after"` 与 stackChange 的顺序决定，参考已有中毒实现

## 场景 3：造成伤害增益（力量 / 敏捷类 buff）

目标
    造成伤害时增加固定数值，允许被削弱到负数。

涉及机制
    triggers `when: "before"` + `how: "make"` + `key: "damage"`
    reaction 用 `modifyDamageValue`
    `allowNegative: true` 允许层数为负

数据模板

```typescript
{
    label: "力量",
    key: "power",
    category: "buff",
    describe: ["造成的伤害 +当前层数"],
    showType: "number",
    repeate: "stack",
    allowNegative: true,
    interaction: {
        possess: {
            triggers: [{
                when: "before",
                how: "make",
                key: "damage",
                action: "powerBoost"
            }],
            reaction: {
                powerBoost: [{
                    key: "powerBoost",
                    label: "力量增伤",
                    targetType: "triggerEffect",
                    effect: [{
                        key: "modifyDamageValue",
                        params: { delta: "$source.stateStack()" }
                    }]
                }]
            }
        }
    }
}
```

常见变体

    敏捷（受到伤害 -N）：`how` 改 `"take"`，`delta: "-$source.stateStack()"`
    百分比增伤：`modifyDamageByPercent`，`percent: "$source.stateStack() * 0.1"`
    每回合结束消失：加 `stackChange: [{ timing: "turnEnd", delta: "all" }]`

要点
    `allowNegative: true` 使力量可以被虚弱、削弱之类的效果打到负数
    不加 allowNegative 时，层数最低为 0，扣到 0 后状态被自动移除

## 场景 4：无层数标记（壁垒 / 完美体）

目标
    只表示「有 / 无」，不显示层数。存在时干预某种行为。

涉及机制
    `showType: "bool"` — UI 不显示数字
    `cancelEvent: true` — 直接阻止事件发生

数据模板

```typescript
{
    label: "壁垒",
    key: "barricade",
    category: "buff",
    describe: ["护甲不在回合开始时消失"],
    showType: "bool",
    repeate: "stack",
    interaction: {
        possess: {
            triggers: [{
                when: "before",
                how: "take",
                key: "clearArmor",
                cancelEvent: true
            }]
        }
    }
}
```

常见变体

    Buff 阻挡：拦截 `applyState` 的 debuff 事件（参考「神器」类实现）
    带层数的阻挡（消耗式）：`showType` 保持 `"number"`，改用 `action` + reaction，在 reaction 里调 `removeState` 或 `changeStateStack`

要点
    `cancelEvent: true` 是一次性直接阻止，不需要 reaction 段
    `showType: "bool"` 与 stacks 的实际值分离，可以有内部计数只是不显示

## 场景 5：每回合自动衰减 / 增长

目标
    状态层数随时间自动变化，无需外部触发。

涉及机制
    stackChange 数组

数据模板：回合结束 -1

```typescript
stackChange: [
    { timing: "turnEnd", delta: -1 }
]
```

数据模板：回合开始 +2

```typescript
stackChange: [
    { timing: "turnStart", delta: 2 }
]
```

数据模板：战斗结束清空

```typescript
stackChange: [
    { timing: "battleEnd", delta: "all" }
]
```

数据模板：多规则组合

```typescript
stackChange: [
    { timing: "turnStart", delta: 1 },   // 每回合开始 +1
    { timing: "turnEnd", delta: -1 }     // 回合结束 -1（净变化 0，但可以配合其他触发器）
]
```

timing 可选值
    `turnStart` / `turnEnd` — 玩家/敌人回合切换
    `battleStart` / `battleEnd` — 战斗生命周期

delta 特殊值
    数字 — 增减层数（可正可负）
    `"all"` — 清零

## 场景 6：一次性触发消耗（双发 / 蓄势）

目标
    满足某种条件时触发一次强化，消耗自身层数。

涉及机制
    triggers → reaction → 由效果内部调 `consumeStateKey`
    某些效果本身就带消耗参数（如 `modifyRepeat`）

数据模板

```typescript
{
    label: "双发",
    key: "doubleTap",
    category: "buff",
    describe: ["下一张攻击牌打出两次"],
    showType: "number",
    repeate: "stack",
    stackChange: [
        { timing: "turnEnd", delta: "all" }
    ],
    interaction: {
        possess: {
            triggers: [{
                when: "before",
                how: "make",
                key: "useCard",
                action: "doubleTapRepeat"
            }],
            reaction: {
                doubleTapRepeat: [{
                    key: "doubleTapRepeat",
                    label: "双发",
                    targetType: "triggerEffect",
                    effect: [{
                        key: "modifyRepeat",
                        params: {
                            requiredTag: "attack",
                            addRepeat: 1,
                            consumeStateKey: "doubleTap"
                        }
                    }]
                }]
            }
        }
    }
}
```

常见变体

    只对特定 tag 触发：`requiredTag` 换成其他 tag
    每次消耗多层：`consumeStateKey` 之外另加 `changeStateStack` 效果，负值扣多层

要点
    `consumeStateKey` 是 effect 内部参数，不需要单独写 removeState
    如果没有 stackChange，效果不消耗时状态会一直存在（可能是 bug 也可能是设计）

## 场景 7：回合结束时自动移除（临时 buff）

目标
    只在本回合生效的临时增益 / 减益。

涉及机制
    stackChange delta: "all" 清空
    或用 apply/remove 定义添加/移除时的一次性效果

数据模板：简单版

```typescript
{
    label: "临时护甲",
    key: "tempArmor",
    describe: ["本回合结束时消失"],
    stackChange: [
        { timing: "turnEnd", delta: "all" }
    ]
}
```

数据模板：临时力量（复杂版 — 消失时同时移除对应力量）

```typescript
{
    label: "临时力量",
    key: "tempPower",
    describe: ["回合结束时失去等量力量"],
    showType: "number",
    repeate: "stack",
    allowNegative: true,
    interaction: {
        possess: {
            triggers: [{
                when: "after",
                how: "take",
                key: "turnEnd",
                action: "removeTempPower"
            }],
            reaction: {
                removeTempPower: [{
                    key: "removeTempPower",
                    label: "移除临时力量",
                    targetType: "triggerOwner",
                    effect: [
                        {
                            key: "changeStateStack",
                            params: {
                                stateKey: "power",
                                delta: "$source.stateStack()",
                                negate: true
                            }
                        },
                        { key: "removeState", params: { stateKey: "tempPower" } }
                    ]
                }]
            }
        }
    }
}
```

要点
    简单版单靠 stackChange 就够
    复杂版需要级联移除另一个 state（本身层数用完前先扣掉对应 power）

## 场景 8：应用时 / 移除时的一次性效果

目标
    获得状态的瞬间做一件事，或失去状态的瞬间做另一件事。

涉及机制
    interaction.apply / interaction.remove

数据模板

```typescript
{
    label: "圣光庇护",
    key: "holyShield",
    category: "buff",
    interaction: {
        apply: {
            effects: [{ key: "gainArmor", params: { value: 5 } }]
        },
        remove: {
            effects: [{ key: "heal", params: { value: 3 } }]
        },
        possess: {
            // 持续期的触发器
        }
    }
}
```

要点
    apply 只在层数从 0 变为正数时执行一次，重复获得同状态不会重复触发
    remove 只在层数变为 0 时执行
    大多数状态用不到这两段，只有需要「触点效果」时才写

## 场景 9：器官内部状态（无 interaction）

目标
    只作为计数存储，逻辑由持有它的器官在 EffectFunc 中处理。

涉及机制
    只定义基本字段，interaction 留空
    器官通过专属效果（如 `organ_heatTick`）操作它

数据模板

```typescript
{
    label: "热量",
    key: "heat",
    category: "debuff",
    describe: ["热量超过 3 时引发爆炸"],
    showType: "number",
    repeate: "stack"
}
```

在 EffectFunc 里操作这类状态

```typescript
import { gainStateStack } from "@/core/objects/system/State"
import { getStateModifier } from "@/core/objects/system/modifier/StateModifier"

// 加层数：目标还没有该状态时自动创建，已有时按 repeate 规则叠加
gainStateStack(target, "heat", 1, event.medium)

// 读层数
const stateModifier = getStateModifier(target)
const heat = stateModifier.getState("heat")?.stacks.find(s => s.key === "default")?.stack ?? 0

// 清空
stateModifier.removeState("heat")
```

要点
    不写 interaction — 逻辑走器官的 EffectFunc 而不是状态自身触发
    命名可以带前缀方便识别，如 `heat_organ_forge`，但通用状态用短 key
    这类状态一般只在特定器官装备时出现，其他地方不会互动
    加层数必须用 `gainStateStack`，不能用 `stateModifier.changeStack`（见常见错误 8）
    内部计数标记同样要在 stateList 注册（见常见错误 9），并且玩家在状态浮层里看得见它，
    label 和 describe 要写成玩家读得懂的话，而不是内部变量名
    `gainStateStack` 是同步的，加完可以立刻读层数判断阈值；换成 `applyState` 效果则要等事务执行，
    同一个 EffectFunc 内后续读到的还是旧值

相关文档
    参考/效果开发指南.md — 器官专属效果命名规范

## 场景 10：条件触发的状态

目标
    状态存在但只在满足条件时触发效果。例如「敌人身负 X 时才触发」。

涉及机制
    triggers 的 `condition` 字段
    `requirePositiveEffect: true`（当伤害或效果值 > 0 时才触发）

数据模板

```typescript
{
    label: "劲敌之怒",
    key: "nemesisRage",
    category: "buff",
    describe: ["对满血敌人造成伤害时 +5"],
    showType: "number",
    repeate: "stack",
    interaction: {
        possess: {
            triggers: [{
                when: "before",
                how: "make",
                key: "damage",
                action: "rageBoost",
                condition: "$target.hpPercent >= 1.0"
            }],
            reaction: {
                rageBoost: [{
                    key: "rageBoost",
                    label: "劲敌之怒",
                    targetType: "triggerEffect",
                    effect: [{
                        key: "modifyDamageValue",
                        params: { delta: 5 }
                    }]
                }]
            }
        }
    }
}
```

要点
    condition 是字符串表达式，语法见《实现参考手册》
    `requirePositiveEffect: true` 常用于只在真的造成正伤害时触发，避免 damage 为 0 的边缘情况

## 常见错误与修正

错误 1：状态触发写在效果层
    错：在卡牌 effect 里写「若目标有 X 则额外触发」的复杂逻辑
    对：把该逻辑放在状态自身的 triggers/reaction 中，卡牌只负责施加状态

错误 2：对着 state.stacks 直接改
    错：手写代码 `state.stacks -= 1`
    对：走 `changeStateStack` 或 `removeState` 效果，让事件系统清理

错误 3：allowNegative 未开导致 buff 无法被削弱
    症状：给力量施加 -2 时，力量停在 0 而不是变成 -2
    修复：`allowNegative: true`

错误 4：showType: "bool" 但依赖层数逻辑
    如果代码里依赖 stacks 值，UI 却不显示层数，玩家会看不到状态强弱
    要么统一用 number，要么确保 bool 状态真的只是标记

错误 5：triggers 的 how 用错
    造成伤害的一方要用 `"make"`，承受一方用 `"take"`
    中毒是自己给自己造伤害？— 通过 damage 事件，持有者作为 target，写 `"take"`

错误 6：忘了 stackChange 导致 debuff 永不消失
    虚弱 / 易伤这类应该有 `[{ timing: "turnEnd", delta: -1 }]`
    没写时 debuff 会一直挂着直到战斗结束

错误 7：reaction 引用了未定义的 action 名
    triggers 中 `action: "myAction"`，reaction 段必须有对应 key
    否则触发时找不到 reaction，效果沉默失效

错误 8：用 changeStack 给目标加一个它还没有的状态
    错：`getStateModifier(target).changeStack("heat", "default", 1)`
    症状：日志照常打出「热量 +1」，状态浮层里却始终没有热量，整套机制像是完全没接上
    原因：`StateModifier.changeStack` 开头就是 `if (!this.getState(stateKey)) return false`，
          它只负责改已存在状态的层数，不会从 0 创建；目标第一次获得该状态时直接静默失败，
          之后永远不会有这个状态
    对：代码里用 `gainStateStack(target, stateKey, delta, source)`（没有则创建，有则叠加）
        数据层用 `applyState` 效果 —— 走事件系统，能被拦截型触发器（如剧毒心核给 poison 加层）捕获
    changeStack 本身没有问题，用它减层数、改已有层数是正确用法，不要去改它的语义

错误 9：状态没在 stateList 注册就直接使用
    症状：`getState("xxx")` 恒为 undefined，靠它实现的「每回合只触发一次」这类限制彻底失效，
          表现是效果每次都触发，而不是报错
    原因：`gainStateStack` 和 `applyState` 都要按 key 从 stateList 查 StateData，查不到就无法创建状态
    对：任何状态 key 都先在 `static/list/target/stateList.ts` 注册，纯内部计数标记也不例外

## 快速对照表

想实现的状态类型 → 场景编号

    简单增减伤 debuff → 1
    每回合造成伤害 → 2
    造成伤害增益（力量类）→ 3
    无层数标记（壁垒类）→ 4
    只是每回合衰减/增长 → 5
    满足条件消耗一次 → 6
    只在本回合有效 → 7
    获得/失去时的一次性效果 → 8
    器官内部计数 → 9
    有触发条件 → 10
