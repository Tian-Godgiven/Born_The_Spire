# 效果实现场景手册

面向 AI 与 Mod 开发者的场景式教程。想在数据里写一个效果链（`effect: [...]` 数组或 `effects: [...]` 数组），先在本手册里找相似场景，复制模板，改数值和描述。

本手册与其他文档的分工
    参考/效果开发指南.md — 三层效果分类（原子/复合/专属）、命名规范、决策流程
    参考/实现参考手册.md — `$` 引用表达式的完整可用变量清单
    src/static/list/system/effectMap.ts — 所有已注册效果的权威清单
    本手册 — 我要实现「某个具体的效果链」，数据长什么样

---

## 使用方法

每个场景包含
    目标 — 一句话说清楚要产生什么效果
    涉及机制 — 用到哪些 EffectFunc、依赖哪些参数
    数据模板 — 完整可复制的 effect 数组片段
    常见变体 — 数值 / 参数小改
    要点 — 容易混淆或踩的坑

「effect 数组」在触发器 reaction 里叫 `effect`，在卡牌 use / possess 交互里叫 `effects`——名字有分歧但结构一样，都是 `EffectUnit[]`：

```typescript
{ key: "effectFuncKey", params: { ... } }
```

## 场景 1：单一原子效果（最基础）

目标
    「造成 5 点伤害」「回复 8 点生命」「获得 3 点护甲」——一次只做一件事。

涉及机制
    去 `effectMap.ts` 找对应的原子效果 key
    翻 `src/core/effects/<分类>/xxx.ts` 找它接受哪些 params
    填一个 `{ key, params }` 就完事

数据模板

```typescript
// 造成伤害
[{ key: "damage", params: { value: 5 } }]

// 回血
[{ key: "heal", params: { value: 8 } }]

// 获得护甲
[{ key: "gainArmor", params: { value: 3 } }]

// 施加 2 层中毒
[{ key: "applyState", params: { stateKey: "poison", stacks: 2 } }]

// 抽 1 张牌
[{ key: "drawFromDrawPile", params: { value: 1 } }]

// 获得 5 点金币
[{ key: "gainReserve", params: { reserveKey: "gold", amount: 5 } }]
```

常见变体
    只改数值：换 `value`
    换状态类型：换 `stateKey`（poison / bleed / weak / vulnerable / power / dexterity …）
    减少数值：某些 effect 用负数（如 `addStatusBase value: -2`），有些效果不接受负数、要用专门的反义 effect（如 `removeState`）

要点
    数值型效果通常用 `value`；施加状态用 `stackChange` 或 `stacks`（视 EffectFunc 而定）；金币用 `amount + reserveKey`
    不确定参数时打开 `src/core/effects/<分类>/xxx.ts`，注释里通常列了 params
    在 effectMap 里找不到的 key = 没注册 = 数据里写了也不会执行

## 场景 2：一次多效果（顺序执行）

目标
    「打伤害 + 施加流血 + 抽 1 张」——一次动作做多件事。

涉及机制
    EffectUnit 数组里放多个 `{ key, params }`，**顺序执行**
    数组是同一次 doEvent 的载荷，一起走 before/after 触发周期
    如果要不同 target，一般把每个动作**拆成独立的 reaction event**（见触发器手册场景 3），而不是塞到同一个 effect 数组

数据模板：普通攻击卡

```typescript
{
    label: "毒攻",
    key: "card_poison_strike",
    describe: ["造成 6 点伤害", "施加 2 层流血"],
    interaction: {
        use: {
            target: { faction: "enemy" },
            effects: [
                { key: "damage", params: { value: 6 } },
                { key: "applyState", params: { stateKey: "bleed", stacks: 2 } }
            ]
        }
    }
}
```

常见变体
    重复同一效果 N 次：用 `repeatEffects` 而不是复制 N 份数据

```typescript
[{
    key: "repeatEffects",
    params: {
        count: 3,
        effects: [{ key: "damage", params: { value: 4 } }]
    }
}]
```

    做完 A 再判断做 B：拆成两个 event 或用 condition（见触发器手册场景 5）

要点
    同一数组内的 effect 都作用于同一个 `event.target`，如果这次是"对敌人打伤害 + 给自己抽卡"这种跨方，**必须**拆成不同 reaction event
    数组顺序 = 执行顺序，靠前的效果修改的状态在后面可见（例如先加护甲再算减伤）
    如果一个 effect 里 target 是 `Entity[]`（AOE），后面的 effect 也会对整个数组作用

## 场景 3：动态数值（`$` 引用表达式）

目标
    「造成的伤害等于当前生命上限的 10%」「回血量等于本次受到的伤害」「护甲量按力量层数」——参数是动态计算的，不是常量。

涉及机制
    在 params 的值位置写 `"$xxx"` 字符串，会被 ReferenceResolver 解析
    可用引用（完整清单见 `参考/实现参考手册.md`）
        `$owner.status(key)` — 持有者的 status 值
        `$owner.current(key)` — 持有者的当前值（health/energy/mass）
        `$owner.stateStack(key)` — 状态层数
        `$source.xxx` `$medium.xxx` `$target.xxx` — 事件三方的对应属性
        `$triggerEffect.params(key)` — 引发本次触发的 Effect 的 params 字段
        `$eventInfo.key` — 事件 info 字段（例如 `$eventInfo.turn`）
        `$eventResult.key` — 事件返回结果
        `$battle.turn` — 当前回合数
        `$scene` — 当前场景（combat/map 等）
        `random(min, max)` — 随机整数

数据模板：反射护甲（受伤时反弹相同数值伤害给对方）

```typescript
reaction: {
    reflect: [{
        targetType: "eventSource",
        key: "damage",
        effect: [{
            key: "damage",
            params: { value: "$triggerEffect.params(value)" }
        }]
    }]
}
```

数据模板：伤害按力量层数

```typescript
[{
    key: "damage",
    params: { value: "$owner.stateStack(power) * 2 + 5" }
}]
```

数据模板：回血 = 生命上限的 10%

```typescript
[{
    key: "heal",
    params: { value: "$owner.status(maxHealth) * 0.1" }
}]
```

常见变体
    带算术：`$owner.status(x) + 3` `$x * 2` 都支持
    带条件回退：写成两个 effect + 分别 condition，别在 `$` 里写三元
    随机数：`random(1, 6)` 会用当前战斗种子

要点
    `$` 引用**必须写成字符串**：`{ value: "$owner.stateStack(power)" }`，不能写 `{ value: $owner... }`（那是 JS 变量）
    accessor 后面**必须有括号**：`$owner.status(health)`——`$owner.status.health` 不识别
    accessor 只支持 effectMap 已知的一批（`status/current/stateStack/hasStatus/hasState/hasOrgan/hasRelic/hasCard/hasTag/reserve/pileCount/itemType`），要新加访问器改 `EntityAccessor.ts`
    引用的求值时机是**创建 Effect 时**——如果需要"延迟到执行时才算"，改用 EffectFunc 里读当前值

## 场景 4：影响牌堆 / 手牌

目标
    「抽 1 张牌」「弃掉手牌 X」「洗弃牌堆进抽牌堆」「塞一张特定卡进手牌」「消耗手牌里所有 X 卡」——操作 Player.cardPiles。

涉及机制
    抽卡：`drawFromDrawPile` value=n（不够就洗弃牌堆）
    弃牌：`discard` `chooseHandCardDiscard`（玩家选）`discardAllCard`（全弃）
    消耗：`voidExhaust` `pay_exhaust`（作为费用消耗某张卡）
    洗牌：`shuffleDiscardIntoDraw`
    塞牌：`addCardToHand`（cardKey + count） / `addRandomCardsToPile` / `stuffCard`
    移动：`retrieveCardsToHand`（从其他堆拿回手牌） / `moveInherentToHand`

数据模板：塞 2 张"打击"进手牌

```typescript
[{
    key: "addCardToHand",
    params: {
        cardKey: "original_card_strike",
        count: 2
    }
}]
```

数据模板：抽 2 张、洗弃牌堆进抽牌堆、再抽 1 张

```typescript
[
    { key: "drawFromDrawPile", params: { value: 2 } },
    { key: "shuffleDiscardIntoDraw" },
    { key: "drawFromDrawPile", params: { value: 1 } }
]
```

数据模板：玩家自选弃 1 张

```typescript
[{ key: "chooseHandCardDiscard", params: { count: 1 } }]
```

常见变体
    塞到抽牌堆而不是手牌：换成 `stuffCard` 并指定 pileName
    按 tag 消耗随机卡：`exhaustRandomCardByTag` + tag 参数
    加临时卡（本战有效）：`addTemporaryCard`（本战结束自动消失）

要点
    `addCardToHand` 的 `cardKey` 必须是 `cardList.ts` 里注册过的 key，写错静默无效（会在 console error）
    弃牌与消耗的区别：弃 = 进 discardPile，回合结束不会消失；消耗 = 进 exhaustPile，本战不能再抽到
    "本战有效的临时卡"用 `addTemporaryCard`，别用 `addCardToHand`（后者是永久加入牌组）——两者语义不同

## 场景 5：影响 status（永久属性）

目标
    「生命上限 +5」「初始能量 +1」「首回合抽牌数 +2」——改的是属性上限、初始值这类常量。

涉及机制
    `addStatusBase` — 加/减基础属性值（base 层，永久）
    `setBaseStatus` — 直接设置基础属性值
    `addStatusCurrent` — 改当前的即时值（不修改 base）
    `setCurrentToMax` — 当前值拉满
    `addCurrent` — 改 current（例如加能量、扣生命）
    `addMaxHealthAndHeal` — 加生命上限并回满（常见）
    `addFirstTurnDraw` — 改首回合抽牌数
    `decrementStatus` / `multiplyStatusBase` — 计数递减、倍率变更

数据模板：初始能量 +1（存活到战斗内）

```typescript
[{ key: "addStatusBase", params: { key: "maxEnergy", value: 1 } }]
```

数据模板：生命上限 +8 并回满

```typescript
[{ key: "addMaxHealthAndHeal", params: { value: 8 } }]
```

数据模板：首回合额外抽 2 张

```typescript
[{ key: "addFirstTurnDraw", params: { value: 2 } }]
```

常见变体
    负值削弱：`{ value: -2 }` 减基础属性
    临时改：用 `addStatusModifier`（带 duration，见 StatusModifier）
    需要 setter 语义（直接赋值）：`setBaseStatus`

要点
    base 层是"永久"改动，不会被 modifier 清理逻辑撤销
    如果这个 status 是**遗物/器官提供的**（挂在 modifier 上）——**别**用 `addStatusBase`，用 `addStatusModifier` 让它随物品一起自动清理
    改 status 与改 current 的区别：status 是上限/常量（例如 maxHealth），current 是当前值（例如 health）——想回血是改 current

## 场景 6：影响 state（施加/移除状态）

目标
    「施加 3 层流血」「移除所有虚弱」「层数 +2」——操作 buff/debuff。

涉及机制
    `applyState` — 施加状态，stackChange 层数
    `removeState` — 移除状态
    `changeStateStack` — 修改现有状态层数（不新加）

数据模板：施加流血 3 层

```typescript
[{
    key: "applyState",
    params: { stateKey: "bleed", stacks: 3 }
}]
```

数据模板：移除所有虚弱

```typescript
[{
    key: "removeState",
    params: { stateKey: "weak" }
}]
```

数据模板：现有流血层数 +2（如果没有则不加）

```typescript
[{
    key: "changeStateStack",
    params: { stateKey: "bleed", change: 2 }
}]
```

常见变体
    对 event.source 施加（比如"你被打时反弹 debuff"）：写在 reaction 里、`targetType: "eventSource"`
    动态层数：`stacks: "$owner.stateStack(power)"`
    多状态一起：数组多个 applyState

要点
    `applyState` 会新建状态（如果没有），有则叠加 stacks
    `changeStateStack` 只改现有，没有则不生效——想"要有才加、没有就不加"用它
    `stateKey` 必须是 `stateList.ts` 注册的 key，写错静默无效
    状态本身可能带触发器（衰减、每回合触发等），一律在 stateList 定义时配好，不要在 apply 时临时加

## 场景 7：拦截修改事件参数

目标
    「受伤时 -2 减免」「造成伤害 +50%」「抽卡数量 -1」——事件已经在跑，我方在 before 阶段改它的 params。

涉及机制
    专用 modify effect
        `modifyDamageValue` — 改伤害数值（正/负都可）
        `modifyDamageByPercent` — 按百分比修改伤害
        `reduceDamageValue` — 减伤专用
        `nullifyDamageValue` — 让本次伤害归 0
        `damageIgnoreArmor` — 让伤害无视护甲
    在 reaction 里 `targetType: "triggerEffect"`，effect 用上面的 modify 效果作用于**引发本次触发的 Effect**

数据模板：受伤减免 2

```typescript
reaction: {
    reduceDamage: [{
        targetType: "triggerEffect",
        key: "modifyDamageValue",
        effect: [{ key: "modifyDamageValue", params: { value: -2 } }]
    }]
}
```

数据模板：造成伤害 +50%（下场伤害额外算 50%）

```typescript
reaction: {
    boostDamage: [{
        targetType: "triggerEffect",
        key: "modifyDamageByPercent",
        effect: [{ key: "modifyDamageByPercent", params: { percent: 50 } }]
    }]
}
```

常见变体
    完全免疫：`nullifyDamageValue`
    不能减到负数：modifyDamage 类效果通常内部会 clamp 到 0
    仅当伤害超过 X：外层加 condition（见触发器手册场景 5）
    按层数加伤再乘倍率：`params: { delta: "$triggerEffect.target.stateStack(weak)", multiplier: "$owner.status(weak-bonus)" }`（现行：腐蚀腺）。`multiplier` 缺省 1，实际加值 = delta × multiplier。效果参数里 `$owner` 是定义该效果的器官，不是持有者

要点
    `modifyDamageValue` 只在 **before + take + damage** 的触发器里有效——after 阶段改了没用，伤害已经算完
    正数是加、负数是减；不要用 `damage` 效果来"减伤"（那是产生新伤害事件）
    `targetType: "triggerEffect"` 是这个场景的固定写法——把效果作用于原 Effect 对象，不是某个 Entity

## 场景 8：取消 / 重定向整个事件

目标
    「完全取消这次伤害事件」「让敌人的攻击打到别人」——不是改 params，而是取消/重定向整个事件。

涉及机制
    `cancelEvent` `cancelCurrentEvent` — 取消当前事件
    事件的 target 已经在创建时定死，重定向要在 reaction 里换 `targetType`（等于发起新事件到别人）
    某些拦截可以直接在触发器 callback 里 `event.cancel()`（命令式路线，见触发器手册场景 9）

数据模板：debuff 免疫（拦截 applyState 事件）

```typescript
// possess.triggers
{
    when: "before",
    how: "take",
    key: "applyState",
    action: "blockDebuff",
    condition: "$eventInfo.isDebuff == true"
}

// reaction
{
    blockDebuff: [{
        targetType: "triggerEffect",
        key: "artifactBlockDebuff",
        effect: [{ key: "artifactBlockDebuff" }]
    }]
}
```

要点
    "免除某类事件"用专用 EffectFunc（如 `artifactBlockDebuff`）比裸 `cancelEvent` 语义清楚
    如果只是"这次伤害归 0"，用 `nullifyDamageValue`——伤害流程还走，只是数值 0；这跟"整个 damage 事件取消"不同（后者会打断级联触发）
    重定向不是原地改 event.target，而是新建一个针对新 target 的事件（新事件也会走完整 before/after 周期）

## 场景 9：随机与玩家选择

目标
    「随机造成 1-5 点伤害」「玩家从 3 张卡里选 1 张进手牌」「随机选一个敌人」——不是固定，需要玩家或随机数介入。

涉及机制
    随机数字：`random(min, max)` 表达式（走战斗种子）
    随机敌人：reaction 的 `targetType: "allEnemies.random"`
    两个不同随机目标：先 `allEntities.random`，再 `allEntities.except(pickedTargets).random`
    需要点名同一次抽取时，reaction 写 `as: "hurt"`，后面 `targetType: "hurt"` 或 `except(hurt)`
    玩家选卡：`discoverCard` `chooseRandomCard` `chooseCardUpgrade` `chooseCardRemove` `chooseCardDuplicate` `customCardChoice`
    玩家选器官：`chooseOrganRemove`
    随机做点什么给一批：`giveTemporaryEffectToRandomCards`

数据模板：造成 1-6 点随机伤害

```typescript
[{ key: "damage", params: { value: "random(1, 6)" } }]
```

数据模板：玩家从 3 张随机稀有卡里选 1 张永久获得

```typescript
[{
    key: "discoverCard",
    params: {
        count: 3,
        rarity: "rare",
        addTo: "deck"
    }
}]
```

数据模板：从 3 张自定义卡里选（cardKeys 显式指定）

```typescript
[{
    key: "customCardChoice",
    params: {
        cardKeys: ["card_a", "card_b", "card_c"],
        addTo: "hand"
    }
}]
```

要点
    `random()` 是**创建 Effect 时**摇一次——每次触发都不同，但同一次触发内的所有引用是**同一个数**
    要每次都不同的场景：写在 EffectFunc 里，用 `getRandom(battle)`（走种子）
    `.random` 两次会进同一只 `pickedTargets` 袋；要另一个人用 `except(pickedTargets).random`，不要连写两个裸 `.random`（同回合同种子会抽到同一个人）
    玩家选卡类效果**必须**在玩家可交互的场景（战斗内 / 房间事件），战斗外触发会卡住 UI

## 场景 10：新建专属 EffectFunc

目标
    「现有原子/复合效果拼不出我要的行为，需要一个新的 EffectFunc」

涉及机制
    在 `src/core/effects/<分类>/xxx.ts` 新建 EffectFunc
    在 `src/static/list/system/effectMap.ts` 注册（`import` + `key + effect` 项）
    命名规范
        通用可复用：`gainArmor` `applyState`
        某器官专属：`organ_<器官key主体>`（如 `organ_heatTick`）
        某卡牌专属：`card_<卡牌key主体>`（如 `card_commandStrike`）
        某状态专属：`state_<状态key>`（如 `state_hardenAbsorb`）

代码模板

```typescript
// src/core/effects/organ/myOrganTick.ts
import type { EffectFunc } from "@/core/objects/system/effect/EffectFunc"

export const organ_myOrganTick: EffectFunc = async (event, effect) => {
    const value = Number(effect.params.value ?? 1)
    // 修改状态、发起新事件、读运行时数据...
    // 严禁直接改 Entity.status，用 doEvent 或专用工具函数
}
```

注册

```typescript
// src/static/list/system/effectMap.ts
import { organ_myOrganTick } from "@/core/effects/organ/myOrganTick"

// 在 effectMap 数组里加：
{ key: "organ_myOrganTick", effect: organ_myOrganTick }
```

数据里用

```typescript
[{ key: "organ_myOrganTick", params: { value: 2 } }]
```

要点
    EffectFunc 是 `async` 函数，签名 `(event, effect) => Promise<void>`
    **必须**通过 `doEvent(...)` 修改游戏状态——不能直接 `player.current.health.value -= 10`
    如果新效果只服务于一个内容，用 `organ_ / card_ / state_` 前缀——避免污染通用命名空间
    通用可复用的效果先想清楚它是不是已有一个类似 effect 只是差点参数；99% 情况扩展现有 effect 的 params 比新建一个更好
    每个新 EffectFunc 都要在 effectMap 注册；漏注册的话数据里写了不会执行，静默失败

能量效果语义
```
gainEnergy   参数 value   加能量（正数）
loseEnergy   参数 value   减能量（正数；广播 loseEnergy 事件，供触发器统一监听）
refillEnergy 无参         能量回到当前上限（回合开始 / 大黄蜂之类）
emptyEnergy  无参         能量清零（回合结束）
payEnergy    参数 value   有校验的支付：不足时 showQuickInfo 并返回 false；
                          够则委派 loseEnergy 子事件完成扣减
                          用 resultStoreAs 读支付结果（true/false）
```

选 payEnergy 还是 loseEnergy：会因资源不足而中止的"支付"用 payEnergy（卡牌费、
主动能力费），无条件扣减用 loseEnergy（惩罚性效果、任意直接扣能量）。触发器只
需监听 loseEnergy 即可覆盖两种路径。

## 附录 B：常见坑速查

    `$` 引用写成裸变量：`{ value: $owner... }` 是语法错——必须字符串 `"$owner..."`
    accessor 忘写括号：`$owner.status.health` 不识别，要 `$owner.status(health)`
    找不到 EffectFunc：effectMap 里没注册，数据里写了会静默不执行 → 检查 effectMap.ts + import
    `cardKey` `stateKey` 拼错：静默无效，控制台会有 warning
    `addStatusBase` 用在遗物/器官提供的属性上：物品失去时不会自动撤销，导致玩家永久多出属性 → 用 `addStatusModifier` 让 modifier 系统自动清理
    数组顺序当成随意：靠前 effect 改的状态在后面 effect 里能读到，别把依赖顺序的效果打乱
    多 target（AOE）时算错：一个 effect 数组内所有 effect 都会对整个 target 数组作用，不是"第一个 effect 打 A、第二个打 B"
    `random(1, 6)` 每次触发都摇一次，同次触发内所有引用是同一个数——想每次不同要在 EffectFunc 里 `getRandom(battle)`
    改 params 用了 `after` 触发：来不及了 → 用 `before`（见触发器手册场景 2）
    直接改 Entity 属性：绕过效果系统 → 用 `doEvent` 或专用 effect（详见 `常见错误排查手册.md`）
    忘了 `discoverCard` 需要玩家可交互场景：战斗外调用会 UI 卡住 → 用在房间事件或战斗中

## 快速对照表

想实现的效果 → 场景编号

    单一简单效果（伤害/回血/护甲/施加状态） → 1
    一次做多件事 → 2
    动态数值（引用属性 / 力量层数 / 原伤害） → 3
    影响牌堆手牌（抽/弃/消耗/塞牌） → 4
    改属性上限 / 首回合抽牌数 → 5
    施加或移除 buff / debuff → 6
    减免伤害 / 修改事件参数 → 7
    取消 / 免疫某类事件 → 8
    随机数或玩家选择 → 9
    新建专属 EffectFunc → 10
