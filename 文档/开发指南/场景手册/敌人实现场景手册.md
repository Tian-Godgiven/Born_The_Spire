# 敌人实现场景手册

面向 AI 与 Mod 开发者的场景式教程。想实现某种敌人，先在本手册找相似场景，复制模板，改数值和描述。

本手册与《敌人AI系统》文档的分工：
    敌人AI系统 — behavior / pattern / condition 语法完整参考
    本手册 — 我要做出「XX 行为模式的敌人」，具体数据怎么写

敌人 vs 玩家的对称
    敌人本质上是 Chara，与玩家共用大部分系统
    区别：敌人有 behavior（AI 决策），玩家有玩家操作
    敌人也可以有 trigger / reaction，与玩家一致

---

## 使用方法

每个场景包含：
    目标 — 一句话说清楚要实现什么
    涉及机制 — 用到哪些系统
    数据模板 — 完整可复制的 EnemyMap 定义
    常见变体 — 数值 / 条件小改
    相关文档 — 需要延伸阅读时的入口

## 场景 1：简单敌人（只有 fallback）

目标
    每回合从可用卡里随机打出。没有条件分支。

涉及机制
    behavior.fallback 决定始终执行的行为
    action.selector 从卡池筛卡

数据模板

```typescript
{
    label: "毒液蟾",
    key: "enemy_poison_toad",
    status: { "max-health": 30 },
    organ: [
        "enemy_organ_poison_gland",
        "enemy_organ_poison_skin",
        "enemy_organ_sticky_tongue"
    ],
    behavior: {
        patterns: [],
        fallback: {
            intent: "attack",
            action: { selector: { tags: ["attack"] }, mode: "random" },
            describe: "随机使用攻击牌"
        }
    }
}
```

常见变体

    随机使用任意牌：`selector: {}` 空对象 → 从所有牌里选
    只打特定 tag：`tags: ["attack", "multiHit"]` 任一 tag 匹配即可
    只用某张固定卡：`selector: { key: "enemy_card_bite" }`

要点
    没有 patterns 时，fallback 是必需的
    describe 只在开发调试面板显示，玩家看不到
    organ 里挂什么器官就自动获得对应卡牌，无需在 cards 字段重复

    **selector 筛不到卡会静默退回基础牌**：`selectActionCards` 筛出空数组时走 `getFallbackCard`，
    带 defence tag 的退回 `original_card_00014`（基础防御），其余一律退回 `original_card_00001`（基础打击）。
    敌人于是打出一张它器官根本没提供的牌，不报错，很难查。两种情形要特别小心：
        卡没打 `tags: ["attack"]`，却用 `selector: { tags: ["attack"] }` 去选
        卡带了消耗类词条，打出一次就离场，之后每回合都退回打击
    只有一两张专属牌的敌人，直接用 `selector: { key: "enemy_card_xxx" }` 点名最稳。

## 场景 2：条件行为切换（每 N 回合防御）

目标
    「偶数回合防御，奇数回合攻击」「HP 低于 50% 优先治疗」。

涉及机制
    patterns 是按优先级评估的条件行为列表
    condition 用 turn / selfHealth / playerHealth / hasState 描述条件

数据模板：偶数回合防御

```typescript
{
    label: "不屈小鼠",
    key: "test_enemy_mouse",
    status: { "max-health": 50 },
    organ: ["test_organ_cards_001", "organ_resilient_shell"],
    behavior: {
        patterns: [{
            priority: 5,
            intent: "defend",
            condition: { turn: { mod: [2, 0] } },
            action: { selector: { tags: ["defence"] }, mode: "random" },
            describe: "偶数回合防御"
        }],
        fallback: {
            intent: "attack",
            action: { selector: { tags: ["attack"] }, mode: "random" },
            describe: "默认攻击"
        }
    }
}
```

condition 全部可选字段

```typescript
condition: {
    playerHealth: { below?: number, above?: number, equals?: number },  // 百分比
    selfHealth: { below?: number, above?: number, equals?: number },
    turn: {
        equals?: number,
        above?: number,
        below?: number,
        mod?: [number, number]    // [除数, 余数]，如 [3, 0] 每 3 回合
    },
    hasState: {
        target: "self" | "player",
        stateKey: string,
        stacks?: number    // 默认 > 0
    },
    custom: (enemy, player) => boolean    // 复杂条件用自定义函数
}
```

常见变体

    满血敌人狂暴：`selfHealth: { equals: 100 }`
    玩家残血时补刀：`playerHealth: { below: 30 }`
    玩家中毒时优先毒攻：`hasState: { target: "player", stateKey: "poison" }`

要点
    patterns 按 priority 从高到低评估，第一个满足 condition 的执行
    priority 相同时按列表顺序
    没有 condition 的 pattern 相当于始终满足（此时更像 fallback）

## 场景 3：多阶段 Boss（血量阈值切换）

目标
    「>66% 蓄力 / 33-66% 猛攻 / <33% 狂暴」。

涉及机制
    多个 pattern，每个用 selfHealth condition 划分血量区间
    Born The Spire 没有独立的 phases 字段，阶段通过 condition 表达

数据模板

```typescript
{
    label: "守护者",
    key: "test_enemy_boss",
    status: { "max-health": 150, "action-order": 10 },
    organ: ["test_organ_cards_001", "test_organ_cards_002"],
    behavior: {
        patterns: [
            {
                priority: 10,
                intent: "buff",
                condition: { selfHealth: { above: 66 } },
                action: { selector: { tags: ["power"] }, mode: "random" },
                describe: "阶段1：蓄力"
            },
            {
                priority: 10,
                intent: "attack",
                condition: { selfHealth: { above: 33 } },
                action: {
                    selector: { tags: ["attack"] },
                    mode: "weighted",
                    weights: { "original_card_00002": 3 }
                },
                describe: "阶段2：猛攻"
            },
            {
                priority: 10,
                intent: "attack",
                condition: { selfHealth: { below: 33 } },
                action: {
                    selector: { tags: ["attack"] },
                    mode: "weighted",
                    weights: { "original_card_00002": 5 }
                },
                describe: "阶段3：狂暴"
            }
        ],
        fallback: {
            intent: "attack",
            action: { selector: { tags: ["attack"] }, mode: "random" }
        }
    }
}
```

要点

    上面 3 个 pattern 同 priority，按顺序评估：第一个 above:66 匹配则用 → 血量掉进 33-66 区间时上一个失效、下一个上位
    如果想让阶段切换本身触发一次性行为（比如"进入下阶段时施加 buff"），用敌人的 trigger + reaction，见场景 8
    Boss 通常还搭配「相位转换」类效果（`organ_phaseShift`）通过器官提供

## 场景 4：循环 / 序列行为

目标
    「打击 → 强化 → 打击 → 强化」严格按序循环。

涉及机制
    action.mode: "sequence" 或 "loop"
    action.sequence 数组指定卡牌 key 序列

数据模板

```typescript
{
    label: "法师",
    key: "test_enemy_mage",
    status: { "max-health": 35 },
    organ: ["test_organ_cards_001", "test_organ_cards_002"],
    behavior: {
        patterns: [{
            priority: 0,
            action: {
                selector: {},
                mode: "loop",
                sequence: [
                    "original_card_00001",
                    "original_card_00004"
                ]
            },
            describe: "打击和强化交替"
        }]
    }
}
```

mode 全部值

    `random` — 从 selector 结果里随机（默认）
    `weighted` — 按 weights 加权随机
    `sequence` — 严格按 sequence 顺序，最后一张后不再执行
    `loop` — 循环 sequence 直到战斗结束

要点

    sequence 里的 key 必须是敌人可用的卡牌（在 organ 提供或 cards 字段中）
    如果 sequence 里的卡在某回合被过滤（比如器官损坏了对应器官），会跳过或走 fallback

## 场景 5：权重随机（偏好某类攻击）

目标
    「主要用群咬，偶尔用蚀咬」— 加权随机，不是完全均匀。

涉及机制
    action.mode: "weighted"
    action.weights 指定每张卡的权重

数据模板

```typescript
{
    priority: 0,
    intent: "attack",
    action: {
        selector: { tags: ["attack"] },
        mode: "weighted",
        weights: {
            "enemy_card_swarm_bite": 3,
            "enemy_card_acid_bite": 1
        }
    },
    describe: "群咬为主，偶尔蚀咬"
}
```

要点

    weights 未列出的卡权重为 1（默认）
    weights 里的卡必须先被 selector 选中，否则不参与
    「3:1」= 3/4 概率群咬，1/4 概率蚀咬

## 场景 6：精英 / 多行动敌人

目标
    「每回合行动 2 次」的精英怪。

涉及机制
    status 里 `actions-per-turn` 决定每回合行动次数
    `action-order` 影响多个敌人时的行动顺序（越大越靠后）

数据模板

```typescript
{
    label: "双头蛇",
    key: "test_enemy_elite",
    status: {
        "max-health": 80,
        "actions-per-turn": 2,
        "action-order": 5
    },
    organ: ["test_organ_cards_001", "test_organ_cards_002"],
    behavior: {
        patterns: [{
            priority: 10,
            intent: "buff",
            condition: { turn: { mod: [3, 0] } },
            action: { selector: { tags: ["power"] }, mode: "random" },
            describe: "每 3 回合强化一次"
        }],
        fallback: {
            intent: "attack",
            action: { selector: { tags: ["attack"] }, mode: "random" }
        }
    }
}
```

要点

    每回合 pattern 会评估 actions-per-turn 次
    如果 pattern 是"每 3 回合触发一次"，2 次行动都会满足条件，可能连续两次强化
    要避免这种情况，pattern 内可以借助 hasState 检查是否已强化

## 场景 7：Boss 专属牌堆 + 复杂器官组合

目标
    Boss 有多个专属器官，加上直接挂在敌人上的专属卡牌，形成复杂牌堆。

涉及机制
    organ 数组挂多个专属器官
    cards 字段直接列专属卡（不通过器官）
    trigger + reaction 处理阶段切换等一次性事件

数据模板

```typescript
{
    label: "疫孢菌母",
    key: "enemy_plague_mother",
    status: { "max-health": 180, "actions-per-turn": 1 },
    organ: [
        "enemy_organ_spore_gland",
        "enemy_organ_parasitic_root",
        "enemy_organ_corruption_armor",
        "enemy_organ_toxic_core_boss",
        "enemy_organ_mycelial_network"
    ],
    cards: ["enemy_card_spore_burst", "enemy_card_parasitic_spawn"],
    trigger: [{
        when: "after",
        how: "take",
        key: ["attack", "damage"],
        action: "checkPhaseShift"
    }],
    reaction: {
        checkPhaseShift: [{
            key: "checkPhaseShift",
            label: "相位转换",
            targetType: "owner",
            effect: [{
                key: "organ_phaseShift",
                params: { threshold: 0.5, actions: 2 }
            }]
        }]
    }
}
```

cards vs organ 提供的卡

    organ 的卡通过 CardModifier 加入，器官损坏时自动过滤
    cards 直接挂在敌人上，始终可用
    selector 选卡时两者合并
    selector 用 `organ: "key"` 可以精确选某器官的卡

要点

    Boss 专属卡 tag 通常有 "enemy" 便于池过滤，防止被玩家意外抽到
    多器官组合是 Boss 的常见做法，能表达"多种能力"而无需一个巨大的怪物类
    器官损坏会禁用相关卡，可作为难度调节点（打破某个器官降低威胁）

## 场景 8：敌人的 trigger + reaction（受伤反击 / 阶段切换）

目标
    「受到攻击时反击 5 伤害」「HP 首次跌破 50% 时召唤援军」。

涉及机制
    敌人的 trigger 字段（与 chara 共用）
    reaction 段声明触发时行为

数据模板

```typescript
{
    label: "多刺兽",
    key: "your_mod_enemy_thorn",
    status: { "max-health": 40 },
    organ: ["your_mod_organ_thorn_hide"],
    trigger: [{
        when: "after",
        how: "take",
        key: "attack",
        action: "thornCounter"
    }],
    reaction: {
        thornCounter: [{
            key: "thornCounter",
            label: "反击",
            targetType: "triggerSource",
            effect: [{ key: "attack", params: { value: 5 } }]
        }]
    }
}
```

要点

    `targetType: "triggerSource"` — 谁打的我就反击谁
    与器官上的 reaction 语义完全一致，只是宿主变成了敌人本体
    敌人 trigger 上写的东西不受器官损坏影响；如果想能被玩家「打断」，应该把它挂到某个器官上，破坏该器官即失效

## 场景 9：battleList 的 enemyConfig 覆盖

目标
    同一敌人在不同战斗里用不同 behavior 或不同血量。

涉及机制
    battleList 中 `enemyConfigs` 支持 override

数据模板：单敌人覆盖

```typescript
// src/static/list/room/battle/battleList.ts
{
    key: "battle_f1_poison_toad",
    name: "毒沼",
    battleType: "normal",
    encounterPool: "easy",
    enemyConfigs: [{
        key: "enemy_poison_toad",
        behavior: {
            patterns: [],
            fallback: {
                intent: "attack",
                action: { selector: { tags: ["attack"] }, mode: "random" },
                describe: "易伤打击"
            }
        }
    }]
}
```

数据模板：多敌人 + 各自不同覆盖

```typescript
{
    key: "battle_f1_two_soldiers",
    name: "蚁群巡逻",
    battleType: "normal",
    encounterPool: "easy",
    enemyConfigs: [
        {
            key: "enemy_ant_soldier",
            behavior: {
                patterns: [{
                    priority: 5,
                    condition: { turn: { equals: 1 } },
                    action: { selector: { key: "enemy_card_acid_bite" }, mode: "random" },
                    describe: "第 1 回合蚀咬"
                }],
                fallback: {
                    intent: "attack",
                    action: {
                        selector: { tags: ["attack"] },
                        mode: "weighted",
                        weights: {
                            "enemy_card_swarm_bite": 3,
                            "enemy_card_acid_bite": 1
                        }
                    }
                }
            }
        },
        {
            key: "enemy_ant_soldier",   // 同一敌人 key 可以出现多次
            statusOverrides: { "max-health": 20 }  // 更弱的一只
        }
    ]
}
```

可覆盖字段

    `behavior` — 完全替代 enemyList 中定义的 behavior
    `statusOverrides` — 单个属性覆盖，其他保留原值

要点

    覆盖不是「合并」，behavior 是完全替换。想只微调一部分，改 enemyList 或写新的 enemy
    同一 key 可以在 enemyConfigs 里出现多次，产生同类型的多只敌人
    只写字符串 `"enemy_key"` 等价于 `{ key: "enemy_key" }`，不带任何覆盖

## 场景 10：意图（intent）的作用

目标
    正确设置 intent 让玩家看到直观的意图图标。

涉及机制
    action.intent 决定 UI 显示的意图图标

intent 全部值

    `attack` — 攻击（红色刀图标）
    `defend` — 防御（盾牌）
    `buff` — 自我强化（上箭头）
    `debuff` — 给玩家上负面（骷髅）
    `heal` — 回血（心）
    `escape` — 逃跑
    `unknown` — 未知（迷雾）
    `special` — 特殊（星）

要点

    intent 可以不写，UI 会从所选卡牌的 use 效果推导（硬化的 `gainArmor` 显示防御和护甲值，毒孢的 `applyState` 打全体显示减益）
    混合技能池（毒孢或硬化）不要写 `intent: "unknown"`，否则一律显示问号
    显式指定 intent 覆盖推导结果
    多段攻击的 pattern 仍然是 attack 意图，配合数字气泡显示多次伤害
    unknown 只用于真正要藏意图的行动（Boss 迷雾），不要拿来当「我不知道选哪张」

## 常见错误与修正

错误 1：patterns 顺序反了
    错：把「兜底攻击」pattern 放前面，「HP 低时治疗」放后面
    对：优先级高、更特化的 pattern 放前面（或用 priority 明确排序）

错误 2：organ 里的器官坏了导致没牌可用
    症状：敌人 idle 或触发兜底
    修复：给 organ 数组挂多个器官，或用 cards 字段挂几张保底牌

错误 3：condition 用 selfHealth: 30 而不是 { below: 30 }
    condition 里的数值必须包在 `{ below: N }` / `{ above: N }` / `{ equals: N }` 结构里，光写数字不生效

错误 4：sequence mode 没写 sequence
    action.mode: "sequence" 但没有 action.sequence 数组，会退化成 random

错误 5：忘了给 boss 的卡加 "enemy" tag
    症状：Boss 的专属卡出现在玩家奖励池
    修复：卡牌定义里加 `tags: ["attack", "enemy"]`

错误 6：battleList 里改 behavior 一小点，整个 fallback 消失
    原因：behavior 覆盖是完全替换，不是深度合并
    修复：要么复制原 behavior 完整重写，要么把这个变体做成独立的 enemy key

错误 7：忘了 organ 是必需字段
    敌人可以没有 status 里的自定义字段，但 organ 数组不能省略（可以是 `organ: []` 空数组）

错误 8：actions-per-turn 与 pattern 交互没考虑
    症状：多行动敌人在同一回合内连续两次触发条件行为
    修复：pattern condition 里加 hasState 检查已完成动作，或改用 sequence mode

错误 9：混合技能池写成 intent: "unknown"
    症状：孢子菌打硬化也显示问号
    原因：`unknown` 会覆盖效果推导，一律显示迷雾
    修复：不写 intent，让系统按所选卡牌的 `gainArmor` / `applyState` 推导；`unknown` 只留给真正要藏意图的行动
