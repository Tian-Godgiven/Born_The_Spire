# 卡牌实现场景手册

面向 AI 与 Mod 开发者的场景式教程。想实现某种卡牌，先在本手册找相似场景，复制模板，改数值和描述，多数情况下不用写新代码。

本手册与《新内容开发清单》的分工：
    新内容开发清单 — 加卡牌需要动哪些文件、CardMap 最小字段
    本手册 — 我要做出「XX 效果的卡牌」，具体数据怎么写

## 使用方法

每个场景包含：
    目标 — 一句话说清楚要实现什么
    涉及机制 — 用到哪些系统，是否需要写新效果函数
    数据模板 — 完整可复制的 CardMap 定义
    常见变体 — 数值/条件小改
    相关文档 — 需要延伸阅读时的入口

场景之间可以自由组合：伤害 + 状态 + 消耗 = 消耗型施毒攻击牌，模板照抄拼装。

## 通用约定：describe 里提到状态/术语必须用 `$` 标记

这是所有场景都适用的横切规范，写 describe 时先看这一节。

描述里凡是出现状态名、词条名、规则名词，都要写成 `{$:"名称"}`，不能留成纯文字。

```typescript
describe: ["对目标施加", { key: ["status", "stacks"] }, "层蚀伤"]          // 错
describe: ["对目标施加", { key: ["status", "stacks"] }, "层", {$:"蚀伤"}]  // 对
```

为什么必须标记
    只有带 `$` 标记的片段，玩家悬停卡牌时才会弹出它的说明
    纯文字对 UI 来说和「点」「层」这种连接词没有区别，蚀伤是什么就永远查不到

`$` 里写什么
    写注册表 key（`acidWound`）或显示名（`蚀伤`）都可以，两种都能命中
    解析顺序：`glossaryMap` → `stateList` → `entryDefinitions`，查不到则退化成纯文字显示

说明写在哪里（不要写重复的第二份）
    状态 — 写在 `stateList.ts` 该状态的 `describe` 字段
    词条 — 写在 `entry/CardEntry.ts`、`entry/OrganEntry.ts` 该词条的 `describe` 字段
    以上都不属于的规则性名词（护甲、格挡）— 才写进 `glossaryMap.ts`

新增一个状态时，只要在 `stateList.ts` 写好 `label` 和 `describe`，卡牌里 `{$:"状态名"}` 立刻就有说明，不需要也不应该再往 `glossaryMap` 抄一份——抄了就会有两份描述互相脱节。

同样的规范适用于器官、遗物的 `describe`。

## 场景 1：造成固定伤害的攻击牌

目标
    基础攻击牌：花 1 费打 X 点伤害。

涉及机制
    效果：`damage`（已存在）
    无需新效果函数

数据模板

```typescript
{
    label: "打击",
    key: "original_card_00001",
    tags: ["attack"],
    status: { damage: 5, cost: 1 },
    describe: ["造成", { key: ["status", "damage"] }, "点伤害"],
    interaction: {
        use: {
            target: { faction: "opponent" },
            effects: [{ key: "damage", params: { value: 5 } }]
        }
    }
}
```

常见变体

    高费高伤害：cost 改 2、damage 改 12
    诅咒攻击牌：`tags` 加 `"curse"`
    锁定伤害数值：`describe` 里直接写「造成 8 点伤害」而不引用 status
    描述与数值同步：`params.value` 用 `"$owner.status(damage)"` 使升级 status 后描述与效果一起变

相关文档
    参考/效果开发指南.md

## 场景 2：造成伤害 + 施加负面状态

目标
    攻击时给目标叠一个 debuff（虚弱、易伤、中毒 等）。

涉及机制
    效果：`damage` + `applyState`
    需要目标 state 已注册在 `stateList.ts`

数据模板

```typescript
{
    label: "易伤打击",
    key: "original_card_00011",
    tags: ["attack"],
    status: { damage: 8, vulnerable: 2, cost: 1 },
    describe: [
        "造成", { key: ["status", "damage"] }, "点伤害，",
        "使目标获得", { key: ["status", "vulnerable"] }, "层", {$:"易伤"}
    ],
    interaction: {
        use: {
            target: { faction: "enemy" },
            effects: [
                { key: "damage", params: { value: "$medium.status(damage)" } },
                { key: "applyState", params: { stateKey: "vulnerable", stacks: "$medium.status(vulnerable)" } }
            ]
        }
    },
    upgradeConfig: {
        maxLevel: 1,
        levelConfigs: {
            1: { status: { damage: 10, vulnerable: 3 } }
        }
    }
}
```

常见变体

    先叠 debuff 再打伤害：调换 effects 顺序，可利用刚施加的 vulnerable 增伤
    自身叠 buff：加一条 `{ key: "applyState", params: { stateKey: "power", stacks: 1 } }`，target 分开写会更清晰，或直接用 `applyState` 的 target 参数
    施加多种状态：多加几条 effect 条目

相关文档
    开发指南/状态系统开发指南.md — stateKey 怎么加

## 场景 3：多段攻击

目标
    「攻击 3 次，每次造成 4 点伤害」。多段攻击对护甲、单次减伤有独特互动。

涉及机制
    tag：`multiHit`（供其他系统识别多段属性）
    效果：`repeatEffects`（把一组 effect 重复执行指定次数）

数据模板

```typescript
{
    label: "铁刺",
    key: "boss1_card_iron_spike",
    tags: ["attack", "multiHit"],
    status: { damage: 4, hits: 2, cost: 1 },
    describe: [
        "攻击", { key: ["status", "hits"] }, "次，",
        "每次造成", { key: ["status", "damage"] }, "点伤害"
    ],
    interaction: {
        use: {
            target: { faction: "opponent" },
            effects: [{
                key: "repeatEffects",
                params: {
                    times: "$owner.status(hits)",
                    effects: [{ key: "damage", params: { value: 4 } }]
                }
            }]
        }
    }
}
```

常见变体

    次数由状态动态决定：`times` 改成 `"$owner.status(otherStatKey)"`
    每段带附加效果：内层 effects 加一条 `applyState`

注意
    单纯写多条 `damage` 效果不算多段攻击，护甲/闪避会按每次单独结算，正确写法是 `repeatEffects`
    敌人意图会显示成 `单段伤害 × 次数`（群咬 3 点打 2 次 → `3 × 2`）。写成专属 EffectFunc 包一层伤害的话，意图读不到段数。

## 场景 4：群体攻击 / 多目标选择

目标
    对多个敌人生效：全体、随机 N 个、指定阵营 N 个。

涉及机制
    调整 `target` 字段的 `number`
    效果函数需处理 `event.target` 是数组的情况（现有 `damage`、`applyState` 已处理）

数据模板：全体

```typescript
{
    label: "旋风斩",
    key: "original_card_00005",
    tags: ["attack"],
    status: { damage: 3, cost: 1 },
    describe: ["对敌方全体造成", { key: ["status", "damage"] }, "点伤害"],
    interaction: {
        use: {
            target: { faction: "opponent", number: "all" },
            effects: [{ key: "damage", params: { value: 3 } }]
        }
    }
}
```

数据模板：至多 N 个

```typescript
target: { faction: "opponent", number: 3 }
```

常见变体

    随机 N 个：结合注册效果 `chooseRandomCard` 类思路，或用 `repeatEffects` + 随机 target 逻辑（视需求）
    全体附加状态：把 damage 换成 applyState，全体施加 debuff

相关文档
    参考/反应系统详解.md — target 选择器完整语法

目标
    技能牌：花 X 费获得 Y 点护甲。

涉及机制
    效果：`gainArmor`
    target：`{ key: "self" }`

数据模板

```typescript
{
    label: "防御",
    key: "original_card_00014",
    tags: ["skill", "defence"],
    status: { armor: 5, cost: 1 },
    describe: ["获得", { key: ["status", "armor"] }, "点", {$:"护甲"}],
    interaction: {
        use: {
            target: { key: "self" },
            effects: [{ key: "gainArmor", params: { value: 5 } }]
        }
    }
}
```

常见变体

    护甲 + buff：加 `applyState`，比如「获得护甲并获得 2 层力量」
    双份护甲：`gainArmor` 效果重复 2 次或写 `value: 10`
    每张攻击牌+1 armor：条件动态计算，见场景 12

## 场景 6：抽牌 / 弃牌 / 卡牌操作

目标
    「抽 2 张牌」「弃 1 张手牌」「从牌堆检索一张卡」。

涉及机制
    效果：`drawCard` / `discard` / `drawFromDrawPile` / `discoverCard` 等
    参考 effectMap 中的卡牌操作类效果

数据模板：抽牌

```typescript
{
    label: "急速",
    key: "your_mod_card_draw",
    tags: ["skill"],
    status: { cost: 0, drawCount: 2 },
    describe: ["抽", { key: ["status", "drawCount"] }, "张牌"],
    interaction: {
        use: {
            target: { key: "self" },
            effects: [{ key: "drawCard", params: { value: 2 } }]
        }
    }
}
```

数据模板：检索式（从N张随机中选1加入手牌）

```typescript
{
    label: "大发现",
    key: "original_card_00016",
    tags: ["skill"],
    status: { cost: 1 },
    describe: ["从 30 张随机卡牌中选择一张加入手牌"],
    interaction: {
        use: {
            target: { key: "self" },
            effects: [{
                key: "discoverCard",
                params: {
                    count: 30,
                    selectCount: 1,
                    allowDuplicate: false,
                    addToHand: true
                }
            }]
        }
    }
}
```

常见变体

    弃牌换抽牌：先 `chooseHandCardDiscard`，再 `drawCard`
    直接洗弃牌堆入抽牌堆：`shuffleDiscardIntoDraw`
    塞入指定卡：`addCardToHand` / `stuffCard`

## 场景 7：消耗牌（用后从战斗中移除）

目标
    使用后进消耗堆，本场战斗不再出现。

涉及机制
    entry：`card_exhaust`（自动处理，无需额外效果）

数据模板

```typescript
{
    label: "消耗打击",
    key: "original_card_00002",
    tags: ["attack"],
    status: { damage: 15, cost: 1 },
    entry: ["card_exhaust"],
    describe: ["造成", { key: ["status", "damage"] }, "点伤害"],
    interaction: {
        use: {
            target: { faction: "opponent" },
            effects: [{ key: "damage", params: { value: 15 } }]
        }
    }
}
```

常见变体

    Power 牌天然消耗：直接加 `entry: ["card_exhaust"]` 或 `["exhaust"]`
    条件消耗：不在 entry 里写，而是在 effects 末尾加 `pay_exhaust` 效果，可搭配 condition 只在满足条件时消耗

## 场景 11：手牌触发型（在手牌中就会做事）

目标
    卡牌不需要打出，只要在手牌里就在每回合结束/开始时触发效果。典型场景：孢子、诅咒、燃烧牌。

涉及机制
    interaction 中的 `inHand` 段（对应 possess 语义）
    reaction 声明式：action + reaction 模式

数据模板

```typescript
{
    label: "孢子",
    key: "boss2_card_spore",
    tags: ["skill"],
    status: { cost: 4 },
    entry: ["card_void"],
    describe: ["在手牌中时，回合结束施加 1 层中毒（随后消耗）"],
    interaction: {
        use: {
            target: { key: "self" },
            effects: []
        },
        inHand: {
            target: { key: "self" },
            effects: [],
            triggers: [{
                when: "before",
                how: "take",
                key: "turnEnd",
                action: "sporePoison"
            }]
        }
    },
    reaction: {
        sporePoison: [{
            key: "sporePoison",
            label: "孢子毒素",
            targetType: "owner",
            effect: [{ key: "applyState", "params": { stateKey: "poison", stacks: 1 } }]
        }]
    }
}
```

要点
    `use` 段依然要写，即便空 effects — 因为 cost 存在时玩家仍可能打出
    `inHand.triggers` 声明什么事件触发，`reaction` 声明触发时做什么
    `targetType: "owner"` 指卡牌的持有者（谁在手上）

常见变体

    燃烧类：`stateKey` 改 "burn"，或直接对 owner 加 loseHp
    条件触发：在 triggers 里加 `condition`

相关文档
    参考/反应系统详解.md — action + reaction 完整语义
    参考/实现参考手册.md — inHand 交互的执行时机

## 场景 12：条件伤害 / 动态数值

目标
    「每张手牌 +1 伤害」「若敌人身负中毒则额外 5 伤害」「本场每打出过 X 张攻击牌，伤害翻倍」。

涉及机制
    `params.value` 支持 `$expr` 引用
    condition 可以过滤是否触发
    accumulator 类效果（`countAndTrigger`、`accumulateAndTrigger`）

数据模板：数值依赖状态

```typescript
{
    label: "重击",
    key: "your_mod_card_heavyhit",
    tags: ["attack"],
    status: { damage: 6, cost: 2 },
    describe: [
        "造成", { key: ["status", "damage"] }, "点伤害。",
        "若目标身负中毒，额外造成 5 点伤害"
    ],
    interaction: {
        use: {
            target: { faction: "opponent" },
            effects: [
                { key: "damage", params: { value: 6 } },
                {
                    key: "damage",
                    params: { value: 5 },
                    condition: "$target.hasState(poison)"
                }
            ]
        }
    }
}
```

数据模板：多段可变次数

```typescript
{
    key: "repeatEffects",
    params: {
        times: "$owner.status(hits)",
        effects: [{ key: "damage", params: { value: 3 } }]
    }
}
```

常见变体

    引用手牌数：`params.value: "$owner.hand.length"` — 具体语法需确认参考手册
    多重条件：把 condition 表达式写成布尔组合

相关文档
    参考/实现参考手册.md — `$xxx` 表达式语法与可用字段清单

## 场景 15：消耗自身状态的攻击牌（放电 / 蓄力释放）

目标
    平时靠别的牌积累某个状态（充能 / 蓄力 / 怒气），这张牌按层数打出伤害，然后把状态清空。

涉及机制
    `$source.stateStack(stateKey)` — 读使用者自己身上的状态层数
    damage 的 `multiplier` 参数 — 最终伤害 = value × multiplier
    EffectUnit 的 `target` 字段 — 让单条效果打到与卡牌默认目标不同的对象上

数据模板

```typescript
{
    label: "放电",
    tags: ["attack", "enemy"],
    status: { cost: 0, damage: 3 },
    describe: ["造成", { key: ["status", "damage"] }, "×", { $: "充能" }, "层数点伤害，", { $: "充能" }, "归零"],
    key: "enemy_card_discharge",
    interaction: {
        use: {
            target: { faction: "opponent" },
            effects: [
                { key: "damage", params: { value: 3, multiplier: "$source.stateStack(charge)" } },
                // 卡牌 target 是对手，但充能在使用者自己身上，要用 target 把清除打回自己
                { key: "removeState", params: { stateKey: "charge" }, target: "source" }
            ]
        }
    }
}
```

要点
    `use.target` 是整张卡的默认目标，攻击牌指向对手；凡是要操作**自己**身上状态/资源的效果，
    都必须单独写 `target: "source"`，否则会静默打到对手身上（打空了不报错，就是什么都不发生）
    `stateStack(charge)` 括号里填的是状态 key，不是层 key
    层数为 0 时伤害就是 0，想让「没充能时打不出」要在 use 上加 condition
    意图会把 `multiplier` 乘进显示值（2 层充能、底伤 3 → 显示 6），不要指望它自动画成 `3 × 2`

常见变体

    消耗固定层而不清空：`{ key: "changeStateStack", params: { stateKey: "charge", delta: -2 }, target: "source" }`
    按层数决定段数而不是倍率：用 `repeatEffects`，`times: "$source.stateStack(charge)"`
    消耗对手身上的状态：不写 `target`，跟着卡牌默认目标走即可

## 常见错误与修正

错误 1：直接改 Entity 属性
    错：`player.current.health.value -= 10`
    对：在 effects 里用 `damage` 或 `loseHp` 效果

错误 2：把 cost 写在顶层
    错：`{ cost: 1, status: { damage: 5 } }`
    对：`{ status: { cost: 1, damage: 5 } }`
    cost 必须在 status 内，因为它是可能被修饰器修改的属性

错误 3：target 用错格式
    错：`target: { key: "enemy" }`
    对：`target: { faction: "opponent" }` 或 `target: { faction: "enemy" }`
    「self」用 `key`，阵营用 `faction`，两者互斥

错误 4：inHand 段忘了写 use
    inHand 只描述在手时行为，卡牌被打出仍需要 use 段（即使 effects 为空数组）

错误 5：写新原子效果，而不是复用
    加 debuff 应该用 `applyState`，不要为每种状态写一个新效果函数
    专属效果（`card_xxx` 或 `organ_xxx` 前缀）只在真的没有可复用原子效果时才写

错误 6：多段攻击写成多个 damage effect
    错：3 条 `damage value:4` 并列
    对：`repeatEffects` 包裹一条 `damage`
    原因：护甲/减伤/伤害修饰器按事件结算，多个独立 effect 会各自独立触发系统副作用，语义不等价

错误 7：操作自己身上的状态却没写 `target: "source"`
    错：攻击牌的 effects 里直接写 `{ key: "removeState", params: { stateKey: "charge" } }`
    症状：伤害正常，但自己的状态怎么也不消失 —— 因为它被打到对手身上去了，对手没这个状态，静默无事发生
    对：`{ key: "removeState", params: { stateKey: "charge" }, target: "source" }`
    `removeState` / `applyState` / `gainArmor` 都不校验目标身上有没有对应东西，打空了不报错

错误 8：`stateStack(x)` 里的 x 当成层 key
    `stateStack(charge)` 读的是「charge 状态的 default 层」，不是「stacks 里 key 为 charge 的层」
    要读非 default 层用点语法：`stateStack(poison.duration)`
    空括号 `$source.stateStack()` 只在 `$source` 本身就是状态时用（状态自己的 reaction 里）
