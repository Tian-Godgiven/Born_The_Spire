# 遗物实现场景手册

面向 AI 与 Mod 开发者的场景式教程。想实现某种遗物，先在本手册找相似场景，复制模板，改数值和描述。

本手册与《新内容开发清单》的分工：
    新内容开发清单 — 添加遗物需要动的文件、RelicMap 最小字段
    本手册 — 我要做出「XX 效果的遗物」，具体数据怎么写

遗物与器官的关键区别
    遗物没有 part 字段，不占身体部位
    遗物没有 max-mass / 损坏机制，永久生效直到失去
    遗物 rarity 只有 common / uncommon / rare 三档
    遗物有 `pool` 字段决定进入哪个奖励池

---

## 使用方法

每个场景包含：
    目标 — 一句话说清楚要实现什么
    涉及机制 — 用到哪些系统
    数据模板 — 完整可复制的 RelicMap 定义
    常见变体 — 数值 / 条件小改
    相关文档 — 需要延伸阅读时的入口

## 场景 1：战斗开始触发（进战斗获得资源）

目标
    「战斗开始时获得 1 层力量」「战斗开始额外抽 2 张」。

涉及机制
    triggers 监听 `key: "battleStart"`
    reaction 段决定做什么

数据模板：战斗开始获得力量

```typescript
{
    label: "金刚杵",
    describe: ["战斗开始时", "获得力量 1 层"],
    key: "original_relic_vajra",
    rarity: "uncommon",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "owner" },
            triggers: [{
                when: "after",
                how: "take",
                key: "battleStart",
                action: "gainPower"
            }]
        }
    },
    reaction: {
        gainPower: [{
            targetType: "owner",
            key: "applyState",
            effect: [{
                key: "applyState",
                params: { stateKey: "power", stacks: 1 }
            }]
        }]
    }
}
```

数据模板：第一回合额外抽牌

```typescript
{
    label: "先手之戒",
    describe: ["第一回合", "额外抽", { key: ["status", "first-turn-draw"] }, "张牌"],
    key: "original_relic_00005",
    rarity: "common",
    pool: ["common"],
    status: { "first-turn-draw": 2 },
    interaction: {
        possess: {
            target: { key: "self" },
            effects: [],
            triggers: [{
                when: "after",
                how: "make",
                key: "battleStart",
                action: "addFirstTurnDraw"
            }]
        }
    },
    reaction: {
        addFirstTurnDraw: [{
            targetType: "owner",
            key: "addFirstTurnDrawBonus",
            effect: [{ key: "addFirstTurnDraw", params: { value: 2 } }]
        }]
    }
}
```

常见变体

    战斗开始获得护甲：reaction 换 `gainArmor`
    每 3 场战斗触发一次：加 condition 检查战斗计数
    只在精英战触发：加 condition 检查 battleType
    进入房间时触发（如"每移动 1 层 +5 金币"）：`key` 换 `roomEnter`；三方都是玩家，`how` 用 `make`/`take` 均可；不加 condition 时所有房间（战斗/事件/水池/商店/Boss/floorSelect）都算，想限定房型加 `condition: "$event.info(roomType) == battle"`

## 场景 2：战斗结束触发（回复生命 / 获得金币）

目标
    战斗胜利后自动做点事。

涉及机制
    triggers `key: "battleEnd"`

数据模板

```typescript
{
    label: "回血石",
    describe: ["战斗结束时", "回复", { key: ["status", "heal"] }, "生命"],
    key: "original_relic_00001",
    rarity: "common",
    pool: ["common"],
    status: { "heal": 5 },
    interaction: {
        possess: {
            target: { key: "self" },
            effects: [],
            triggers: [{
                when: "after",
                how: "make",
                key: "battleEnd",
                action: "healOwner"
            }]
        }
    },
    reaction: {
        healOwner: [{
            targetType: "owner",
            key: "heal",
            effect: [{ key: "heal", params: { value: 5 } }]
        }]
    }
}
```

常见变体

    只在满血时无效：condition 检查 `$owner.hpPercent < 1.0`
    按最大生命百分比回血：走 `heal` 的 `percent` 参数，例如 `{ key: "heal", params: { percent: 0.1 } }`（回 10% max，Math.floor 取整）
    只在精英战触发：condition 检查 battleType

⚠️ $xxx 表达式**不支持算术运算**，不要写 `"$owner.status(max-health) * 0.1"` 这种形式 —— ReferenceResolver 正则严格匹配 `^$xxx(...)$`，末尾多出 ` * 0.1` 会整个匹配失败。凡是"读某个值算个百分比"的需求，都要在 effect 内部实现（参考 `heal` 与 `addMaxHealthAndHeal` 的 `percent` 参数）

要点
    battleEnd 与 battleStart 是遗物最常用的两个事件
    when 用 "after"：等战斗真正结束再回血，避免被死亡结算等打断

## 场景 3：每回合开始触发（+护甲 / +力量 / 拉伤害）

目标
    「每回合开始 +N 护甲」「每回合开始 +1 力量」「每 3 回合造成 8 伤害」。
    与 battleStart 不同的是，每回合都会触发一次。

涉及机制
    triggers 监听 `key: "turnStart"`
    turnStart 事件的 source / medium / target 三方都是玩家自己，`how` 用 make / via / take 都命中，遗物惯例用 `make`

数据模板：每回合 +N 护甲

```typescript
{
    label: "卫士纹章",
    describe: ["每回合开始时", "获得", { key: ["status", "armor-gain"] }, "点护甲"],
    key: "original_relic_guardian_emblem",
    rarity: "common",
    pool: ["common"],
    status: { "armor-gain": 3 },
    interaction: {
        possess: {
            target: { key: "owner" },
            triggers: [{
                when: "after",
                how: "make",
                key: "turnStart",
                action: "gainArmorOnTurnStart"
            }]
        }
    },
    reaction: {
        gainArmorOnTurnStart: [{
            targetType: "owner",
            key: "gainArmor",
            effect: [{ key: "gainArmor", params: { value: 3 } }]
        }]
    }
}
```

常见变体

    每回合 +力量：reaction effect 换 `{ key: "applyState", params: { stateKey: "power", stacks: 1 } }`
    每回合抽 1 张：reaction effect 换 `{ key: "drawFromDrawPile", params: { value: 1 } }`
    每 N 回合才触发一次：加冷却计数（`status.cooldown` + condition 检查），参考"节拍器"
    每 N 回合对场上两个不同随机目标分别伤害/治疗：抄「祸福轮」
        第一条 `allEntities.random`
        第二条 `allEntities.except(pickedTargets).random`
        抽空（场上只剩 1 人）那一条跳过
        需要回头点名同一个单位时才写 `as: "hurt"`，这件遗物不用
    只在**第 N 回合**触发（例：第 1 回合 +2 抽牌）：加 `condition: "$battle.turn === N"`；每场战斗都会重新触发，与 disableUntil 的"用一次就锁"不同
    每回合不同效果（例：第 1 回合 +2 抽、第 2 回合 -1 抽）：写多个 trigger，各自带 `$battle.turn === N` condition
    低血/满血才触发：加 condition，参考场景 8
    回合结束触发：`key` 换 `turnEnd`

要点

    turnStart 与 battleStart 的区别：**不需要 `disableUntil: "battleEnd"`**——每回合都要触发才是设计意图，battleStart 才需要"一场战斗只触发一次"的限制
    与场景 5（addStatusBase 永久改常量）的区别：turnStart 每回合执行一次动作（护甲/伤害/抽卡），addStatusBase 是永久改属性上限或抽牌数常量
    turnEnd 与 turnStart 完全对称，都是玩家自己的三方事件

## 场景 4：累计触发（每 X 次做一次）

目标
    「每受到 10 点伤害回复 1 生命」「每打出 5 张牌抽 1 张」。

涉及机制
    效果：`accumulateAndTrigger`
    status 存 point 和 maxPoint
    badges 字段让 UI 显示进度

数据模板：吸血徽章

```typescript
{
    label: "吸血徽章",
    describe: [
        "每累积", { key: ["status", "point"] }, "/", { key: ["status", "maxPoint"] }, "点伤害",
        "回复 1 生命"
    ],
    key: "original_relic_vampiric_badge",
    rarity: "uncommon",
    pool: ["common"],
    status: { "point": 0, "maxPoint": 10 },
    badges: [{ type: "counter", status: "point", maxStatus: "maxPoint" }],
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "accumulateAndTrigger",
                params: {
                    pointKey: "point",
                    on: { when: "after", how: "take", key: ["attack", "damage"] },
                    gain: "$triggerEffect.params(value)",
                    threshold: 10,
                    consume: 10,
                    targetType: "owner",
                    effects: [{ key: "heal", params: { value: 1 } }]
                }
            }]
        }
    }
}
```

数据模板：学者笔记（每 5 张牌抽 1）

```typescript
{
    label: "学者笔记",
    describe: ["每打出", { key: ["status", "maxPoint"] }, "张牌", "抽 1 张牌"],
    key: "original_relic_scholar_note",
    rarity: "common",
    pool: ["common"],
    status: { "point": 0, "maxPoint": 5 },
    badges: [{ type: "counter", status: "point", maxStatus: "maxPoint" }],
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "accumulateAndTrigger",
                params: {
                    pointKey: "point",
                    on: { when: "after", how: "make", key: "useCard" },
                    gain: 1,
                    threshold: 5,
                    consume: 5,
                    targetType: "owner",
                    effects: [{ key: "drawFromDrawPile", params: { value: 1 } }]
                }
            }]
        }
    }
}
```

参数说明

    `pointKey` — status 中的计数字段
    `on` — 什么事件让计数增加（when/how/key）
    `gain` — 每次事件增加多少（可为常量或表达式）
    `threshold` — 触发阈值
    `consume` — 触发后扣减多少（通常等于 threshold，也可为 0 表示不清零）
    `targetType` — 触发效果作用于谁
    `effects` — 触发时执行的效果

badges 说明
    `{ type: "counter", status: "point", maxStatus: "maxPoint" }` 让 UI 显示 point / maxPoint 进度圈
    不写 badges 也能工作，只是玩家看不到进度
    完整的徽章类型、位置、样式配置见后文《徽章配置参考》章节

## 场景 5：修改战斗规则（每回合额外抽 X 张）

目标
    永久改动战斗中的某个规则常量（每回合抽牌数、能量上限）。

涉及机制
    效果：`addStatusBase` — 给一个基础属性加固定值

数据模板

```typescript
{
    label: "学者之戒",
    describe: ["每回合多抽", { key: ["status", "extra-draw"] }, "张牌"],
    key: "original_relic_00004",
    rarity: "common",
    pool: ["common"],
    status: { "extra-draw": 2 },
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "addStatusBase",
                params: {
                    statusKey: "draw-per-turn",
                    value: 2,
                    type: "additive"
                }
            }]
        }
    }
}
```

常见变体

    +1 能量：statusKey 换 `"max-energy"`
    每回合额外弃牌：statusKey 换成弃牌相关字段
    +最大生命上限：用 `addMaxHealthAndHeal`（会同时回满新增部分）

要点
    走 addStatusBase 就走「基础属性 + 修饰器」路径，遗物失去时自动回滚
    不需要写 lose 段清理，参考「修饰器清理是自动的」原则

## 场景 6：解锁行动（水池 / 器官奖励）

目标
    让水池房间出现新选项、或器官奖励界面出现新动作。

涉及机制
    效果：`enablePoolAction` / `enableOrganRewardAction`
    lose 段配对：`disablePoolAction` / `disableOrganRewardAction`

数据模板

```typescript
{
    label: "血祭之石",
    describe: ["战斗奖励中，器官选择时可以选择献祭，回复生命值"],
    key: "original_relic_sacrifice",
    rarity: "uncommon",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "enableOrganRewardAction",
                params: { actionKey: "sacrifice" }
            }]
        },
        lose: {
            target: { key: "owner" },
            effects: [{
                key: "disableOrganRewardAction",
                params: { actionKey: "sacrifice" }
            }]
        }
    }
}
```

常见变体

    水池锻炼类：`enablePoolAction` + actionKey: "exercise"
    多解锁：effects 数组里堆多条 enable 效果

⚠️ 这是极少数需要写 lose 段的场景之一
    因为 enabledOrganRewardActions / enabledPoolActions 是 Player 上的 Set，不是走 StatusModifier
    所以失去遗物时必须显式移除，不然遗物没了行动还留着

## 场景 7：常驻属性（一次性永久加成）

目标
    「获得时最大生命 +5」「获得时能量上限 +1」— 拿到就永久生效。

涉及机制
    interaction.possess.effects 里放 `addMaxHealthAndHeal` / `addStatusBase`

数据模板

```typescript
{
    label: "草莓",
    describe: ["获得时", "最大生命 +5"],
    key: "original_relic_00006",
    rarity: "common",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "addMaxHealthAndHeal",
                params: { value: 5 }
            }]
        }
    }
}
```

常见变体

    只加上限不回血：换 `addStatusBase`，statusKey: "max-health"
    减最大生命换其他增益：先 `addStatusBase` 负值再 `applyState` buff
    +多种属性：effects 数组堆多条

要点
    这类遗物不需要 triggers/reaction，只用一次性 effects
    失去时属性自动回滚（StatusModifier 系统负责）

## 场景 8：条件触发（低血 / 满血 / 手牌数量）

目标
    「生命值低于 50% 时受到伤害 -1」「满血时造成伤害 +3」。

涉及机制
    triggers 里加 `condition` 字段
    reaction 段做实际动作

数据模板

```typescript
{
    label: "低血战旗",
    describe: ["生命值低于 50% 时", "造成伤害 +3"],
    key: "original_relic_low_health_banner",
    rarity: "rare",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "owner" },
            triggers: [{
                when: "before",
                how: "make",
                key: "attack",
                action: "lowHpBoost",
                condition: "$owner.hpPercent < 0.5"
            }]
        }
    },
    reaction: {
        lowHpBoost: [{
            targetType: "triggerEffect",
            key: "boost",
            effect: [{ key: "modifyDamageValue", params: { delta: 3 } }]
        }]
    }
}
```

常见变体

    满血才生效：condition 改 `$owner.hpPercent >= 1.0`
    手牌数 >=X：condition 改 `$owner.hand.length >= 5`（具体语法查参考手册）
    敌人身负 debuff 时：condition 改 `$target.hasState(vulnerable)`
    施加 debuff 时才生效（读 Effect 参数分类）：`condition: "$triggerEffect.stateCategory() == debuff"`（配 `key: applyState` 触发器）
    能量归零时（"祈愿石"）：after/take/`loseEnergy` + `condition: "$owner.current(energy) == 0"`
        after 时点上能量已扣完，直接读 current 即可判定是否触底。loseEnergy 是所有能量流失
        路径的统一广播 key（payEnergy 也委派到它），一条触发器覆盖打牌 / 主动能力 / 直接扣。

相关文档
    参考/实现参考手册.md — condition 表达式语法

## 场景 9：限次触发（disableUntil）

目标
    「战斗中只触发一次」。

涉及机制
    triggers 里加 `disableUntil: "battleEnd"`

数据模板

```typescript
{
    label: "战前仪式",
    describe: ["战斗开始时", "获得 3 层力量"],
    key: "original_relic_pre_battle_ritual",
    rarity: "uncommon",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "owner" },
            triggers: [{
                when: "after",
                how: "take",
                key: "battleStart",
                disableUntil: "battleEnd",
                action: "gainPower3"
            }]
        }
    },
    reaction: {
        gainPower3: [{
            targetType: "owner",
            key: "applyState",
            effect: [{ key: "applyState", params: { stateKey: "power", stacks: 3 } }]
        }]
    }
}
```

要点

    `disableUntil` 目前**只支持 `"battleEnd"`**（ItemModifier.ts:138、trigger.d.ts:119）
    battleStart 触发 → 战斗中即使再触发 battleStart 也不会重复（防止意外级联）

要做「本回合首次」而不是「战斗中首次」

    disableUntil 不认 turnEnd，改用**遗物自带 status 做冷却锁**（参考"节拍器"和"鹫发"）：
    status: { used: 0 }
    触发 A（真正效果）：condition: "$item.status(used) == 0"，reaction 里 setBaseStatus item.used = 1
    触发 B（回合开始重置）：after/make/turnStart，reaction 里 setBaseStatus item.used = 0

过滤"非临时器官/非临时卡"

    用 `condition: { not: "$medium.isTemporary()" }`；`isTemporary()` accessor 读实体的 `isTemporary` 字段

## 场景 10：主动能力（可发动的遗物）

目标
    遗物在玩家回合可以主动激活，如「投掷炸药瓶」「射击手枪」。

涉及机制
    `activeAbilities: ActiveAbility[]` — 遗物也支持主动能力（与器官相同）
    interaction 可以为空对象 `{}`

数据模板：单次使用

```typescript
{
    label: "爆炸药瓶",
    key: "original_relic_00002",
    describe: ["对所有敌人造成 10 点伤害（一次性）"],
    rarity: "uncommon",
    pool: ["common"],
    status: { "damage": 10 },
    interaction: {},
    activeAbilities: [{
        key: "throw",
        label: "投掷",
        describe: ["对所有敌人造成 10 点伤害"],
        usage: {
            type: "allTargets",
            target: { faction: "enemy", number: "all" }
        },
        disableAfterUse: true,
        effects: [{ key: "attack", params: { value: 10 } }]
    }]
}
```

数据模板：带冷却

```typescript
{
    label: "袖珍手枪",
    key: "original_relic_pistol",
    rarity: "uncommon",
    pool: ["common"],
    activeAbilities: [{
        key: "shoot",
        label: "射击",
        describe: ["对指定敌人造成 10 点伤害"],
        usage: {
            type: "selectTarget",
            target: { faction: "enemy" }
        },
        restrictions: {
            cooldown: 3,
            conditions: { scene: "combat" }
        },
        effects: [{ key: "attack", params: { value: 10 } }]
    }],
    interaction: {}
}
```

要点

    `usage.type` — direct / selectTarget / allTargets / toggle
    `disableAfterUse: true` — 使用后灰掉（单次遗物专用）
    `restrictions.cooldown` — 回合数
    `restrictions.conditions.scene: "combat"` — 只能在战斗中使用
    UI 会自动根据 badges / cooldown 状态显示可用性

相关文档
    参考/实现参考手册.md — abilityCharges / cooldown 效果 key

## 场景 11：获得时让玩家选择，后续触发时消费

目标
    遗物获得时立即弹出交互（例如选牌 / 选敌人 / 选状态），把结果存到遗物自身，后续满足条件时读出来用。以「口香糖」为例：获得时选一张卡，第 2 回合把它从任意堆抓到手牌。

涉及机制
    possess 交互中的 effect 用来「让玩家选择并写入 status」
    存的字段走 Status 系统（string 型 status，隐藏且不作为徽章显示）—— 不要直接给 Entity 加普通字段
    `chooseAndMarkCard` — 弹选牌窗，把选中卡的 __id 写到 event.medium.status[storeKey]，如未预声明会自动创建一个隐藏 status
    `$owner.status(storeKey)` 在后续 reaction 的 effect 参数里读回
    `retrieveCardsToHand` 支持 `cardId` 精确匹配 + `sourcePile: "any"` 依次搜三堆

数据模板

```typescript
{
    label: "口香糖",
    key: "original_relic_bubble_gum",
    describe: ["伸缩自如的爱❤️"],
    rarity: "rare",
    pool: ["rare"],
    // 建议在这里显式声明用于记忆的 status（字符串型，全隐藏）
    status: {
        markedCardId: { label: "记号卡id", value: "", hidden: true, display: false, calc: false }
    },
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "chooseAndMarkCard",
                params: {
                    title: "选一张牌作为记号",
                    description: "第 2 回合开始时，它会从抽/弃/消耗牌堆移入你的手牌",
                    fromPile: "deck",
                    storeKey: "markedCardId"
                }
            }],
            triggers: [{
                when: "after",
                how: "take",
                key: "turnStart",
                condition: "$battle.turn == 2",
                disableUntil: "battleEnd",
                action: "pullMarkedCard"
            }]
        }
    },
    reaction: {
        pullMarkedCard: [{
            targetType: "owner",
            key: "retrieveCardsToHand",
            effect: [{
                key: "retrieveCardsToHand",
                params: {
                    sourcePile: "any",
                    cardId: "$owner.status(markedCardId)"
                }
            }]
        }]
    }
}
```

要点
    存的字段一定走 Status，不要写 `item.xxx = ...`。Status 值天然支持 `number | string`，字符串型 status 不参与修饰器计算（`calc: false` + `hidden: true` + `display: false`）
    如果不预声明 markedCardId，chooseAndMarkCard 会自动创建，但显式声明更清晰、Debug 工具能看到字段
    读取时用 `$owner.status(storeKey)`
    possess.effects 是异步执行（弹窗要 await），但 triggers 是同步注册的，选卡完成前触发器已经挂好
    卡在触发时已被删除 / 不在三堆中，retrieveCardsToHand 静默失败，不报错
    `disableUntil: "battleEnd"` 必写，否则第 3、4、5 回合会重复触发

常见变体

    选敌人存 id — 目前无对应原子，可仿照 chooseAndMarkCard 写一个 chooseAndMarkTarget，同样走 Status 存
    选牌多张 — 当前 chooseAndMarkCard 固定 min/max = 1；多选需扩展参数
    换触发条件 — 换 action.when/how/key 与 condition 即可，存与读的两端不变

## 场景 12：不同稀有度池

目标
    控制遗物出现在哪些奖励场景。

涉及机制
    `rarity` — 稀有度（common / uncommon / rare）
    `pool` — 出现的池数组

数据模板

```typescript
// 出现在普通奖励池
pool: ["common"]

// 只出现在商店
pool: ["shop"]

// Boss 战掉落
pool: ["boss"]

// 兜底池（其他池抽完才出）
pool: ["fallback"]

// 多个池都能出
pool: ["common", "shop"]
```

要点

    rarity 决定颜色和稀有权重
    pool 决定出现场景
    没写 pool 的遗物不会被自动分配（只能通过效果直接获得，比如活动奖励）

## 场景 13：物品失效（disabled 语法糖）

目标
    「用完 N 场之后不再生效但仍留在栏位里」「触发过一次后仍然显示但不再响应」。
    区别于场景 9 的 disableUntil（一场战斗内失效）和场景 9 底部的 status 冷却锁（回合级冷却）—— 本场景是**跨战斗、跨事件、语义清晰的"失效"标志**。

涉及机制
    通用 status `disabled`（`statusMap.ts` 已注册，category:"special", hidden:true, notNegative:true）
    遗物在 status 里初始化 `disabled: 0`
    trigger 加 `condition: "$source.status(disabled) == 0"` —— 失效时短路
    某个 reaction 里用 `setBaseStatus { statusKey: "disabled", value: 1 }` 触发失效

数据模板：跨 N 场战斗后失效（无常之神的祝福）

```typescript
{
    label: "无常之神的祝福",
    describe: [
        "接下来 ", { key: ["status", "battles-remaining"] }, " 场战斗，",
        "战斗开始时获得 3 层力量和 3 层敏捷"
    ],
    key: "relic_god_of_chance_blessing",
    rarity: "rare",
    pool: ["exclusive"],
    status: {
        "battles-remaining": 3,
        "maxBattles": 3,
        "disabled": 0
    },
    badges: [
        { type: "cooldown", status: "battles-remaining" }
    ],
    interaction: {
        possess: {
            target: { key: "owner" },
            triggers: [
                // 主触发：未失效才响应
                {
                    when: "after",
                    how: "take",
                    key: "battleStart",
                    level: 1,
                    condition: "$source.status(disabled) == 0",
                    action: "grantBlessing"
                },
                // 收尾：本次是最后一场
                {
                    when: "after",
                    how: "take",
                    key: "battleStart",
                    level: 0,
                    condition: "$source.status(battles-remaining) <= 0",
                    action: "markDisabled"
                }
            ]
        }
    },
    reaction: {
        grantBlessing: [
            {
                targetType: "owner",
                key: "gainPowerDexterity",
                effect: [
                    { key: "applyState", params: { stateKey: "power", stacks: 3 } },
                    { key: "applyState", params: { stateKey: "dexterity", stacks: 3 } }
                ]
            },
            {
                targetType: "triggerSource",
                key: "decrementRemaining",
                effect: [{
                    key: "decrementStatus",
                    params: { statusKey: "battles-remaining", amount: 1 }
                }]
            }
        ],
        markDisabled: [{
            targetType: "triggerSource",
            key: "markDisabled",
            effect: [{
                key: "setBaseStatus",
                params: { statusKey: "disabled", value: 1 }
            }]
        }]
    }
}
```

要点

    disabled 不是"删除物品"—— 物品仍在栏位、栏位仍占用；只是不再响应触发器
    每个想失效的 trigger 都要**自行加 condition** —— 目前没有框架级的全局短路（这是主动设计取舍：局部机制，未来发现广泛需求再升 Trigger 层）
    跟 `disableUntil: "battleEnd"` 的区别：disableUntil 是"本战斗触发过就该战斗内失效"，disabled 是"任何时候由 reaction 明确置 1 即永久失效"
    跟场景 9 底部的 status 冷却锁的区别：冷却锁是"每回合重置"，disabled 只有 setBaseStatus 才会切回 0
    可复原：任何 reaction 里 `setBaseStatus { statusKey: "disabled", value: 0 }` 就能重新激活
    双 trigger + level 排序（level 1 先跑主触发、level 0 后跑收尾）是本场景的关键模式，保证收尾能读到主触发已扣减过的 status

跨类型复用

    这个模式对遗物 / 器官 / 卡都成立 —— 底层就是 status 语法糖类，任何 Entity 都能挂
    器官已有的 `isDisabled: boolean` raw field（Organ.ts:91）是历史包袱，新代码不要再用它 —— 走这里的 disabled status 才是标准通路

## 徽章配置参考

角标（badges）在遗物 / 器官卡片四个角显示状态信息。玩家看到进度圈、冷却数、模式标识等，能预判触发时机。徽章只影响 UI，不影响机制；不写也能工作。

类型定义位于 `src/core/types/BadgeConfig.ts`。

### 四种类型（默认位置与颜色）

    indicator  左上，蓝色  类型标识 / 固定文字（如 "稀有" "⚡"）
    state      右上，紫色  状态或模式（用 displayMap 映射，如 偶/奇）
    counter    左下，绿色  计数进度（如 3/10）
    cooldown   右下，灰色  冷却倒数（0 时显示 ✓）

位置和颜色都是默认；每种类型可用 `position` / `style` 覆盖。

### 数据来源（三选一）

    status / maxStatus       从遗物自身 entity.status[key] 读值（最常见）
    value / maxValue         通用 `$xxx` 引用表达式（读 owner 属性等外部值）
    text                     固定文字

### 现有用例

节拍器（cooldown 型，每 3 回合造成 8 伤害）

```typescript
status: { cooldown: 3, maxCooldown: 3 }
badges: [{ type: "cooldown", status: "cooldown" }]
```

右下显示当前 cooldown 数，玩家知道还剩几回合触发。

吸血徽章 / 第六指 / 有生命活铁（counter 型，累计触发）

```typescript
status: { point: 0, maxPoint: 10 }
badges: [{ type: "counter", status: "point", maxStatus: "maxPoint" }]
```

左下显示 "point/maxPoint" 进度圈。搭配 accumulateAndTrigger 用。

过载电池（counter 型，"已用次数"变体）

```typescript
status: { used: 0, maxUse: 1, /* ... */ }
badges: [{ type: "counter", status: "used", maxStatus: "maxUse" }]
```

显示"本战斗触发过几次 / 最大几次"，用于限次型遗物。

### counter vs cooldown 怎么选

    accumulateAndTrigger 型 → counter（点数由 0 累计到阈值触发）
    每回合固定 -1 型      → cooldown（数字倒数到 0 触发并重置）

两者语义不同：counter 是"往上加"（从 0 到 maxPoint），cooldown 是"往下减"（从 max 到 0）。看你 status 的自然读法选择。

### 条件显示

```typescript
badges: [{ type: "cooldown", status: "cooldown", showWhen: "$scene == combat" }]
```

`showWhen` 复用 ConditionSystem，只在满足条件时显示。常用于"仅战斗中相关"的状态。

### 覆盖位置和样式

```typescript
badges: [{
    type: "counter",
    status: "point",
    maxStatus: "maxPoint",
    position: "top-right",
    style: { backgroundColor: "#ff0000" }
}]
```

一般不建议覆盖 —— 默认位置/颜色能保证跨遗物的视觉一致性，玩家一看颜色就知道类型。只在同一个遗物有多个同型 badges 需要错位显示时才用。

### 多 badges 同时使用

一个遗物可以配置多个 badges，同时显示不同角上的信息。例如：

```typescript
badges: [
    { type: "counter",   status: "point", maxStatus: "maxPoint" },  // 左下：累计进度
    { type: "indicator", text: "限战斗" }                            // 左上：附加标识
]
```

### 要点

    accumulateAndTrigger 型 / 冷却型遗物强烈建议加 badges，否则玩家无法预判触发时机
    counter 的 `status` 是当前值字段，`maxStatus` 是分母字段；两个字段都要在 `status` 里声明
    cooldown 只需要 `status`（一个数字），maxCooldown 用于 reset 效果读取，不作为徽章分母
    `value` 用于跨实体读值（如 `$owner.stateStack(power)`），普通遗物内部计数用 `status` 即可

## 常见错误与修正

错误 1：为了「失去时清理」写 lose 段
    错：给一个普通「+3 力量」遗物写 lose 段去减掉力量
    对：能通过 StatusModifier / ContentModifier 提供的属性，失去自动回滚，不写 lose

错误 2：什么都不写 lose 段
    错：解锁行动型遗物（enablePoolAction）不写 lose disablePoolAction
    对：只有 Set-based 的开关状态需要显式 lose，这是例外

错误 3：battleStart 忘了 disableUntil 导致每回合都触发
    症状：某些遗物设计成战斗开始一次，结果每次战斗都触发多次
    修复：`disableUntil: "battleEnd"`

错误 4：when 用 "before" 应该用 "after"
    错：battleStart when: "before" — 战斗还没真正开始，一些状态可能没准备好
    对：想在战斗真正开始后触发用 "after"，想在触发前拦截才用 "before"

错误 5：pool 写错分类
    症状：期望的遗物在商店没出现
    修复：确认 `pool: ["shop"]` 拼写正确、且不是 `pool: "shop"`（必须是数组）

错误 6：$triggerEffect.params(value) 拿不到值
    症状：累计伤害的遗物永远不涨
    原因：不同事件的 params 名可能不同，damage 事件通常是 `value`，applyState 是 `stacks`
    修复：查看事件源头的 effectMap 定义，或用具体常量值 `gain: 1`

错误 8：效果参数里 `$owner.current(energy)` 报没有当前值
    症状：回合结束抛 `[EntityAccessor] 实体 "能量沉淀" 没有当前值 "energy"`
    原因：效果参数里 `$owner` / `$item` 都是遗物自己，遗物没有 energy。条件里的 `$owner` 才是持有者（祈愿石那种 condition 不要照搬到 params）
    对：读持有者能量用 `sourceTargetType: "triggerOwner"` + `"$source.current(energy)"`，写入仍 `targetType: "triggerSource"`（现行：能量沉淀）
