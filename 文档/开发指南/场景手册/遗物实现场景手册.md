# 遗物实现场景手册

面向 AI 与 Mod 开发者的场景式教程。想实现某种遗物，先在本手册找相似场景，复制模板，改数值和描述。

本手册与《新内容开发清单》的分工：
    新内容开发清单 — 添加遗物需要动的文件、RelicMap 最小字段
    本手册 — 我要做出「XX 效果的遗物」，具体数据怎么写

遗物与器官的关键区别
    遗物没有 part 字段，不占身体部位
    遗物没有 max-mass / 损坏机制，永久生效直到失去
    遗物 rarity 只有 common / uncommon / rare 三档
    遗物有 `pool` 字段决定进入哪个奖励池

---

## 使用方法

每个场景包含：
    目标 — 一句话说清楚要实现什么
    涉及机制 — 用到哪些系统
    数据模板 — 完整可复制的 RelicMap 定义
    常见变体 — 数值 / 条件小改
    相关文档 — 需要延伸阅读时的入口

## 场景 1：战斗开始触发（进战斗获得资源）

目标
    「战斗开始时获得 1 层力量」「战斗开始额外抽 2 张」。

涉及机制
    triggers 监听 `key: "battleStart"`
    reaction 段决定做什么

数据模板：战斗开始获得力量

```typescript
{
    label: "金刚杵",
    describe: ["战斗开始时", "获得力量 1 层"],
    key: "original_relic_vajra",
    rarity: "uncommon",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "owner" },
            triggers: [{
                when: "after",
                how: "take",
                key: "battleStart",
                action: "gainPower"
            }]
        }
    },
    reaction: {
        gainPower: [{
            targetType: "owner",
            key: "applyState",
            effect: [{
                key: "applyState",
                params: { stateKey: "power", stacks: 1 }
            }]
        }]
    }
}
```

数据模板：第一回合额外抽牌

```typescript
{
    label: "先手之戒",
    describe: ["第一回合", "额外抽", { key: ["status", "first-turn-draw"] }, "张牌"],
    key: "original_relic_00005",
    rarity: "common",
    pool: ["common"],
    status: { "first-turn-draw": 2 },
    interaction: {
        possess: {
            target: { key: "self" },
            effects: [],
            triggers: [{
                when: "after",
                how: "make",
                key: "battleStart",
                action: "addFirstTurnDraw"
            }]
        }
    },
    reaction: {
        addFirstTurnDraw: [{
            targetType: "owner",
            key: "addFirstTurnDrawBonus",
            effect: [{ key: "addFirstTurnDraw", params: { value: 2 } }]
        }]
    }
}
```

常见变体

    战斗开始获得护甲：reaction 换 `gainArmor`
    每 3 场战斗触发一次：加 condition 检查战斗计数
    只在精英战触发：加 condition 检查 battleType

## 场景 2：战斗结束触发（回复生命 / 获得金币）

目标
    战斗胜利后自动做点事。

涉及机制
    triggers `key: "battleEnd"`

数据模板

```typescript
{
    label: "回血石",
    describe: ["战斗结束时", "回复", { key: ["status", "heal"] }, "生命"],
    key: "original_relic_00001",
    rarity: "common",
    pool: ["common"],
    status: { "heal": 5 },
    interaction: {
        possess: {
            target: { key: "self" },
            effects: [],
            triggers: [{
                when: "after",
                how: "make",
                key: "battleEnd",
                action: "healOwner"
            }]
        }
    },
    reaction: {
        healOwner: [{
            targetType: "owner",
            key: "heal",
            effect: [{ key: "heal", params: { value: 5 } }]
        }]
    }
}
```

常见变体

    只在满血时无效：condition 检查 `$owner.hpPercent < 1.0`
    按最大生命百分比回：`params.value: "$owner.status(max-health) * 0.1"`
    只在精英战触发：condition 检查 battleType

要点
    battleEnd 与 battleStart 是遗物最常用的两个事件
    when 用 "after"：等战斗真正结束再回血，避免被死亡结算等打断

## 场景 3：累计触发（每 X 次做一次）

目标
    「每受到 10 点伤害回复 1 生命」「每打出 5 张牌抽 1 张」。

涉及机制
    效果：`accumulateAndTrigger`
    status 存 point 和 maxPoint
    badges 字段让 UI 显示进度

数据模板：吸血徽章

```typescript
{
    label: "吸血徽章",
    describe: [
        "每累积", { key: ["status", "point"] }, "/", { key: ["status", "maxPoint"] }, "点伤害",
        "回复 1 生命"
    ],
    key: "original_relic_vampiric_badge",
    rarity: "uncommon",
    pool: ["common"],
    status: { "point": 0, "maxPoint": 10 },
    badges: [{ type: "counter", status: "point", maxStatus: "maxPoint" }],
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "accumulateAndTrigger",
                params: {
                    pointKey: "point",
                    on: { when: "after", how: "take", key: "damage" },
                    gain: "$triggerEffect.params(value)",
                    threshold: 10,
                    consume: 10,
                    targetType: "owner",
                    effects: [{ key: "heal", params: { value: 1 } }]
                }
            }]
        }
    }
}
```

数据模板：学者笔记（每 5 张牌抽 1）

```typescript
{
    label: "学者笔记",
    describe: ["每打出", { key: ["status", "maxPoint"] }, "张牌", "抽 1 张牌"],
    key: "original_relic_scholar_note",
    rarity: "common",
    pool: ["common"],
    status: { "point": 0, "maxPoint": 5 },
    badges: [{ type: "counter", status: "point", maxStatus: "maxPoint" }],
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "accumulateAndTrigger",
                params: {
                    pointKey: "point",
                    on: { when: "after", how: "make", key: "useCard" },
                    gain: 1,
                    threshold: 5,
                    consume: 5,
                    targetType: "owner",
                    effects: [{ key: "drawFromDrawPile", params: { value: 1 } }]
                }
            }]
        }
    }
}
```

参数说明

    `pointKey` — status 中的计数字段
    `on` — 什么事件让计数增加（when/how/key）
    `gain` — 每次事件增加多少（可为常量或表达式）
    `threshold` — 触发阈值
    `consume` — 触发后扣减多少（通常等于 threshold，也可为 0 表示不清零）
    `targetType` — 触发效果作用于谁
    `effects` — 触发时执行的效果

badges 说明
    `{ type: "counter", status: "point", maxStatus: "maxPoint" }` 让 UI 显示 point / maxPoint 进度圈
    不写 badges 也能工作，只是玩家看不到进度

## 场景 4：修改战斗规则（每回合额外抽 X 张）

目标
    永久改动战斗中的某个规则常量（每回合抽牌数、能量上限）。

涉及机制
    效果：`addStatusBase` — 给一个基础属性加固定值

数据模板

```typescript
{
    label: "学者之戒",
    describe: ["每回合多抽", { key: ["status", "extra-draw"] }, "张牌"],
    key: "original_relic_00004",
    rarity: "common",
    pool: ["common"],
    status: { "extra-draw": 2 },
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "addStatusBase",
                params: {
                    statusKey: "draw-per-turn",
                    value: 2,
                    type: "additive"
                }
            }]
        }
    }
}
```

常见变体

    +1 能量：statusKey 换 `"max-energy"`
    每回合额外弃牌：statusKey 换成弃牌相关字段
    +最大生命上限：用 `addMaxHealthAndHeal`（会同时回满新增部分）

要点
    走 addStatusBase 就走「基础属性 + 修饰器」路径，遗物失去时自动回滚
    不需要写 lose 段清理，参考「修饰器清理是自动的」原则

## 场景 5：解锁行动（水池 / 器官奖励）

目标
    让水池房间出现新选项、或器官奖励界面出现新动作。

涉及机制
    效果：`enablePoolAction` / `enableOrganRewardAction`
    lose 段配对：`disablePoolAction` / `disableOrganRewardAction`

数据模板

```typescript
{
    label: "血祭之石",
    describe: ["战斗奖励中，器官选择时可以选择献祭，回复生命值"],
    key: "original_relic_sacrifice",
    rarity: "uncommon",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "enableOrganRewardAction",
                params: { actionKey: "sacrifice" }
            }]
        },
        lose: {
            target: { key: "owner" },
            effects: [{
                key: "disableOrganRewardAction",
                params: { actionKey: "sacrifice" }
            }]
        }
    }
}
```

常见变体

    水池锻炼类：`enablePoolAction` + actionKey: "exercise"
    多解锁：effects 数组里堆多条 enable 效果

⚠️ 这是极少数需要写 lose 段的场景之一
    因为 enabledOrganRewardActions / enabledPoolActions 是 Player 上的 Set，不是走 StatusModifier
    所以失去遗物时必须显式移除，不然遗物没了行动还留着

## 场景 6：常驻属性（一次性永久加成）

目标
    「获得时最大生命 +5」「获得时能量上限 +1」— 拿到就永久生效。

涉及机制
    interaction.possess.effects 里放 `addMaxHealthAndHeal` / `addStatusBase`

数据模板

```typescript
{
    label: "草莓",
    describe: ["获得时", "最大生命 +5"],
    key: "original_relic_00006",
    rarity: "common",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "addMaxHealthAndHeal",
                params: { value: 5 }
            }]
        }
    }
}
```

常见变体

    只加上限不回血：换 `addStatusBase`，statusKey: "max-health"
    减最大生命换其他增益：先 `addStatusBase` 负值再 `applyState` buff
    +多种属性：effects 数组堆多条

要点
    这类遗物不需要 triggers/reaction，只用一次性 effects
    失去时属性自动回滚（StatusModifier 系统负责）

## 场景 7：条件触发（低血 / 满血 / 手牌数量）

目标
    「生命值低于 50% 时受到伤害 -1」「满血时造成伤害 +3」。

涉及机制
    triggers 里加 `condition` 字段
    reaction 段做实际动作

数据模板

```typescript
{
    label: "低血战旗",
    describe: ["生命值低于 50% 时", "造成伤害 +3"],
    key: "original_relic_low_health_banner",
    rarity: "rare",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "owner" },
            triggers: [{
                when: "before",
                how: "make",
                key: "damage",
                action: "lowHpBoost",
                condition: "$owner.hpPercent < 0.5"
            }]
        }
    },
    reaction: {
        lowHpBoost: [{
            targetType: "triggerEffect",
            key: "boost",
            effect: [{ key: "modifyDamageValue", params: { delta: 3 } }]
        }]
    }
}
```

常见变体

    满血才生效：condition 改 `$owner.hpPercent >= 1.0`
    手牌数 >=X：condition 改 `$owner.hand.length >= 5`（具体语法查参考手册）
    敌人身负 debuff 时：condition 改 `$target.hasState(vulnerable)`

## 场景 8：限次触发（disableUntil）

目标
    「战斗中只触发一次」「本回合只触发一次」。

涉及机制
    triggers 里加 `disableUntil: "battleEnd"` 或 `disableUntil: "turnEnd"`

数据模板

```typescript
{
    label: "战前仪式",
    describe: ["战斗开始时", "获得 3 层力量"],
    key: "original_relic_pre_battle_ritual",
    rarity: "uncommon",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "owner" },
            triggers: [{
                when: "after",
                how: "take",
                key: "battleStart",
                disableUntil: "battleEnd",
                action: "gainPower3"
            }]
        }
    },
    reaction: {
        gainPower3: [{
            targetType: "owner",
            key: "applyState",
            effect: [{ key: "applyState", params: { stateKey: "power", stacks: 3 } }]
        }]
    }
}
```

要点

    `disableUntil` 值在指定事件发生前，本触发器不会再次响应
    battleStart 触发 → 战斗中即使再触发 battleStart 也不会重复（防止意外级联）
    battleEnd / turnEnd / roomExit 等都可以作为解禁点

## 场景 9：主动能力（可发动的遗物）

目标
    遗物在玩家回合可以主动激活，如「投掷炸药瓶」「射击手枪」。

涉及机制
    `activeAbilities: ActiveAbility[]` — 遗物也支持主动能力（与器官相同）
    interaction 可以为空对象 `{}`

数据模板：单次使用

```typescript
{
    label: "爆炸药瓶",
    key: "original_relic_00002",
    describe: ["对所有敌人造成 10 点伤害（一次性）"],
    rarity: "uncommon",
    pool: ["common"],
    status: { "damage": 10 },
    interaction: {},
    activeAbilities: [{
        key: "throw",
        label: "投掷",
        describe: ["对所有敌人造成 10 点伤害"],
        usage: {
            type: "allTargets",
            target: { faction: "enemy", number: "all" }
        },
        disableAfterUse: true,
        effects: [{ key: "damage", params: { value: 10 } }]
    }]
}
```

数据模板：带冷却

```typescript
{
    label: "袖珍手枪",
    key: "original_relic_pistol",
    rarity: "uncommon",
    pool: ["common"],
    activeAbilities: [{
        key: "shoot",
        label: "射击",
        describe: ["对指定敌人造成 10 点伤害"],
        usage: {
            type: "selectTarget",
            target: { faction: "enemy" }
        },
        restrictions: {
            cooldown: 3,
            conditions: { scene: "combat" }
        },
        effects: [{ key: "damage", params: { value: 10 } }]
    }],
    interaction: {}
}
```

要点

    `usage.type` — direct / selectTarget / allTargets / toggle
    `disableAfterUse: true` — 使用后灰掉（单次遗物专用）
    `restrictions.cooldown` — 回合数
    `restrictions.conditions.scene: "combat"` — 只能在战斗中使用
    UI 会自动根据 badges / cooldown 状态显示可用性

相关文档
    参考/实现参考手册.md — abilityCharges / cooldown 效果 key

## 场景 10：不同稀有度池

目标
    控制遗物出现在哪些奖励场景。

涉及机制
    `rarity` — 稀有度（common / uncommon / rare）
    `pool` — 出现的池数组

数据模板

```typescript
// 出现在普通奖励池
pool: ["common"]

// 只出现在商店
pool: ["shop"]

// Boss 战掉落
pool: ["boss"]

// 兜底池（其他池抽完才出）
pool: ["fallback"]

// 多个池都能出
pool: ["common", "shop"]
```

要点

    rarity 决定颜色和稀有权重
    pool 决定出现场景
    没写 pool 的遗物不会被自动分配（只能通过效果直接获得，比如活动奖励）

## 常见错误与修正

错误 1：为了「失去时清理」写 lose 段
    错：给一个普通「+3 力量」遗物写 lose 段去减掉力量
    对：能通过 StatusModifier / ContentModifier 提供的属性，失去自动回滚，不写 lose

错误 2：什么都不写 lose 段
    错：解锁行动型遗物（enablePoolAction）不写 lose disablePoolAction
    对：只有 Set-based 的开关状态需要显式 lose，这是例外

错误 3：battleStart 忘了 disableUntil 导致每回合都触发
    症状：某些遗物设计成战斗开始一次，结果每次战斗都触发多次
    修复：`disableUntil: "battleEnd"`

错误 4：when 用 "before" 应该用 "after"
    错：battleStart when: "before" — 战斗还没真正开始，一些状态可能没准备好
    对：想在战斗真正开始后触发用 "after"，想在触发前拦截才用 "before"

错误 5：pool 写错分类
    症状：期望的遗物在商店没出现
    修复：确认 `pool: ["shop"]` 拼写正确、且不是 `pool: "shop"`（必须是数组）

错误 6：$triggerEffect.params(value) 拿不到值
    症状：累计伤害的遗物永远不涨
    原因：不同事件的 params 名可能不同，damage 事件通常是 `value`，applyState 是 `stacks`
    修复：查看事件源头的 effectMap 定义，或用具体常量值 `gain: 1`

错误 7：没写 badges 玩家看不到进度
    症状：accumulateAndTrigger 型遗物玩家不知道什么时候触发
    修复：加 `badges: [{ type: "counter", status: "point", maxStatus: "maxPoint" }]`
