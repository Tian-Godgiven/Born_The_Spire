# 事件实现场景手册

面向 AI 与 Mod 开发者的场景式教程。想在数据里定义一个事件（房间类型 `event`），先在本手册里找相似场景，复制模板，改数值、描述、选项即可用。

本手册与其他文档的分工

    src/core/objects/room/EventRoom.ts — 生命周期、执行顺序的权威代码
    src/core/types/EventMapData.ts — EventMap / EventSceneMap / EventOptionMap 的类型定义
    src/static/list/room/event/eventList.ts — 所有已注册事件
    src/static/list/room/event/eventEffectMap.ts — 所有已注册的 event effect
    本手册 — 我要实现「某一类事件」，数据长什么样

事件配置全部放在 `eventList.ts` 的 `eventList` 数组里；单幕用 `options`，多幕用 `scenes`。事件在楼层里怎么分配、什么时候出现，是楼层配置和地图生成的事，跟本手册无关。

---

## 使用方法

每个场景包含

    目标 — 一句话说清楚要做的事件类型
    涉及机制 — 用到 EventMap 里哪些字段、走哪些通道
    数据模板 — 完整可复制的配置片段
    常见变体 — 参数或结构小改
    要点 — 容易混淆或踩的坑

事件的执行链只有一条

```
玩家选一个 option
    → saveData(sceneData)
    → 执行 effects[]（走 eventEffectMap）
    → 弹 rewards[]（走 rewardRegistry）
    → customCallback(sceneData)
    → 多幕：跳 nextScene，或打开地图（不立刻结束房间）
    → 单幕：打开地图（成交则锁住选项）
    → 点进下一个房间时才 complete
```

只要能把想要的行为放进这一条链里，事件就成立。

## 选项文案

title 写玩家做的事（含代价），description 写结果。玩家看到的是「标题 + 下面一行描述」，不要把结果塞进 title 的括号里。

    title: "给他20金币"
    description: "获得一瓶随机药水"

对照：事件正文写场景，不写数值结果。正文换行用 `/br/`。

大部分事件选完要进结果幕，把「发生了什么」写在第二幕正文里。花钱、拿东西这类结算写在第一幕 option 的 effects 上，结果幕只留一个离开。不交易的「无视他」写 `openMap: true`：只开地图，关掉地图还能改选。成交后选项锁死，只能走。点进下一个房间才真正离开。

## 关于"离开"选项

不是硬规则，只是"少这么做更好玩"的经验。原作里很多经典事件（腐化心脏、Cursed Tome、面具幽会）不给免费出口，抉择才有痛感；反过来每个事件都塞一个"离开 / 什么也不发生"，玩家会习惯性默选它，事件就退化成"跳过按钮"。

倾向留"离开"的情况

    所有其它选项都有明显负面代价（献祭生命、失去器官、诅咒）——留一个保底
    事件本身是纯负面（陷阱/惩罚），"离开"是唯一合理出口

倾向不留"离开"的情况

    已有一个明显中性/低成本的选项，那个就是实质的"离开"
    有一个纯收益选项，"离开"变成"自愿放弃"，稀释设计
    tradeoff 之间真的希望玩家做抉择时——留"离开"多半会让人默选它

系统层面：开地图不等于结束房间。`openMapToLeave` 解锁下一层并打开地图，关掉还能继续操作。`finishRoomAndOpenMap` 先锁交互再开地图。点进下一个房间才 `completeCurrentRoom`。战斗胜利仍可马上 complete（要收掉战斗状态）。

## 场景 1：选择 + 结果幕（纯 effect）

目标

    「选完之后进第二幕，把选择的结果写成一段话」——现在大部分事件都这样。

涉及机制

    EventMap 用 `scenes`；第一幕选，带 `nextScene` 的进结果幕
    结算写在第一幕 option 的 effects[] 里，每个 effect key 必须存在于 eventEffectMap
    结果幕不写 nextScene，点离开只开地图
    正文换行用 `/br/`

数据模板（神秘商人，现行数据）

```typescript
{
    key: "event_mysterious_merchant",
    title: "神秘商人",
    description: "你遇到了一个衣衫褴褛的流浪汉，他却说他曾经是个商人，如果你能给他一些金币……",
    icon: "🧙",
    scenes: [
        {
            key: "offer",
            title: "神秘商人",
            description: "你遇到了一个衣衫褴褛的流浪汉，他却说他曾经是个商人，如果你能给他一些金币……",
            options: [
                {
                    title: "给他20金币",
                    description: "获得一瓶随机药水",
                    icon: "🧪",
                    ifAble: "$owner.reserve(gold) >= 20",
                    nextScene: "result_potion",
                    effects: [
                        { key: "loseGold", params: { amount: 20 } },
                        { key: "gainRandomPotion", params: { count: 1 } }
                    ]
                },
                {
                    title: "给他60金币",
                    description: "获得一个随机遗物",
                    icon: "💎",
                    ifAble: "$owner.reserve(gold) >= 60",
                    nextScene: "result_relic",
                    effects: [
                        { key: "loseGold", params: { amount: 60 } },
                        { key: "gainRandomRelic", params: { count: 1 } }
                    ]
                },
                {
                        title: "无视他",
                        description: "离开",
                        icon: "🚪",
                        openMap: true,
                        effects: [{ key: "nothing" }]
                }
            ]
        },
        {
            key: "result_potion",
            title: "神秘商人",
            description: "你吐出了一些金币，他欣喜若狂地捧了起来，随后鬼鬼祟祟地从一个脏污的布料里拿出一瓶药水交给你/br/\"又一笔买卖......嚯嚯嚯！有得赚！\"",
            options: [{ title: "离开", description: "离开", icon: "🚪" }]
        },
        {
            key: "result_relic",
            title: "神秘商人",
            description: "你吐出了许多金币，他欣喜若狂地捧了起来，随后鬼鬼祟祟地从一个脏污的布料里拿出一个遗物交给你/br/\"又一笔买卖......嚯嚯嚯！有得赚！\"",
            options: [{ title: "离开", description: "离开", icon: "🚪" }]
        }
    ]
}
```

常见变体

    换 effect key 组合出不同选项行为
    两个选项共用一段结果文，只改几个词：拆成两幕（本例），或结果幕 description 写成 `(data) => string`（场景 7）
    「无视 / 离开」写 `openMap: true`（或不写 nextScene、没有实质效果），只开地图，不锁选项
    成交后进结果幕，选项锁死，离开只能走地图

要点

    key 用 `event_` 前缀
    结果幕的 title 继续用事件名，不要写「第二幕」
    effects 在跳幕前执行完，玩家读结果文时东西已经到手
    开地图不 complete 房间。点进下一个房间才离开。结果幕的离开也只是再开地图。

## 场景 2：带资源门槛的选项（ifAble）

目标

    「给他 20 金换药水，金钱不够时选项置灰但仍然显示」——用 Condition 系统限制可用性。

涉及机制

    ifAble 是 Condition 字符串（走 checkCondition）
    context 里 owner = nowPlayer / item = nowPlayer（只有这两个可用）
    常用 $ 引用
        `$owner.reserve(gold) >= 20`
        `$owner.reserve(material) >= 100`
        `$owner.status(max-health) >= 20`
        `$owner.current(health) > 50%`

数据模板（神秘商人的药水选项）

```typescript
{
    title: "给他20金币",
    description: "获得一瓶随机药水",
    icon: "🧪",
    ifAble: "$owner.reserve(gold) >= 20",
    effects: [
        { key: "loseGold", params: { amount: 20 } },
        { key: "gainRandomPotion", params: { count: 1 } }
    ]
}
```

常见变体

```typescript
// AND：金钱够 且 最大生命够
ifAble: { and: [
    "$owner.reserve(gold) >= 100",
    "$owner.status(max-health) >= 30"
]}

// OR：金钱够 或 灵魂够
ifAble: { or: [
    "$owner.reserve(gold) >= 100",
    "$owner.reserve(soul) >= 5"
]}

// NOT
ifAble: { not: "$owner.status(max-health) < 15" }
```

要点

    ifAble 不满足 → **置灰**（仍然显示）；ifShow 不满足 → **完全不显示**（场景 7）
    Condition 语法权威定义在 `src/core/types/ConditionSystem.ts`
    百分比比较：`$owner.current(health) > 50%` 会自动查 current 的 maxBy 换算
    事件 context 只有 $owner / $item，$event / $triggerCard 之类在事件里都拿不到

## 场景 3：奖励选择弹窗（rewards[]）

目标

    「打开某样东西，弹出选择框：3 个遗物里挑 1 个 + 一份物质」——不给固定物，而是弹选择界面让玩家挑。现行「两个宝箱」不走这条，随机遗物用 `gainRandomRelic`。

涉及机制

    option.rewards[] 走 rewardRegistry.createRewards
    reward 常用 type
        `material` — 直接给一份物质（不弹窗）
        `potion` — 直接给指定药水
        `relicSelect` — 弹遗物选择框
    `draw` 抽池：`draw: { count: 3 }` → 房间层用 drawItems 从池里抽 3 个候选放进 `relicOptions`

数据模板

```typescript
// 简单：直接给固定物质
{
    title: "翻开袋子",
    description: "获得物质",
    icon: "🔓",
    rewards: [
        { type: "material", amount: 100 }
    ]
}
```

```typescript
// 复杂：花代价 + 弹遗物选择框（3 选 1）
{
    title: "强行撬开",
    description: "获得更多物质，3 个遗物里选 1 个",
    icon: "⚠️",
    effects: [
        { key: "loseHealth", params: { amount: 10 } }
    ],
    rewards: [
        { type: "material", amount: 150 },
        { type: "relicSelect", draw: { count: 3 }, selectCount: 1 }
    ]
}
```

常见变体

    多个 rewards 会顺序弹多个选择框
    要指定池子而不是全体：`draw` 里加 filter，具体能力见 `src/core/hooks/draw.ts`

要点

    rewards 是"选择弹窗"（玩家主动挑）；effects 是"被动执行"（无 UI）
    给固定物用 effect（`gainRelic { relicKey }` 之类），不用 rewards
    rewards 在 effects 之后弹（见附录 C 执行顺序）
    draw 抽池的 type 命名规则见附录 D 坑 6

## 场景 4：互斥选项组

目标

    「治疗泉水：饮用 vs 净化 只能选一个」——多个选项互相禁用，选中一个自动置灰同组其它。

涉及机制

    EventMap 顶层加 `mutuallyExclusiveGroups: string[][]`
    每个数组内的 option key 互斥
    option 必须显式写 `key` 才能进互斥组
    多幕事件把互斥组写在 EventSceneMap 上（scene 级）

数据模板（互斥组本身；清澈泉水已改成结果幕，选完就锁，不再用互斥组）

```typescript
{
    key: "event_example_mutex",
    title: "二选一",
    description: "两口井，你只能饮其中一口。",
    mutuallyExclusiveGroups: [
        ["drink_spring", "purify_cards"]
    ],
    options: [
        {
            key: "drink_spring",
            title: "饮用泉水",
            description: "回复生命",
            icon: "🍶",
            effects: [{ key: "healHealth", params: { percent: 50 } }]
        },
        {
            key: "purify_cards",
            title: "用泉水净化",
            description: "移除一张卡牌",
            icon: "✨",
            effects: [{ key: "removeCard", params: { count: 1, minCount: 1 } }]
        }
    ]
}
```

要点

    清澈泉水现在是结果幕锁选择：吸收 / 浸泡二选一，没有离开。牌组为空时浸泡置灰。
    没写 key 的选项写进 mutuallyExclusiveGroups 里也不生效——它永远不进组
    多幕互斥写在 scene 上：`EventSceneMap.mutuallyExclusiveGroups`
    互斥不改变"是否可选"，只是选中一个后同组的其它选项自动禁用

## 场景 5：打开选择界面的效果

目标

    「让玩家从自己的卡组里选一张移除」「从自己的器官里选一个丢弃」——不是给玩家新东西，而是让玩家挑现有的东西。

涉及机制

    走现成 event effect，内部自动 doEvent 一个 `choose*` 事件，UI 层自动弹选择界面

现成的

    `removeCard { count, minCount }` — 从卡组选卡移除
    `upgradeCard { count }` — 从卡组选卡升级
    `removeOrgan { count, minCount }` — 从已装器官选一个移除

数据模板

```typescript
{
    title: "净化牌组",
    description: "移除一张卡牌",
    icon: "✨",
    effects: [
        { key: "removeCard", params: { count: 1, minCount: 0 } }
    ]
}
```

常见变体

    `minCount: 0` 玩家可以取消（不选也不亏）
    `minCount: 1` 强制选一张（弹窗没取消按钮）
    `count > 1` 一次移除多张
    `upgradeRandomCards { count, tags: ["attack"] }` 不是选择界面，是**随机**升级 N 张符合 tag 的卡

要点

    这类 effect 是"打开选择界面"，不是自动执行；如果没有可选目标（比如空卡组）界面会关闭什么也不做
    不要在事件里自己写 `doEvent({ key: "chooseCardRemove", ... })`，用现成的 event effect wrapper（层级正确、行为一致）
    随机操作用 `upgradeRandomCards / gainRandomCard` 等（无 UI，直接结算）

## 场景 6：多幕事件基础（scenes + nextScene）

目标

    「分岔路：先看到路口，选左或右后进入不同的第二幕，最终线性收尾」——多幕故事推进。

涉及机制

    EventMap 用 `scenes: EventSceneMap[]` 替代 `options`
    每个 scene 有 `key / title / description / options`
    option 里用 `nextScene: "另一幕的 key"` 跳转
    option 没有 nextScene → 打开地图（成交则锁住；`openMap: true` 或纯离开不锁）
    点进下一个房间才 complete
    第一幕总是 scenes 数组的第 0 项

数据模板

```typescript
{
    key: "event_forked_path",
    title: "分岔路",
    description: "路口出现分岔",
    icon: "🌲",
    scenes: [
        {
            key: "scene1",
            title: "分岔",
            description: "左边是山路，右边是密林",
            options: [
                {
                    title: "走山路",
                    description: "崎岖但视野好",
                    icon: "⛰️",
                    nextScene: "mountain_top"
                },
                {
                    title: "走密林",
                    description: "深邃看不清",
                    icon: "🌳",
                    nextScene: "forest_lost"
                }
            ]
        },
        {
            key: "mountain_top",
            title: "山巅",
            description: "你登上山顶，发现一处遗迹",
            options: [
                {
                    title: "接受奖励",
                    description: "从遗迹里带走一件遗物",
                    icon: "✨",
                    effects: [{ key: "gainRandomRelic", params: { count: 1 } }]
                    // 没有 nextScene → 事件结束
                }
            ]
        },
        {
            key: "forest_lost",
            title: "迷雾",
            description: "你在密林中失去方向",
            options: [
                {
                    title: "自认倒霉",
                    description: "折返时踢到石头",
                    icon: "💔",
                    effects: [{ key: "loseHealth", params: { amount: 10 } }]
                }
            ]
        }
    ]
}
```

要点

    scenes 与 options 二选一，`scenes` 存在时忽略 `options`
    跳幕有 500ms 延迟（EventRoom.ts:541 里 setTimeout），给 UI 动画留时间
    每幕独立的 title/description 会覆盖顶层
    title 写给玩家看的场景名（「平静的湖面」），不要写「第一幕 / 第二幕」——那是开发结构，会直接出现在事件标题上
    单幕 vs 多幕的收尾差异见附录 D 坑 3

## 场景 7：多幕数据传递（saveData + ifShow）

目标

    「湖面精灵：玩家在第一幕丢的是卡还是器官，会影响第二幕能看到什么选项、走向哪个第三幕」——幕之间要记住玩家的选择。

涉及机制

    `saveData(sceneData)` — option 选中时写入 EventRoom 上的共享对象
    `ifShow(sceneData): boolean` — 后续 option 判断要不要显示（纯函数，不是 Condition 字符串）
    sceneData 在整个事件生命周期共享；跨事件不保留

数据模板

```typescript
scenes: [
    {
        key: "scene1",
        title: "湖面",
        description: "湖中央的漩涡邀请你投入一件东西",
        options: [
            {
                title: "丢入一张卡牌",
                description: "……",
                icon: "🃏",
                nextScene: "scene2",
                saveData: async (data) => {
                    data.itemType = 'card'
                }
            },
            {
                title: "丢入一个器官",
                description: "……",
                icon: "🫀",
                nextScene: "scene2",
                saveData: async (data) => {
                    data.itemType = 'organ'
                }
            }
            // 没有第三个"离开"选项——两个投入都不算大代价，玩家必须做出选择
        ]
    },
    {
        key: "scene2",
        title: "幻影",
        description: "湖面浮起透明幻影，问你丢的是什么",
        options: [
            {
                key: "honest_card",
                title: "承认是卡牌",
                description: "……",
                ifShow: (data) => data.itemType === 'card',
                nextScene: "scene3_honest"
            },
            {
                key: "lie_card",
                title: "谎称是器官",
                description: "……",
                ifShow: (data) => data.itemType === 'card',
                nextScene: "scene3_lie"
            },
            {
                key: "honest_organ",
                title: "承认是器官",
                description: "……",
                ifShow: (data) => data.itemType === 'organ',
                nextScene: "scene3_honest"
            },
            {
                key: "lie_organ",
                title: "谎称是卡牌",
                description: "……",
                ifShow: (data) => data.itemType === 'organ',
                nextScene: "scene3_lie"
            }
        ]
    }
    // scene3_honest / scene3_lie 略
]
```

常见变体

    要弹出选卡/选器官：写在 customCallback 里 await 选择界面。选不到东西时 `return "当前幕 key"`，才能拦住 nextScene（saveData 不能取消跳转）
    实证：`event_lake_spirit` 丢入卡牌/器官
    ifShow 复杂条件写在函数里，不受 Condition 系统的表达能力限制
    ifAble 也能在多幕里用，与单幕语义一致

要点

    ifShow 目前是**纯函数**，未来会重构成 Condition 系统（见 `文档/任务列表.md`）；现在写函数即可
    saveData 是就地修改 data 对象（不需要返回）
    打开选择界面不要只写在 saveData 里——选不到仍会跳 nextScene。用 customCallback 返回当前幕 key 留下
    心脏带 `organ_cannot_remove` 词条（status `cannot-remove`）。丢入器官走 `getRemovableOrgans()`；没有可舍弃器官时用 `$owner.removableOrganCount() >= 1` 置灰
    诚实：取回原物 + 200 物质。撒谎：物品不还 + 10 点伤害
    没有 ifShow 的选项永远显示
    "看不见的选项也不会占位置"——过滤在 createChoicesFromOptions 里做（EventRoom.ts:152）

## 场景 8：嵌入战斗（type: "battle"）

目标

    「事件中途遇到怪，打赢继续故事，打输游戏结束（或走失败分支）」——把战斗嵌入事件流。

涉及机制

    scene.type = "battle" + scene.battle 配置
    `battle.enemies: string[]` — 敌人 key 数组
    `battle.rewards` — 战斗奖励（gold / cardPool+cardChoices+cardPick / relics / potions）
    `battle.onWin: "scene_key"` — 胜利跳到哪一幕
    `battle.onLose: "scene_key" | "gameOver"` — 失败跳的地方
    `battle.afterEffects: EventEffectUnit[]` — 胜利后 event effect 数组

数据模板

```typescript
{
    key: "event_arena",
    title: "竞技场",
    description: "一场野蛮的角斗",
    icon: "⚔️",
    scenes: [
        {
            key: "prelude",
            title: "序幕",
            description: "角斗士挥手邀战",
            options: [
                {
                    title: "接受挑战",
                    description: "走上竞技场",
                    icon: "⚔️",
                    nextScene: "fight"
                },
                {
                    title: "拒绝",
                    description: "转身离开",
                    icon: "🚪"
                    // 没 nextScene → 直接结束事件
                }
            ]
        },
        {
            key: "fight",
            title: "决斗",
            description: "开打",
            type: "battle",
            battle: {
                enemies: ["enemy_gladiator"],
                rewards: {
                    gold: 100,
                    relics: [{ rarity: "uncommon" }]
                },
                onWin: "victory",
                onLose: "gameOver",
                afterEffects: [
                    { key: "healHealth", params: { percent: 20 } }
                ]
            },

        },
```

    afterEffects 在胜利结算 & 奖励弹窗之后、跳 onWin 之前执行
    如果第一幕就是 battle，enter() 会自动启动战斗（不需要玩家点确定）
    `cardPool` 是卡 key 数组，从池里抽 cardChoices 个候选让玩家 pick cardPick 张

## 场景 9：customCallback 兜底

目标

    「effects + rewards 都表达不了这个操作」——比如需要根据 sceneData 里保存的具体对象 id 去操作那个对象、或者要跨系统查询。

涉及机制

    option.customCallback(sceneData) — 兜底口子，异步函数
    执行时机：saveData → effects → rewards → **customCallback** → nextScene

数据模板

```typescript
{
    title: "接受奖励",
    description: "精灵把你之前丢入的卡牌还给你，并升级它",
    icon: "✨",
    effects: [
        { key: "gainMaterial", params: { amount: 200 } }
    ],
    customCallback: async (data) => {
        // 例：把 sceneData 里之前记录的那张卡升级
        const cardId = data.selectedCardId
        if (!cardId) return
        const card = nowPlayer.getCardGroup().find(c => c.__id === cardId)
        if (!card) return
        await doEvent({
            key: "upgradeCard",
            source: nowPlayer,
            medium: card,
            target: nowPlayer,
            effectUnits: [{ key: "upgradeCard", params: { card } }]
        })
    }
}
```

常见变体

    在 saveData 里也可以做类似操作（打开 UI 让玩家选具体 item），用于**先记录选择**、后面幕再消费

要点

    customCallback 里改状态**必须走 doEvent**，别直接改 entity 字段（见常见错误排查手册"事件系统绕过"）
    执行位置在 effects/rewards 之后，nextScene 之前
    大部分场景优先用 effect + reward；callback 是兜底
    异步：async 函数，await 完成后才继续下一步

## 场景 10：新增 event effect

目标

    「我要写的事件需要一个 eventEffectMap 里没有的 effect」——比如"永久 +1 能量上限"、"永久 +1 每回合抽牌"。

涉及机制

    event effect 是一个 wrapper：内部走 `doEvent` + 已有的普通 effect（effectMap）
    改任意 status 走 `addStatusBase` 通用效果（指定 statusKey / value / type: "additive" | "multiplicative"）
    改最大生命有专用 `addMaxHealthAndHeal`（不走 addStatusBase）
    event effect 与普通 effect 是两个体系：event effect 只在 event option 的 `effects[]` 里用；普通 effect 在 EffectUnit 里用（触发器 / 卡牌 / 器官）

数据模板（追加到 `eventEffectMap.ts` 的 `eventEffectMap` 对象里）

```typescript
/**
 * 获得最大能量（永久增加能量上限）
 */
"gainMaxEnergy": async (params: { amount: number }) => {
    await doEvent({
        key: "gainMaxEnergy",
        source: nowPlayer,
        medium: nowPlayer,
        target: nowPlayer,
        effectUnits: [{
            key: "addStatusBase",
            params: { statusKey: "max-energy", value: params.amount, type: "additive" }
        }]
    })
},

/**
 * 获得每回合抽牌数（永久增加每回合抽牌数）
 */
"gainDrawPerTurn": async (params: { amount: number }) => {
    await doEvent({
        key: "gainDrawPerTurn",
        source: nowPlayer,
        medium: nowPlayer,
        target: nowPlayer,
        effectUnits: [{
            key: "addStatusBase",
            params: { statusKey: "draw-per-turn", value: params.amount, type: "additive" }
        }]
    })
},
```

事件数据里直接用

```typescript
effects: [
    { key: "loseMaxHealthPercent", params: { percent: 30 } },
    { key: "gainMaxEnergy", params: { amount: 1 } }
]
```

常见变体

    改任意 status → 一律 `addStatusBase`，换 statusKey
    需要触发流水线介入（触发器能拦截 / 修改的）→ 走对应的高层 effect（如 `heal` / `damage`），不用 `addStatusBase`（后者是直接改数据）
    只服务某一个事件的效果 → 直接放 `eventEffectMap.ts`；如果是普适的原子操作，考虑加进 `effectMap.ts`（普通 effect）而不是 event effect

要点

    命名遵循 `gainXxx / loseXxx / xxx` 的动词风格，与现有一致
    差一个参数就能满足时**扩展现有** event effect，不新写（见 memory [[extend-over-new-effect]]）
    key 冲突后覆盖前（Object 键的行为），新增时确认命名不撞
    event effect 一律 async 函数，即使内部同步；框架用 `await effectFunc(params)` 消费

## 场景 11：幕级整页组件 + 自指循环（无常之神）

目标

    「无常之神：先接近再上桌、左右分栏、两枚十面骰对赌、六把之后结束」——需要自己排版的事件，不要新开房间类型。

涉及机制

    第一幕仍是普通文本（接近 / 离开）
    赌桌幕写 `component: markRaw(GodOfChanceTable)`，EventRoom 不再画标题/正文/选项，由组件自己排左右栏
    组件从 `room.choiceGroup` 读选项，点选走 `choiceGroup.selectChoice`（和普通事件同一条执行链）
    幕 `onEnter` 里 `godOfChance_prepare`：抽出本把奖励/惩罚，庄家先骰时预先掷好点数
    「停下」`nextScene` 指回 `table`；最后一把用 ifShow 拆到 `finale`
    `ifAble` 可传 `(sceneData) => boolean`，每次渲染求值（庄家未亮点时「停下」置灰）
    sceneData 在 EventRoom 里是 `reactive({})`，组件才能盯着点数/奖惩变

数据模板（简化自 `event_god_of_chance`）

```typescript
{
    key: "event_god_of_chance",
    title: "无常之神",
    description: "空无一物的废墟中央，两枚骰子在不休止地旋转……",
    scenes: [
        {
            key: "approach",
            title: "无常之神",
            description: "空无一物的废墟中央，两枚骰子在不休止地旋转……",
            options: [
                { key: "approach", title: "接近", nextScene: "table", saveData: (data) => { data.round = 1 } },
                { key: "walk_away", title: "转身离开" }
            ]
        },
        {
            key: "table",
            title: "无常之神",
            description: (data) => godOfChanceTableText(data),
            component: markRaw(GodOfChanceTable),
            onEnter: async (data) => {
                if (data.resolved) {
                    data.round += 1
                    data.resolved = false
                }
                await eventEffectMap.godOfChance_prepare({ data })
                data.dealId = (data.dealId ?? 0) + 1
            },
            options: [
                {
                    key: "roll_continue",
                    title: "停下骰子",
                    ifShow: (data) => (data.round ?? 1) < 6,
                    ifAble: (data) => !data.busy && !data.resolved && (data.round > 3 || data.houseRevealed),
                    customCallback: (data) => eventEffectMap.godOfChance_apply({ data }),
                    nextScene: "table"
                },
                {
                    key: "roll_final",
                    title: "停下骰子",
                    ifShow: (data) => (data.round ?? 1) === 6,
                    ifAble: (data) => !data.busy && !data.resolved,
                    customCallback: (data) => eventEffectMap.godOfChance_apply({ data }),
                    nextScene: "finale"
                },
                { key: "leave_early", title: "转身离开", ifShow: (data) => (data.round ?? 1) < 4 },
                {
                    key: "leave_curse",
                    title: "转身离开",
                    description: "你会带上一张诅咒。",
                    ifShow: (data) => (data.round ?? 1) >= 4,
                    effects: [{ key: "gainRandomCard", params: { tags: ["curse"] } }],
                    nextScene: "leave_curse"
                }
            ]
        }
    ]
}
```

组件样板在 `src/ui/components/interaction/GodOfChanceTable.vue`：左侧上下两枚骰，右侧 title / 旁白 / 奖励 / 惩罚 / 选项。骰子只换数字，不走动画系统。

调用方法（别的事件要挂同类整页组件，照这个接）

    组件文件放在 `src/ui/components/interaction/`，不要新开房间类型
    事件数据里 `import` 后 `markRaw` 再写到**那一幕**的 `component`，不要写到 EventMap 顶层（顶层 `component` 只插在正文和选项之间）

```typescript
import { markRaw } from "vue"
import GodOfChanceTable from "@/ui/components/interaction/GodOfChanceTable.vue"

const GOD_OF_CHANCE_TABLE = markRaw(GodOfChanceTable)

// 幕上：
{
    key: "table",
    title: "无常之神",
    description: (data) => godOfChanceTableText(data),
    component: GOD_OF_CHANCE_TABLE,
    onEnter: godOfChanceEnterTable,
    options: [ /* 停下 / 离开，组件会画这些 */ ]
}
```

    EventRoom.vue 看到当前幕有 `component`，整页只渲染这一块（`:key` 是幕 key）。标题、旁白、选项都要组件自己画
    组件不接收 props。从 `nowGameRun.currentRoom` 取 `EventRoom`：
        `currentTitle` — 幕标题
        `getSceneData()` — 本把点数、奖惩、houseRevealed、dealId
        `choiceGroup.choices` — 选项列表
        点选：`await room.choiceGroup.selectChoice(choice)`，后面仍走 saveData → effects → customCallback → nextScene
    文案函数放 `godOfChance.ts`（`godOfChanceTableText` / `godOfChancePromptLine`），组件只负责排版和掷骰演出
    点数：组件里先 `godOfChance_rollPlayer` / `godOfChance_rollHouse` 写入 sceneData，再 `selectChoice`；`godOfChance_apply` 只比较已有点数并跑奖惩
    同一幕循环：`nextScene: "table"` 会再跑 `onEnter`。用 `dealId++` 让组件 `watch` 后重开这一把。不要靠把组件 unmount 掉

常见变体

    **只要循环不要整页组件**：把幕上的 `component` 拿掉，EventRoom 会走默认标题+正文+选项。自指 `nextScene` 和 ifShow 拆终章仍然可用
    **无限循环（无自动结束）**：删掉 `roll_final`，`roll_continue` 的 ifShow 也删掉
    **多分支终章**：用多个 ifShow 同名 option 分派到不同终章幕
    **中途插入选择**：option 上的 `component` 仍是打开选卡之类的小 UI，和幕级整页组件不是一回事

要点

    **幕级 component 替换整页**：不要指望 EventRoom 再画一份标题和选项。事件顶层 `component` 仍是插在正文和选项之间的小块
    **Vue 组件要 markRaw**：不要把 SFC 丢进可能被 reactive 包到的对象里
    **onEnter 在切幕之前跑**：`goToScene` 先 await `scene.onEnter(sceneData)`，再改 currentSceneKey。本把奖惩在组件挂上之前就准备好
    **nextScene 指回自己**：同一幕 key 不会 lock 选项；500ms 后再次 onEnter，用 `dealId` 让组件重开这一把的旋转
    **ifAble 函数每次渲染求值**：和字符串 Condition（创建时检查一次）不同。庄家亮点、busy、resolved 都靠它置灰
    **点数比较在组件里掷、在 apply 里结算**：组件先 `godOfChance_rollPlayer` / `rollHouse` 写入 sceneData，再 `selectChoice`；`godOfChance_apply` 只读已有点数，必须严格大于对面才算赢
    **description 函数式**：`godOfChanceTableText` 拼上一把结果 + 当前把开始。tell 是完整句子（你获得了 / 你失去了）
    **终章幕务必有 title**

## 附录 A：eventEffectMap 现有 effect 速查

按功能分类（截至 2026-07-13）

资源

    gainMaterial { amount }
    loseMaterial { amount }
    gainGold { amount } 或 { min, max } 闭区间随机
    loseGold { amount }

生命

    healHealth { amount? | percent? | divisor? }
    loseHealth { amount }
    loseHealthPercent { percent, notLethal? }   // notLethal 至少留 1 点当前生命
    loseMaxHealthPercent { percent }   // 永久扣最大生命
    gainMaxHealth { amount }

物品（指定 key 给固定物）

    gainRelic { relicKey }
    gainPotion { potionKey }
    gainCard { cardKey }
    gainOrgan { organKey }

物品（随机 / 选择）

    gainRandomRelic { count? }
    gainRandomPotion { count? }
    gainRandomCard { count?, rarity? }
    gainRelicFromPool { pool: {keys, weight}[] }
    upgradeRandomCards { count?, tags? }  // 无 UI，直接选中并升级
    removeCard { count?, minCount? }      // 弹选择界面
    upgradeCard { count? }                // 弹选择界面
    removeOrgan { count?, minCount? }     // 弹选择界面

其它

    openChest — 保留位置，目前空实现
    nothing — 什么也不发生（离开选项用）
    godOfChance_prepare { data } — 抽出本把奖惩，庄家先骰时预掷点数
    godOfChance_rollHouse { round } — 按回合加权掷 1–10
    godOfChance_rollPlayer { round } — 公平掷 1–10
    godOfChance_apply { data } — 比较已有点数并结算奖惩

## 附录 B：字段速查

EventMap

    key / title / description / icon
    options — 单幕
    scenes — 多幕（存在时忽略 options）
    mutuallyExclusiveGroups — 单幕互斥组
    component — 顶层插页组件（夹在正文和选项之间，不替换整页）
    availableCondition — 出现条件（RoomAvailableCondition，房间层用）

EventSceneMap

    key / title
    description — 字符串 或 (sceneData) => string（支持函数式，用于渐进/累进文本，见场景 11）
    type: "text" | "battle"（默认 text）
    battle: BattleSceneConfig（type=battle 时用）
    component — 幕级整页组件（有则替换 EventRoom 默认排版，见场景 11）
    onEnter — 进入此幕时调用（含 nextScene 指回自己；在改 currentSceneKey 之前 await）
    options: EventOptionMap[]
    mutuallyExclusiveGroups — 幕级互斥组

EventOptionMap

    key（互斥时必填）
    title / description / icon（description 可省略）
    effects[] — 走 eventEffectMap
    rewards[] — 走 rewardRegistry（含 draw 抽池）
    ifAble — Condition（创建时检查一次）或 (sceneData) => boolean（每次渲染求值）
    ifShow — (sceneData) => bool，隐藏
    nextScene — 多幕跳转
    saveData — 多幕数据保存
    customCallback — 自定义回调
    component — 选项上的复杂 UI（选卡等，不是幕级整页）

BattleSceneConfig

    enemies: string[]
    rewards: { gold?, cardPool?, cardChoices?, cardPick?, relics?, potions? }
    afterEffects: Array<{ key, params }>
    onWin: 下一幕 key
    onLose: 下一幕 key 或 "gameOver"

## 附录 C：onOptionSelected 执行顺序

```
option 被选中
    ↓
1. saveData(sceneData)              保存幕间数据
    ↓
2. executeEventEffects(effects)     顺序执行 event effect
    ↓
3. 弹 rewards[]（rewardRegistry）   玩家挑奖励
    ↓
4. customCallback(sceneData)        自定义回调
    ↓
5. component 由 UI 层承接           复杂交互
    ↓
6a. 多幕：nextScene 存在 → setTimeout 500ms → goToScene（先 await 目标幕 onEnter，再改 currentSceneKey；去别的幕会锁选项）
6b. 没有 nextScene → 打开地图（`openMap` / 纯离开不锁；成交则锁）
6c. 点进下一个房间 → completeCurrentRoom
```

## 附录 D：常见坑

坑 1：ifAble 里 $owner 是 nowPlayer，不是 event.source

    EventRoom.ts 里 context = { owner: nowPlayer, item: nowPlayer }
    只有 $owner / $item 可用；$event / $triggerCard / $source 之类在事件 context 里不会解析
    `$owner.organCount()` / `hasOrgan` / `organsWithCardsCount` 走 `getOrganList()`，不要自己读 `entity.organs`（那是 computed，当数组用永远是 0，选项会一直置灰）
    能不能丢器官用 `$owner.removableOrganCount()`，读 `cannot-remove` status，不要按心脏 key 或 starter 标签特判

坑 2：直接改 status 不走 doEvent

    错：`nowPlayer.status["max-energy"].base += 1`
    对：写一个 event effect wrapper，内部 `doEvent` + `addStatusBase`（场景 10）
    错误示例见常见错误排查手册"事件系统绕过"

坑 3：开地图不是结束房间

    `openMapToLeave`：解锁下一层、打开地图，关掉还能操作
    `finishRoomAndOpenMap`：先锁交互再开地图（成交、开完宝箱）
    点进下一个房间才 `completeCurrentRoom`
    水池、黑市的离开走 `openMapToLeave`，和事件里的「无视他」同一套

坑 4：互斥组的 key 必填

    没写 key 的选项写进 mutuallyExclusiveGroups 也不生效
    这些选项永远不会进任何组

坑 5：ifShow 是纯函数，不是 Condition 字符串

    对：`ifShow: (data) => data.itemType === 'card'`
    错：`ifShow: "$owner.status(x) > 0"`（Boolean("字符串") 恒为 true，写了不报错但恒显示）
    未来会重构成 Condition 系统，届时字符串才有效

坑 6：rewards 里 draw 的 type 命名规则

    reward type `"relicSelect"` + `draw` 时，抽出的候选放到 `"relicOptions"` 字段
    规则：drawn 结果字段名 = type 去掉 "Select" 后缀 + "Options"
    见 EventRoom.ts:517
    typo 或改错命名 → 弹窗里啥都没有

坑 7：effects 数组顺序执行、前后不共享数据

    前一个 effect 的产出不会自动传给后一个
    要传值：写 customCallback 里自己 doEvent；或者用 sceneData 中转（多幕）
    单幕想传值的话，把两个 effect 合并成一个新的 event effect

坑 8：event effect 找不到时静默失败

    executeEventEffect 找不到 effectKey → 只打 console.error，不抛异常
    数据里写了没注册的 key，游戏不崩但不会执行
    编辑器不会报错，只能靠测试发现

坑 9：少默认加"离开"选项

    不是硬规则，是"少这么做更好玩"的经验——不必每个事件都塞
    习惯性加"离开 / 什么也不发生"会让玩家把事件当跳过按钮，抉择感被稀释
    tradeoff 型事件尤其别加：一有免费退路，很少人还会接受 tradeoff
    倾向留"离开"的情形：所有其它选项都痛、事件本身是纯负面（陷阱/惩罚）
    详见开头"关于'离开'选项"
