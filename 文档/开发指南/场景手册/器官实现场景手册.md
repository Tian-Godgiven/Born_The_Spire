# 器官实现场景手册

面向 AI 与 Mod 开发者的场景式教程。想实现某种器官，先在本手册找相似场景，复制模板，改数值和描述。

本手册与《新内容开发清单》的分工：
    新内容开发清单 — 器官需要动的文件、OrganMap 最小字段
    本手册 — 我要做出「XX 效果的器官」，具体数据怎么写

两条不可动摇的原则（来自设计约束，AI 请严格遵守）：

器官对称原则
    器官对 Boss 和玩家的效果 / 卡牌必须一致
    禁止双模式设计（同一器官在玩家身上和敌人身上有不同行为）
    参考：memory feedback_organ_symmetry

器官独立原则
    击败 Boss 玩家只选一个器官
    联动可以有，但没有联动时也不能「完全无效」
    「变弱但仍生效」可接受，「毫无效果」必须换一个极强的独立收益
    参考：memory feedback_organ_standalone

---

## 使用方法

每个场景包含：
    目标 — 一句话说清楚要实现什么
    涉及机制 — 用到哪些系统，是否需要新效果函数
    数据模板 — 完整可复制的 OrganMap 定义
    常见变体 — 数值 / 条件小改
    相关文档 — 需要延伸阅读时的入口

描述里凡是出现状态名、词条名、规则名词，都要写成 `{$:"名称"}`，不能留成纯文字。同《卡牌实现场景手册》。

## 场景 1：纯属性器官（加血 / 加能量 / 加物质）

目标
    只提供数值增益，无触发器，如「+3 最大生命」「+1 最大能量」。

涉及机制
    interaction.possess 只写 effects，不写 triggers
    效果：`addMaxHealthAndHeal` / `addStatusBase` 之类

数据模板

```typescript
{
    label: "石芯",
    key: "original_organ_00002",
    describe: ["最大生命 +3"],
    rarity: OrganRarity.Uncommon,
    part: OrganPartEnum.Heart,
    status: { "max-mass": 40 },
    current: ["mass"],
    interaction: {
        possess: {
            target: { key: "self" },
            effects: [{
                key: "addMaxHealthAndHeal",
                params: { value: 3 }
            }]
        }
    }
}
```

常见变体

    加能量：换成 `addStatusBase`，params 指定 statusKey: "max-energy"
    加物质（自身 max-mass）：max-mass 是自己的属性，直接写在 status 里
    多重加成：effects 数组里堆多条

要点
    `possess` 的 effects 在获得器官时执行一次
    器官失去时 StatusModifier 自动撤销，不需要写 lose 段清理

## 场景 2：只提供卡牌

目标
    器官持有期间往牌组加一张或多张卡。

涉及机制
    `cards: string[]` — 直接引用 cardList 中的卡牌 key
    卡牌在器官失去时自动撤销

数据模板

```typescript
{
    label: "战斗之心",
    key: "test_organ_cards_001",
    describe: ["提供 1 张 ", { "@": 0 }, " 卡牌到牌组", "<br>", "最大生命 +2"],
    rarity: OrganRarity.Common,
    part: OrganPartEnum.Heart,
    status: { "max-mass": 30 },
    current: ["mass"],
    cards: ["original_card_00001"],
    interaction: {
        possess: {
            target: { key: "self" },
            effects: [{
                key: "addMaxHealthAndHeal",
                params: { value: 2 }
            }]
        }
    }
}
```

常见变体

    多张卡：`cards: ["card_a", "card_b", "card_c"]`
    描述引用卡名：describe 里用 `{ "@": 0 }` 引用 cards[0]，会显示卡牌名并支持悬浮预览
    卡和被动分行：数组里插入 `"<br>"`（现行：孢子囊、菌盖）
    只提供卡不加属性：interaction.possess.effects 留空数组 `[]`
    损坏时对对手施加状态：`interaction.break`，`target: { faction: "opponent", number: "all" }`（现行：孢子囊）
    附带防御牌 + 回合开始护甲：cards 挂硬化，被动读 `armor-gain`（现行：菌盖，2 级只锻牌）

要点
    卡牌本体仍要写在 cardList.ts，这里只是引用
    同一张卡可被多个器官引用，撤销时按当前持有的器官计算
    描述里的 `{ "@": 0 }` 索引 cards 数组中的第 N 张

相关文档
    场景手册/卡牌实现场景手册.md — 器官附带卡牌怎么写

## 场景 3：被动触发效果（受伤时 / 造成伤害时）

目标
    「受到的伤害 -1」「造成伤害时额外 +2」这种被动生效。

涉及机制
    triggers 声明监听事件
    reaction 声明触发时做什么
    效果：`reduceDamageValue` / `modifyDamageValue` / …

数据模板：受到伤害 -1

```typescript
{
    label: "石肤",
    key: "original_organ_00003",
    describe: ["受到的攻击伤害 -1"],
    rarity: OrganRarity.Uncommon,
    part: OrganPartEnum.Skin,
    status: { "max-mass": 25 },
    current: ["mass"],
    interaction: {
        possess: {
            target: { key: "self" },
            effects: [],
            triggers: [{
                when: "before",
                how: "take",
                key: "attack",
                action: "reduceDamage1"
            }]
        }
    },
    reaction: {
        reduceDamage1: [{
            key: "reduceDamage",
            label: "石肤防护",
            targetType: "triggerEffect",
            effect: [
                { key: "reduceDamageValue", params: { value: 1 } }
            ]
        }]
    }
}
```

常见变体

    造成攻击伤害时 +X：`how` 改 `"make"`，`key` 用 `"attack"`，effect 换 `modifyDamageValue` params: { delta: 2 }
    按目标虚弱层数加伤，再乘器官倍率：`delta: "$triggerEffect.target.stateStack(weak)"`，`multiplier: "$owner.status(weak-bonus)"`（现行：腐蚀腺；效果参数里 `$owner` 是器官自身）
    受击对伤害来源施加中毒：`how: "take"`，`targetType: "eventSource"`，层数读 `$owner.status(poison-reflect)`（现行：毒皮，2 级空过、3 级 2→3、4 级空过）
    受到某类型伤害时反弹：加 condition 过滤攻击类型
    伤害忽略护甲：换 `damageIgnoreArmor`
    只在特定条件生效：triggers 里加 `condition` 字段

要点
    `how: "make"` — 持有者是伤害源（自己攻击时触发）
    `how: "take"` — 持有者是受害方（自己受伤时触发）
    `targetType: "triggerEffect"` — 修改事件本身的效果参数

相关文档
    参考/反应系统详解.md — targetType 全部可选值、when/how/key 组合表

## 场景 4：有内部状态的器官（累计触发）

目标
    器官内部计数：累计受到若干点伤害 → 获得护甲，然后计数重置。适用于「充能式」「过热式」器官。损坏后停止。

涉及机制
    status 里定义自定义计数字段（如 `damage-taken`、`hurt-threshold`）
    current 数组把计数器列为需要序列化的当前值
    效果：`accumulateAndTrigger` 写在 **work.effects**（激活时挂监听，损坏时撤）
    阈值要随升级变：`thresholdKey` 指向器官 status，`consume: "threshold"`

数据模板（现行：不屈甲壳）

```typescript
{
    label: "不屈甲壳",
    key: "organ_resilient_shell",
    describe: [
        "每累计受到", { key: ["status", "hurt-threshold"] }, "点伤害，获得",
        { key: ["status", "armor-gain"] }, "点", {$:"护甲"}, "（",
        { key: ["status", "damage-taken"] }, "/", { key: ["status", "hurt-threshold"] }, "）"
    ],
    rarity: OrganRarity.Common,
    part: OrganPartEnum.Skin,
    badges: [
        { type: "counter", status: "damage-taken", maxStatus: "hurt-threshold" }
    ],
    status: {
        "max-mass": 20,
        "damage-taken": 0,
        "hurt-threshold": 10,
        "armor-gain": 1
    },
    current: ["mass", "damage-taken"],
    interaction: {
        work: {
            target: { key: "self" },
            effects: [{
                key: "accumulateAndTrigger",
                params: {
                    pointKey: "damage-taken",
                    on: { when: "after", how: "take", key: ["attack", "damage"] },
                    gain: "$triggerEffect.params(value)",
                    thresholdKey: "hurt-threshold",
                    consume: "threshold",
                    targetType: "owner",
                    effects: [{
                        key: "gainArmor",
                        params: { value: "$medium.status(armor-gain)" }
                    }]
                }
            }]
        }
    }
}
```

常见变体

    热量过载：pointKey 改 `heat`，threshold: 3，效果换成 damage 或 organ_heatTick
    造成伤害计数：`on.how` 改 `"make"`
    只吃固定量（不吸满就不算）：`gain` 改成常量 1
    描述里显示当前进度：describe 用 `{ key: ["status", "damage-taken"] }` 引用
    打牌计数抽牌：用 work 触发器 + `countAndTrigger`，阈值读 `$target.status(draw-every)`，损坏即停。现行：旋风引擎

要点
    `pointKey` 是 status 里那个自定义字段
    `gain` 支持表达式，`$triggerEffect.params(value)` 拿到本次伤害值
    写在 work.effects 里才会随损坏卸监听；不要写在 possess 除非损坏后还要继续累计
    阈值要升级：`thresholdKey` + `consume: "threshold"`，不要把数字写死在 threshold / consume 里

    参考/效果开发指南.md — accumulateAndTrigger 完整参数

## 场景 5：回合时触发（每回合施加状态 / 抽卡）

目标
    「回合开始时获得 1 层力量」「回合结束抽 1 张牌」。这是每回合再叠一层，不是「生效期间一直有」。一直有用场景 11。

涉及机制
    triggers 监听 turnStart / turnEnd
    reaction targetType 指定作用对象（owner / allAllies / allOpponents）

数据模板（现行：毒腺）

```typescript
{
    label: "毒腺",
    key: "enemy_organ_poison_gland",
    describe: ["回合开始时对所有对手施加", { key: ["status", "poison-gain"] }, "层", {$:"中毒"}],
    rarity: OrganRarity.Common,
    part: OrganPartEnum.Gland,
    status: { "max-mass": 15, "poison-gain": 1 },
    current: ["mass"],
    interaction: {
        work: {
            target: { key: "self" },
            effects: [],
            triggers: [{
                when: "after",
                how: "make",
                key: "turnStart",
                action: "poisonOnTurnStart"
            }]
        }
    },
    reaction: {
        poisonOnTurnStart: [{
            key: "poison",
            label: "毒腺：回合开始施毒",
            targetType: "allOpponents",
            effect: [{
                key: "applyState",
                params: { stateKey: "poison", stacks: "$owner.status(poison-gain)" }
            }]
        }]
    }
}
```

常见变体

    回合结束：`key: "turnEnd"`
    只影响自己：`targetType: "owner"` / `triggerOwner`
    层数读器官 status、洗涤时改数字：`stacks: "$owner.status(poison-gain)"`（现行：毒腺，2 级空过、3 级 1→2；蓄力腺同结构用 momentum-gain）
    护甲读器官 status：`value: "$owner.status(armor-gain)"`（现行：节甲，2 级 3→4、3 级 4→5）
    开局给状态：`key: "battleStart"`，写在 work 里，损坏的开战不给（现行：薄翅，2 级空过、3 级飞行 3→4）
    影响所有友军：`targetType: "allAllies"`
    随机一个敌人：换 targetType 或用效果参数 selector

要点
    turnStart / turnEnd 事件的持有者就是回合的主体，用 `how: "take"` 即可
    targetType 决定 reaction 对谁生效，不是 triggers 决定

## 场景 6：器官联动（引用其他器官 / tag）

目标
    「装备毒液类器官时额外触发」「与其他器官协同」。

涉及机制
    condition 表达式 — 判断持有者是否有另一个器官 / tag
    tags 字段 — 器官分类，方便被 condition 匹配

数据模板

```typescript
{
    label: "毒素增幅",
    key: "your_mod_organ_poison_amp",
    describe: ["装备毒液类器官时，施加的中毒 +1 层"],
    rarity: OrganRarity.Uncommon,
    part: OrganPartEnum.Gland,
    tags: ["poison"],
    status: { "max-mass": 20 },
    current: ["mass"],
    interaction: {
        possess: {
            target: { key: "self" },
            effects: [],
            triggers: [{
                when: "before",
                how: "make",
                key: "applyState",
                action: "poisonExtra",
                condition: "$owner.hasOrganTag(poison)"
            }]
        }
    },
    reaction: {
        poisonExtra: [{
            key: "poisonExtra",
            label: "毒素增幅",
            targetType: "triggerEffect",
            effect: [{ key: "organ_poisonAmplify", params: {} }]
        }]
    }
}
```

要点（器官独立原则）

    此器官如果没有其他毒器官就毫无效果 — 违反独立原则
    正确做法之一：condition 满足时 +1 层，不满足时至少还有 +2 max-health 的独立收益
    改法：把 possess.effects 里加一条 `addMaxHealthAndHeal` 保底

## 场景 7：Boss 器官（同一器官在玩家 vs Boss 身上完全一致）

目标
    Boss 的器官在玩家吞噬后完全按 Boss 时的效果生效，不做任何特化。

涉及机制
    与前面场景无区别 — 关键是 **不要写玩家 / Boss 分支**
    如果需要玩家版和 Boss 版效果不同 → 拆成两个器官，不是一个器官双模式

数据模板

```typescript
{
    label: "剧毒心核",
    key: "enemy_organ_toxic_core_boss",
    describe: ["施加", {$:"中毒"}, "时额外 +1 层"],
    rarity: OrganRarity.Rare,
    part: OrganPartEnum.Core,
    status: { "max-mass": 50 },
    current: ["mass"],
    interaction: {
        possess: {
            target: { key: "self" },
            effects: [],
            triggers: [{
                when: "before",
                how: "make",
                key: "applyState",
                action: "poisonAmplify"
            }]
        }
    },
    reaction: {
        poisonAmplify: [{
            key: "poisonAmplify",
            label: "剧毒心核：中毒 +1",
            targetType: "triggerEffect",
            effect: [{ key: "organ_poisonAmplify", params: {} }]
        }]
    }
}
```

要点（器官对称原则）

    Boss 装备时对玩家施毒 +1
    玩家吞噬后对敌人施毒 +1
    绝不能写「Boss 时对玩家 +2，玩家用时只 +1」这种双模式
    参考：memory feedback_organ_symmetry

max-mass 观察
    Boss 器官通常 max-mass 更高（30-50+），象征更耐损坏
    玩家吞噬后 max-mass 值保持一致，感觉「捡到大件」是设计意图

## 场景 8：cardsByOwner（谨慎使用）

目标
    同一个器官在玩家 vs 敌人身上给不同卡牌。

涉及机制
    `cardsByOwner: { player?: string[], enemy?: string[] }`

⚠️ 与器官对称原则冲突
    **默认不要用**，用 `cards` 让双方拿到相同卡
    只在极特殊情境（比如 UI 展示需要 / 敌人版本走硬编码 AI 而非普通卡池）才启用

数据模板（仅供参考）

```typescript
{
    label: "示例",
    key: "your_mod_organ_dual",
    // ...
    cardsByOwner: {
        player: ["your_mod_card_player_ver"],
        enemy: ["your_mod_card_enemy_ver"]
    }
}
```

如果用了这个字段，请写清楚为什么两个版本效果类似但引用不同卡（如 tag 差异导致池匹配问题），避免退化成「双模式设计」。

## 场景 9：主动能力（activeAbilities）

目标
    玩家 / 敌人在回合中主动激活的能力（非卡牌）。

涉及机制
    `activeAbilities: ActiveAbility[]` — 器官定义主动能力
    带能量代价、冷却、每回合使用次数上限

数据模板（示例结构，当前 organList 尚无正式案例，参考 ActiveAbility 类型）

```typescript
{
    label: "冷却核心",
    key: "your_mod_organ_active_core",
    rarity: OrganRarity.Rare,
    part: OrganPartEnum.Core,
    status: { "max-mass": 30 },
    current: ["mass"],
    interaction: { possess: { target: { key: "self" }, effects: [] } },
    activeAbilities: [{
        key: "coolDown",
        label: "冷却",
        describe: ["消耗 1 能量，本回合结束前获得 5 ", {$:"护甲"}],
        usage: { type: "direct" },
        restrictions: {
            costs: { energy: 1 },
            uses: { perTurn: 1 }
        },
        effects: [{ key: "gainArmor", params: { value: 5 } }]
    }]
}
```

要点

    usage.type：`"direct"`（无需选择）/ `"selectTarget"`（选目标）/ `"toggle"`（开关）/ `"allTargets"`（全体）
    restrictions.uses.perTurn / perBattle / perFloor / total — 使用次数上限
    restrictions.cooldown — 冷却回合数
    restrictions.charges — 蓄力使用（需先充能）

当前状态
    OrganMap 类型已支持 activeAbilities 字段
    organList 中尚无成型示例
    实现新主动能力时建议：先跑通简单 direct + costs 版本再扩展

    参考/实现参考手册.md — abilityCharges / cooldown / toggle 相关 effect key

## 场景 10：升级配置（upgrade）

目标
    器官可以在水池「洗涤」里升级。到了写过的等级发生一次效果（加血、减伤、锻造它给的牌都写在这里）。

涉及机制
    `upgrade.milestones` — 到某级发生一次
    水池只认里程碑：没写 `milestones` 的器官不会出现在洗涤列表里
    可以升到最高那一档，中间空级用来垫进度
    战斗里悬停默认不展示里程碑。会在战斗中自己升级的器官再写 `upgrade.combatUpgrade: true`

数据模板（现行：蚁颚）

```typescript
{
    label: "蚁颚",
    key: "enemy_organ_ant_mandible",
    describe: ["提供1张", {"@": 0}],
    rarity: OrganRarity.Common,
    part: OrganPartEnum.Bone,
    status: { "max-mass": 20 },
    current: ["mass"],
    cards: ["enemy_card_swarm_bite"],
    upgrade: {
        maxLevel: 2,
        milestones: [{
            level: 2,
            effects: [{ key: "upgradeOrganCards" }]
        }]
    }
}
```

要点

    每一档可以写 `describe`，升级页悬停时竖着列出路线
    只锻本器官提供的牌：里程碑只写 `effects: [{ key: "upgradeOrganCards" }]`，不必写 describe；展示为「锻造提供的xx卡牌」，卡名可悬停。只锻其中一张时加 `params.cardKey`
    同一档还有别的效果：describe 只写锻牌以外的那几句（现行：战斗之心 2 级「最大生命 +2」），锻牌那句糖会自动补在前面
    把提供的牌锻造、改被动、加生命，都放在对应等级的 `effects` 里，不要另开「升级卡牌: n」字段
    锻过的牌在介绍和悬停里显示为「群咬+」这种 `名字+`，不要再写一句「Lv.2：额外攻击」
    器官提供多张牌、只想锻其中一张：`upgradeOrganCards` 加 `params.cardKey`
    空过一档再给强效果：仍要写一条只有 `describe`、没有 `effects` 的里程碑（现行：腐蚀腺 3 级「无」、4 级每层额外伤害 1→2；蓄力腺 2 级「无」、3 级蓄势 1→2；毒皮 2/4 级「无」、3 级反弹中毒 2→3）。不写的话水池能垫过去，但悬停会把下一档高亮错位
    `perLevel` 仍然存在（每升一级都跑），水池列表和封顶只看里程碑
    默认费用随稀有度和当前等级变；打开列表时锁死一次（含波动）
    升级发生在水池「洗涤」，见《水池行动扩展系统》
    生效期间给状态（力量等）不要写在 milestone 的 applyState 里，用 `work.grantStates` + `fromLevel`，见场景 11

## 场景 11：生效时获得状态（损坏即消失）

目标
    「未损坏时拥有 1 力量」。战斗中损坏，这份力量立刻没掉；修好或下一场开战再回来。不要写成开战发一层就不管了。

涉及机制
    `work.grantStates` — 引擎在 work 激活时给持有者挂状态，撤 work 时按差额撤销
    只在战斗中兑现。`Player.startBattle()` 会清空状态栏，糖会在 `battleStart` 自动再挂
    `fromLevel` 用来等洗涤升到某一档才开始给

数据模板（现行：战斗之心）

```typescript
{
    label: "战斗之心",
    key: "test_organ_cards_001",
    describe: ["提供1张", {"@": 0}, "卡牌到牌组", "<br>", "最大生命+2"],
    rarity: OrganRarity.Common,
    part: OrganPartEnum.Heart,
    status: { "max-mass": 30 },
    current: ["mass"],
    cards: ["original_card_00001"],
    upgrade: {
        maxLevel: 3,
        milestones: [
            {
                level: 2,
                describe: ["最大生命 +2"],
                effects: [
                    { key: "upgradeOrganCards" },
                    { key: "addMaxHealthAndHeal", params: { value: 2 } }
                ]
            },
            {
                level: 3,
                describe: ["生效时", {$:"力量"}, " +1"]
            }
        ]
    },
    interaction: {
        possess: {
            target: { key: "self" },
            effects: [{ key: "addMaxHealthAndHeal", params: { value: 2 } }]
        },
        work: {
            target: { key: "self" },
            grantStates: [
                { stateKey: "power", stacks: 1, fromLevel: 3 }
            ]
        }
    }
}
```

常见变体

    拿到就给：去掉 `fromLevel`
    多层：`stacks: 2`（现行：重锤 3 级力量 +2）
    开关型状态：`stacks: 1`（现行：壁垒甲壳，壁垒用 grantStates，开战会清栏也还能再挂）
    升到某级再多赠一层：同一 stateKey 再写一条 `fromLevel`（现行：柔韧甲片 3 级 3→4）
    同时给两种状态：`grantStates` 数组里再写一条
    每回合再叠一层：那是一次性施加，用场景 5 的 turnStart 触发器，不要用 grantStates

要点

    work 触发器只是监听器，`applyState` 加出去的层不会因为损坏而自动消失
    不要写 `battleStart` 加力量 + `break` 再 `changeStateStack -1`。力量允许负层，手扣会扣成 -1
    不要写 `removeState("power")`，那会把牌给的力量一并清掉
    `work.effects` 不会在激活 work 时执行，不能拿来当持续赠层
    目前只有器官的 work 读取 `grantStates`，写在 possess 上无效

## 常见错误与修正

错误 1：写 lose 交互清理属性
    错：在 interaction 里写 lose 段，手动 removeState / removeMaxHealth
    对：不写。器官提供的 StatusModifier 在失去时自动撤销
    参考：CLAUDE.md 「修饰器清理是自动的」

错误 2：不写 current 数组
    症状：器官的自定义 status 值（damage-taken 之类）刷新页面后被清零
    修复：把这些 key 加进 `current: [...]`，让存档序列化

错误 3：直接改 status 值
    错：EffectFunc 里 `organ.status["damage-taken"].value += 5`
    对：走 addCurrent / addStatusBase 之类的效果，让修饰器和事件系统统一处理

错误 4：Boss / 玩家双模式
    错：在 reaction 里判断 `$owner.isEnemy` 走不同分支
    对：删掉分支，同一器官两边效果一致（器官对称原则）

错误 5：孤立时完全无效
    症状：某器官必须和另一个器官联动，独立时不做任何事
    对：给它一个保底收益（+X 生命 / +Y 物质），让「变弱但仍生效」
    参考：器官独立原则

错误 6：max-mass 忘了写
    症状：器官不会因累计受伤而损坏
    修复：status 里必须有 `"max-mass": N`，current 里加 `"mass"`

错误 7：把卡牌硬编码到 organ 里
    错：organ.interaction.possess.effects 里直接写「加一张卡到手牌」
    对：把卡牌 key 写到 organ.cards，让引擎处理生命周期

错误 8：describe 里用 `{ "@": N }` 但 cards 数组没那么多张
    症状：UI 显示 undefined 或错误的卡名
    修复：`{ "@": 0 }` 对应 cards[0]，索引不能越界

错误 9：用手写开战加层、损坏扣层来做「生效时力量」
    错：work 监听 battleStart 去 applyState，再在 break 里 changeStateStack -1
    对：写 `work.grantStates`，见场景 11
