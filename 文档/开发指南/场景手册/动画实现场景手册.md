# 动画实现场景手册

面向 AI、Mod 作者与核心系统开发者的场景式教程。想在游戏里播一个视觉效果，先在下半的场景清单里找相似场景，复制模板，改参数；想改动画系统本身，看后半部分的原理章节。

本手册与其他文档的分工
    src/ui/animation/types.ts — AnimationDefinition / AnimationPlayOptions / AnimationHandle 的字段规格
    src/ui/animation/AnimationManager.ts — 单例管理器实现（注册、绑定、播放、取消、队列）
    src/ui/animation/useAnimation.ts — Vue composable，组件内的绑定入口
    src/ui/animation/presets.ts — 内置预设动画清单
    本手册 — 我要在数据/组件里做出 X 视觉效果，具体怎么写

实证案例（本手册的样板都从这几个组件里抽）
    src/ui/components/object/Target/Chara/components/CharaAnimator.vue — 数据驱动死亡演出（alive → death_fadeout）、触发器接受击动画
    src/ui/components/object/Target/Chara/components/HitText.vue — append 模式实战：受击跳字的接线与连击排布
    src/ui/animation/components/HitTextItem.vue — append 模式的 appendComponent 样板
    src/ui/components/interaction/RandomCardShowcase.vue — 事件用多阶段演出（appear → 停留 → exit）

## 使用方法

每个场景包含
    目标 — 一句话说清楚要产生什么视觉效果
    涉及机制 — 用到哪些 AnimationDefinition 字段、哪个模式
    数据模板 — 完整可复制的 preset 定义 / 组件片段
    常见变体 — 数值 / 参数小改
    要点 — 与相邻场景的分界线，容易踩的坑

三层职责先记住
    注册层（数据）— 在 `presets.ts` 或 mod 里注册一个 AnimationDefinition
    管理层（引擎）— `animationManager` 负责元素绑定、通道互斥、优先级打断、队列
    使用层（组件）— `useAnimation(bindingId)` 拿到 `animRef` 与 `play()`，在合适的生命周期时机调用

三种模式先记住
    overlay — 保持原 DOM，叠加视觉效果（闪、抖、发光、淡入/出）；90% 的场景都用它
    replace — 临时替换 DOM 内容播动画（死亡演出、变身）；本项目目前**未实测**
    append — 在 DOM 旁边添加临时元素（跳字、粒子）；已由受击跳字实证，见场景 11

播放前还要过两道全局闸门（见场景 13）
    玩家在设置里关掉了该动画所属的 category，或者开了「跳过全部动画」，play 会走空转路径
    空转路径照样 resolve promise、照样补触发 callbacks，所以业务流程不会因为玩家关动画而卡住

## 场景 1：复用一个现成的 preset（最基础）

目标
    「让敌人被击中时闪一下」「让某个按钮 pulse 强调一次」——不新加预设，直接用 `presets.ts` 里已经有的动画。

涉及机制
    组件里挂 `useAnimation(bindingId)`
    在需要的时机调 `play("presetKey")`

数据模板

```vue
<template>
    <div ref="animRef" class="something">…</div>
</template>

<script setup lang="ts">
import { useAnimation } from "@/ui/animation/useAnimation"

const { animRef, play } = useAnimation("some_unique_id")

function onHit() {
    play("hit_flash")   // presets.ts 里已注册的 key
}
</script>
```

常见变体
    同时想让它抖动：`play("hit_flash"); play("hit_shake")`（不同 channel 会并行）
    只想强调一次：`play("pulse")`

要点
    bindingId 全局唯一。同一个 id 只能绑定一个元素——如果两处组件都用 `"enemy_death"`，后绑的会覆盖前一个。给 Entity 类的组件用 `"chara_" + entity.__id` 这种带 id 的形式。
    `play()` 是异步的（返回 `Promise<AnimationHandle>`），但不 await 也能触发，用于「触发即忘」场景。

## 场景 2：注册一个简单的预设动画（声明式 animate）

目标
    「新增一个『放大 20% 再回来』的强调动画」「新增一个『淡入 + 从下方滑入』的入场动画」——单个 tween 就能表达。

涉及机制
    `AnimationDefinition.animate`：`{ from?, to?, duration?, ease? }` 的 GSAP tween 简写
    在 `presets.ts` 的数组里追加一项，或在 mod 里 `animationManager.register(def)`

数据模板

```typescript
// src/ui/animation/presets.ts
{
    key: "slide_in_bottom",
    mode: "overlay",
    channel: "visibility",
    animate: {
        from: { opacity: 0, y: 40 },
        to: { opacity: 1, y: 0 },
        duration: 0.4,
        ease: "power2.out",
    },
},
```

常见变体
    只写 `from`——GSAP `.from()`，会从 from 状态动画到当前样式
    只写 `to`——GSAP `.to()`，从当前样式动画到 to
    同时写 from + to——GSAP `.fromTo()`，两端都定死
    ease 常用值：`"power1.out"`（普通结束缓动）、`"back.out(1.4)"`（带回弹的入场）、`"power2.in"`（重力式退场）

要点
    animate 的 from/to 是 GSAP TweenVars，支持 opacity、scale、x、y、rotation、filter、backgroundColor 等
    没写 duration 时默认 0.5s；没写 ease 时默认 `"power1.inOut"`

## 场景 3：注册一个复杂的预设动画（build 时间轴）

目标
    「一个『闪白 + 变灰 + 复原』的三段效果」「一个『先放大后 fade + 位移』的多阶段退场」——单个 tween 表达不了，需要多个 to() 串起来。

涉及机制
    `AnimationDefinition.build(el, params?) => gsap.core.Timeline`
    返回一个 `paused: true` 的 timeline，AnimationManager 会替你 `play()`

数据模板

```typescript
{
    key: "card_duplicate_fadeout",
    mode: "overlay",
    channel: "visibility",
    interruptible: false,
    build: (el) => {
        return gsap.timeline({ paused: true })
            .to(el, { scale: 1.15, filter: "brightness(1.5)", duration: 0.25, ease: "power1.out" })
            .to(el, { scale: 1.05, filter: "brightness(1.15)", duration: 0.2, ease: "power1.inOut" })
            .to(el, { opacity: 0, scale: 1.25, duration: 0.45, ease: "power2.in" })
    },
},
```

常见变体
    需要外部传参调整时长/幅度：`build(el, params) { const dur = params?.duration ?? 0.5; … }`；调用侧 `play("key", { params: { duration: 0.3 } })`
    在时间轴指定位置放置：`.to(el, { … }, "-=0.1")` 与前段重叠 0.1s，或 `.to(el, { … }, 0.5)` 在绝对 0.5s

要点
    必须 `paused: true`；否则 AnimationManager 拿到手时动画可能已经跑过一半
    build 与 animate 二选一，同时写以 build 为准
    build 里想触发中间回调（如"半程时播个音效"），用 `callbacks` 字段而不是 `.call()`（见场景 11）

## 场景 4：组件内绑定并主动播放

目标
    「一个组件挂载后需要动画能力」——最基本的接入方式，`useAnimation` composable 一步到位。

涉及机制
    `const { animRef, play, cancel, cancelAll } = useAnimation(bindingId)`
    `<div ref="animRef">` 把 composable 内的 ref 绑到实际 DOM
    onMounted 时会自动 bind，onBeforeUnmount 会自动 unbind

数据模板

```vue
<template>
    <div ref="animRef" class="target">…</div>
</template>

<script setup lang="ts">
import { useAnimation } from "@/ui/animation/useAnimation"

const props = defineProps<{ entityId: string }>()

// bindingId 要有唯一性——用实体 id 或组件语义 + id 组合
const { animRef, play, cancel } = useAnimation(`chara_${props.entityId}`)

// 什么时候播由业务决定：交互回调、watch 数据变化、生命周期钩子等
function onTakeDamage() {
    play("hit_flash")
    play("hit_shake")
}
</script>
```

常见变体
    单文件组件里播多个：多次 `play()` 同一个 bindingId 即可，不同 channel 并行
    需要在父组件里控制：把 `play` 通过 `defineExpose({ play })` 暴露

要点
    bindingId 不能重复。如果一个 Entity 有多个动画锚点（如"整体"+"头像"），就用不同 id：`"chara_" + id`, `"chara_avatar_" + id`。
    `animRef` 必须在模板里绑到一个 HTMLElement，绑到组件实例不行（组件不是 DOM）。

## 场景 5：等待动画播完再做下一步

目标
    「死亡动画播完再触发结算」「演出结束才 emit complete」——业务逻辑必须等动画。

涉及机制
    `const handle = await play(key)` 拿到 handle
    `await handle.promise` 等它跑完

数据模板

```typescript
async function killAnimation() {
    const handle = await play("death_fadeout")
    await handle.promise
    emit("dead")   // 演完再上报
}
```

常见变体
    只关心播完不关心 handle：`const h = await play(k); await h.promise` 常写；也可以直接 `await (await play(k)).promise`

要点
    `play()` 返回的是 `Promise<AnimationHandle>`，不是 `Promise<void>`——第一层 await 是拿 handle，第二层 await 是等动画本身
    动画被打断（cancel、被更高 priority 顶掉）时 promise 也会 resolve，不会 reject。想区分被打断，用 `options.onCancel` 回调

## 场景 6：多阶段动画演出

目标
    「一张卡先淡入，停留一会儿让玩家看清，然后向上飘走消散」——组合多个动画 + 停留时间。

涉及机制
    在 onMounted 里 async 串行播放，中间用 `setTimeout` 保留时间
    每段之间 `await handle.promise` 确保上一段真的完了

数据模板（源自 RandomCardShowcase.vue）

```vue
<script setup lang="ts">
import { onMounted } from "vue"
import { useAnimation } from "@/ui/animation/useAnimation"

const props = defineProps<{ holdMs: number, mode: "remove" | "duplicate" }>()
const emit = defineEmits<{ complete: [] }>()

const { animRef, play } = useAnimation("random_card_showcase")

onMounted(async () => {
    // 1. 入场
    const appear = await play("card_appear")
    await appear.promise

    // 2. 停留（让玩家看清）
    await new Promise((r) => setTimeout(r, props.holdMs))

    // 3. 退场（按模式选不同动画）
    const exitKey = props.mode === "remove" ? "card_ascend_fadeout" : "card_duplicate_fadeout"
    const exit = await play(exitKey)
    await exit.promise

    emit("complete")
})
</script>
```

常见变体
    多层次奖励弹出：入场 → 数值跳字 → 出场；每一层都是一个 preset，串起来
    可跳过：加个"点击跳过"按钮触发 `cancel()`；因为 `.promise` 也在 cancel 时 resolve，后续步骤照走

要点
    onMounted 里的 async 函数**要小心 unmount 中断**——如果弹窗在动画中途被外部关闭，setTimeout 里的代码继续执行会踩 unmounted 组件。RandomCardShowcase 目前的模态弹窗是"演完自己关"，所以不用担心；对可能被打断的场景，需要在 onBeforeUnmount 里 cancel 并加 `if (unmounted) return` 守卫
    停留时长 (holdMs) 拿捏：短于 800ms 玩家来不及看清，长于 1500ms 会拖累节奏

## 场景 7：动画被数据驱动（watch 触发）

目标
    「Entity 死亡时自动播死亡动画」——不是玩家操作触发，是数据变化触发。

涉及机制
    `watch()` 数据字段，变化时 `play()`
    死亡动画通常要 `interruptible: false` 避免被别的动画干扰

数据模板（源自 CharaAnimator.vue）

```vue
<script setup lang="ts">
import { watch } from "vue"
import { useAnimation } from "@/ui/animation/useAnimation"

const props = defineProps<{ entity: Entity }>()

const { animRef, play } = useAnimation(`chara_${props.entity.__id}`)

watch(
    () => props.entity.isAlive,
    async (alive, wasAlive) => {
        if (!alive && wasAlive) {
            const h = await play("death_fadeout")
            await h.promise
            // 演完之后可以 emit 或让 v-if 隐藏
        }
    }
)
</script>
```

常见变体
    受伤动画：`watch(() => entity.current.health.value, (n, o) => { if (n < o) play("hit_flash") })`
    获得护甲发光：`watch(() => entity.status.armor?.value, (n, o) => { if ((n ?? 0) > (o ?? 0)) play("heal_glow") })`

要点
    watch 的响应式 source 要是 getter 函数——`() => x.value`，不能直接传 `x.value`（那样只传当时的快照）
    不要 watch 高频变化的字段（如每帧变的血条动画数）——会疯狂重播

## 场景 8：channel 互斥 vs priority 打断（设计决策）

目标
    「两个动画能不能同时播？」「新动画能不能打断旧的？」——决定 AnimationDefinition 的 `channel` 和 `priority`。

涉及机制
    `channel`（默认 `"default"`）— 同 channel 互斥，不同 channel 并行
    `priority`（默认 0）— 同 channel 内高 priority 顶掉低 priority
    `interruptible`（默认 true）— false 表示这段动画不能被任何东西打断

决策流程

```
两个动画能否视觉共存？
├─ 能（例：淡入 + 抖动） → 不同 channel
└─ 不能（例：淡入 + 淡出） → 同 channel
    ├─ 新来的更重要（例：死亡覆盖受伤） → 新的 priority 更高
    └─ 新来的不该抢 → 新的 priority 更低，且旧的 interruptible: false
```

预设 channel 命名参考（`presets.ts` 里的实际用法）
    `"visibility"` — 透明度/存在性相关（fade_in/out, scale_in, card_appear/exit）
    `"color"` — 颜色/滤镜（hit_flash, heal_glow）
    `"position"` — 位移抖动（hit_shake）
    `"emphasis"` — 强调放大（pulse）
    `"death"` — 死亡专用（death_fadeout, priority 999）

要点
    channel 是自由字符串，不是枚举。命名有惯例但没约束
    priority 数字自由取；死亡动画用 999 是「几乎不会被顶掉」的惯例值
    channel 判定发生在 play 时——已经在跑的 channel 有活跃动画，新来的按 priority 决定是覆盖还是排队

## 场景 9：重复触发策略（repeat）

目标
    「玩家连续点击一个按钮，同一个动画怎么处理？」——从头重播 / 忽略 / 排队。

涉及机制
    `repeat: "restart" | "ignore" | "queue"`（默认 `"restart"`）

选哪个
    `restart`——每次都从头开始（默认）。适合脉冲、闪烁、抖动这类"最后一次动作最重要"的
    `ignore`——已经在播就忽略新触发。适合入场动画，不能被反复"再入场一次"
    `queue`——排到当前动画后面依次播。适合数值跳字这类每次触发都必须显示的

数据模板

```typescript
{
    key: "damage_number_popup",
    mode: "append",
    channel: "damage_number",
    repeat: "queue",   // 连续掉血时数字排队一个个弹
    animate: { … },
},
```

要点
    `queue` 只有同一个 bindingId + 同一个 key 的重复触发会排队；不同 key 不排队（走 channel 逻辑）
    `restart` 会 kill 上一次的 tween，overlay 模式下 style 可能停在中间值——这是 overlay 的天然痛点，见场景 12

## 场景 10：设置 interruptible 保护关键动画

目标
    「死亡动画一旦开始必须完整播完，不能被任何东西打断」「演出中的卡不能被别的效果顶掉」。

涉及机制
    `interruptible: false`——播放期间新来的同 channel 高优先级动画会被拒绝（play 返回一个立即结束的 handle）

数据模板

```typescript
{
    key: "death_fadeout",
    mode: "overlay",
    channel: "death",
    priority: 999,
    interruptible: false,   // 死透了才停
    animate: {
        to: { opacity: 0 },
        duration: 0.6,
        ease: "power1.in",
    },
},
```

要点
    `interruptible: false` **只对同 channel 的抢占生效**——别的 channel 想并行播还是能播
    如果你想让某个东西"锁定"整个组件的所有动画，让它 priority 极高 + interruptible: false，同时手动 cancel 所有别的 channel

## 场景 11：append 模式跳字/粒子（已实证，样板取自受击跳字）

目标
    「掉血时在敌人头顶跳一个 -5」「获得金币时飘一串粒子」——不是让原元素动，而是往它旁边加临时元素。

涉及机制
    `mode: "append"` + `appendComponent`（一个 Vue 组件）+ `duration`
    AnimationManager 把 component 塞进 `state.appendItems`，使用侧用 `v-for="item in appendItems"` 渲染
    **append 模式下 AnimationManager 完全不碰 DOM**：视觉全部由 appendComponent 自己实现（CSS 动画或组件内 gsap），
    manager 的 timeline 只是一个"多久之后把这一项摘掉"的计时器

最重要的一条：不要给 append 写 `animate`

    animate / build 里的目标元素是**宿主元素**（`useAnimation` 绑定的那个 el），不是新插进来的组件。
    给 append 写 `animate: { to: { y: -40 } }`，向上飘走的会是整个角色本体。
    append 的时长写在顶层 `duration` 字段里（秒），manager 用它计时，并把值（已按全局速度换算）
    通过 props 下发给 appendComponent，组件拿它设自己的 animation-duration，两边才对得齐。

数据模板

```typescript
// presets.ts
import HitTextItem from "./components/HitTextItem.vue"

{
    key: "hit_text",
    category: "hitText",       // 归入类别，玩家可以在设置里单独关掉
    mode: "append",
    channel: "hit_text",
    appendComponent: HitTextItem,
    duration: 1.8,             // 组件挂多久（秒），不是 gsap 动画时长
},
```

```vue
<!-- appendComponent：视觉全在这里，props 由 play 的 params + manager 注入的 duration 合并而来 -->
<template>
<div class="hit-text" :class="kind" :style="style">{{ text }}</div>
</template>

<script setup lang="ts">
const props = withDefaults(defineProps<{
    text: string
    kind?: string
    offsetX?: number
    duration?: number          // manager 注入，已按全局动画速度换算过
}>(), { kind: 'damage', offsetX: 0, duration: 1.8 })

const style = computed(() => ({
    left: `calc(50% + ${props.offsetX}px)`,
    animationDuration: `${props.duration}s`
}))
</script>
```

```vue
<!-- 使用侧组件：自己就是那个飘字层 -->
<template>
<div ref="animRef" class="hit-text-layer">
    <component
        v-for="item in appendItems"
        :key="item.id"
        :is="item.component"
        v-bind="item.props"
    />
</div>
</template>

<script setup lang="ts">
const { animRef, play, appendItems } = useAnimation(`chara_hit_${target.__id}`)

play('hit_text', { params: { text: '-5', kind: 'damage', offsetX: 0 } })
</script>
```

常见变体
    多个同时存在 — append 不走 channel 互斥，连播多次就是多份实例并存，不用设 `repeat`
    错开出场 — 用延迟调用 play（setTimeout）而不是 CSS animation-delay，理由见下面的要点
    传更多参数 — 都塞进 `play` 的 `params`，manager 会连同 duration 一起作为 props 交给组件

要点
    play 的 params 会和 manager 注入的 duration 合并成 `item.props`，使用侧 `v-bind="item.props"` 透传给组件
    append 不占 channel：占了的话第二次 play 会把第一个还挂在空中的实例 cancel 掉，连击就只剩一个
    每次 play 生成一个自增的 appendId，结束时按 id 精确摘除，不会误伤同 key 的其他实例
    错开出场要用延迟 play，不要用组件内的 `animation-delay`：manager 的计时器从 play 那刻起算，
    用 CSS 延迟的话组件会比动画先一步被摘掉，最后几个跳字会被截断（延迟的 timer 记得在卸载时 clear）
    宿主元素别选会被隐藏的容器 — 跳字层要挂在死亡演出容器**外面**，否则致命一击的数字会随
    `death_fadeout` 的淡出和 `visibility: hidden` 一起消失，正好是最该看到数字的那一下

## 场景 12：replace 模式死亡/变身演出（**未实测**，基于代码推断）

目标
    「敌人死亡时暂时用一个"骨架化"组件替换掉本体渲染」「变身时把 A 形象替换成 B 形象」。

涉及机制
    `mode: "replace"` + `replaceComponent`
    使用侧组件用 `replaceComponent` 判断当前是否处于替换态，来切换渲染

数据模板

```typescript
// presets.ts
import EnemyDeathEffect from "@/ui/animation/components/EnemyDeathEffect.vue"

{
    key: "enemy_death_replace",
    mode: "replace",
    channel: "death",
    priority: 999,
    interruptible: false,
    replaceComponent: EnemyDeathEffect,
    // build 或 animate 至少要有一个；建议 build 才好控制时长
    animate: { duration: 1.2 },
},
```

```vue
<template>
    <div ref="animRef" class="enemy">
        <component v-if="replaceComponent" :is="replaceComponent" />
        <EnemyBody v-else :entity="entity" />
    </div>
</template>

<script setup lang="ts">
const { animRef, play, replaceComponent } = useAnimation(`enemy_${id}`)

watch(() => entity.isAlive, (a, w) => {
    if (!a && w) play("enemy_death_replace")
})
</script>
```

要点（谨慎——本模式在项目里目前无实证）
    replace 期间原 DOM 由使用侧决定是否隐藏——AnimationManager 只负责往 state 里塞 replaceComponent，不会自己隐藏 el
    动画结束后 replaceComponent 会被清空；使用侧的 v-if 自动切回本体
    与 append 不同，replace 的 animate / build 仍然作用在宿主元素上，写法和 overlay 一致
    做 append 时修掉的 state 响应式问题（见后半「组件如何观察」）对 replace 同样有效，
    所以 `replaceComponent` 现在能正常驱动渲染了，但整条链路仍未真跑过

## 场景 13：注册动画类别 / 让玩家能关掉你的动画

目标
    「我加的这个演出有人嫌晃眼，想让玩家自己关」「Mod 里加了一整套特效，希望在设置面板里单独出一行开关」。

涉及机制
    `AnimationDefinition.category` — 声明这个动画属于哪一类
    `registerAnimationCategory` — 往类别注册表里加一类，设置面板遍历注册表自动多一行
    `settings.animationCategories` — 存玩家的开关状态

内置类别（`src/ui/animation/categories.ts`）

```
hit       受击表现    hit_flash / hit_shake
hitText   伤害跳字    hit_text
heal      治疗表现    heal_glow
death     死亡演出    death_fadeout
card      卡牌演出    card_appear / card_ascend_fadeout / card_duplicate_fadeout
ui        界面通用    fade_in / fade_out / scale_in / pulse
```

数据模板

```typescript
// 挂到现有类别：动画定义里加一行就行
{
    key: "my_relic_glow",
    category: "ui",
    mode: "overlay",
    animate: { to: { opacity: 0.5 }, duration: 0.3 },
}

// Mod 注册自己的类别
import { registerAnimationCategory } from "@/ui/animation"

registerAnimationCategory({
    key: "myMod_ritual",
    label: "仪式特效",
    describe: "献祭与召唤时的全屏演出"
})
```

要点
    不填 category 的动画不受任何开关管辖，永远播放；想让玩家能关就必须填
    存档只记玩家**主动关掉**的项，判定是 `!== false`，所以以后新增类别不会因为旧存档缺 key 而默认关闭
    类别被关掉和「跳过全部动画」走的是同一条空转路径：不建时间轴、不碰 DOM、不塞 appendItems，
    但 `onStart` / `callbacks` / `onEnd` 照常触发，promise 照常 resolve
    因此**不要把游戏逻辑写在动画里**——玩家关掉动画后，只有视觉消失，流程必须照走

# 后半：AnimationManager 内部机制（核心系统开发者向）

## 数据结构

```typescript
// AnimationManager 单例内维护
{
    definitions:    Map<string, AnimationDefinition>,   // 注册表
    elements:       Map<string, HTMLElement>,           // bindingId → DOM
    states:         Map<string, AnimationBindingState>, // bindingId → 活跃状态
    activeByChannel: Map<string, Map<channel, handle>>, // channel 互斥用
    queues:         Map<string, Map<channel, thunk[]>>, // repeat: "queue" 的等待队列
    appendSeq:      number,                             // append 项 id 的自增序号
}

// AnimationBindingState（每个 bindingId 一份，shallowReactive）
{
    activeHandles: Map<string, AnimationHandle>,   // key 为 `channel:animKey`，append 项用 appendId
    replaceComponent: Component | null,
    appendItems: reactive([{ id, component, props? }]),
}
```

`activeByChannel` 是 **per-channel** 的——同一 bindingId 同时可以有多个 channel 的动画在跑。append 模式**不进** `activeByChannel`（它要多实例并存，占了 channel 会被后来者 cancel），只登记在 `activeHandles` 里。

state 必须是响应式的，否则组件里 `v-for` 渲染的 `appendItems` 永远不会更新。用的是 `shallowReactive` 包对象、`reactive` 包 `appendItems` 数组：`activeHandles` 里装着 gsap timeline 的闭包，深度代理它没有意义还有风险。**移除 appendItems 里的项必须原地 `splice`**，重新赋值会把响应式数组换成普通数组，之后就再也不更新了。

与全局设置相关的字段

```
AnimationDefinition.category   所属类别，玩家可在设置里按类别关；不填则不受管辖
AnimationDefinition.duration   append 模式专用，组件存活时长（秒）
AnimationHandle.appendId       append 模式专用，这次播放塞进 appendItems 的那一项的 id
settings.animationSpeed        全局速度倍率
settings.skipAnimation         跳过全部动画的总开关
settings.animationCategories   分类开关，只记被关掉的项
```

## bind / unbind 时机

由 `useAnimation` composable 自动接管
    onMounted 时 `bind(id, el)`——把 ref 拿到的 HTMLElement 存入 `bindings`
    onBeforeUnmount 时 `unbind(id)`——从 `bindings` 删除，并 cancelAll 该 id 上所有动画

**不由 composable 管的场景**：`animationManager.bind()` 也可手动调用（如动态创建的 overlay 元素）；此时必须成对手动 `unbind`。

## play 决策流程

```
play(bindingId, animKey, options)
├─ 查 definitions[animKey] → 拿 def；查不到 throw
├─ 查 elements[bindingId] → 拿 el；查不到 throw（play 是 async，用 .catch 兜）
├─ 全局闸门：skipAnimation 开着，或 def.category 被玩家关掉
│   └─ 走 playSkipped：onStart → 补触发所有 callbacks → onEnd → 返回已 resolve 的空 handle
├─ def.mode === "append" → 直接 playInternal，跳过下面的 channel 互斥
├─ 检查同 bindingId 内是否已有 activeByChannel[def.channel]
│   ├─ 有 & 是同 key → 走 repeat 策略（restart/ignore/queue）
│   ├─ 有 & 不同 key → 比 priority
│   │   ├─ 新 priority ≥ 旧 → 旧 interruptible? 是→cancel 旧的；否→排队
│   │   └─ 新 priority < 旧 → 排队或返回空 handle
│   └─ 无 → 直接创建
├─ 构建 timeline
│   ├─ append → 对空对象补间 duration 秒，完全不碰 el
│   ├─ build 优先，否则 animate（都作用于 el）
│   └─ timeline.timeScale(全局速度倍率)
├─ 注册状态
│   ├─ append → 生成 appendId，push 一项到 state.appendItems，props 带上换算后的 duration
│   ├─ replace → 塞 replaceComponent 到 state，结束时清空
│   └─ 其余 → 占住 activeByChannel[channel]
├─ 注入 callbacks（options.onAction）
├─ 用 timeline.eventCallback("onComplete", 清理 & resolve promise)
└─ timeline.play() → 返回 handle
```

空转路径（playSkipped）必须 resolve promise，这是硬约束：死亡演出、卡牌展示都在 `await handle.promise`，不 resolve 会让整条流程永久卡死。`callbacks` 也必须就地补触发，否则靠时间轴节点推进的多阶段演出会缺步骤。

## overlay 结束不清理 style 的坑

overlay 模式跑完后，GSAP 设置的 style（opacity/transform/filter）会**留在 DOM 上**。如果动画是"变化到某状态"（如 `to: { opacity: 0 }`），元素会一直保持 opacity:0。

解决方式
    要么让动画首尾闭合（先 to A 再 to 初始值）
    要么在业务层用 v-if 让元素消失
    要么在 `onEnd` 里手动 `gsap.set(el, { clearProps: "all" })`

CharaAnimator 用的是"死亡动画完后 v-if 隐藏"的组合；RandomCardShowcase 用的是"演完弹窗自动关，DOM 整个卸载"的组合——都规避了这个坑，但没有从根本上解决。

## 队列（queue）实现

`repeat: "queue"` 时新触发不会立即播——AnimationManager 内部维护一个每 (bindingId, key) 的等待队列。上一次动画的 onComplete 里会检查队列，有就取下一个继续 play。

**注意**：队列不跨 channel（同 channel 的其他 key 不会顶掉队列头部的等待）；队列不跨 bindingId。这意味着"排队"是很局部的概念。

## 回调（callbacks）

`AnimationDefinition.callbacks` 让预设动画定义能声明"某时刻做点事"，具体行为由使用侧的 `options.onAction` 决定：

```typescript
// 定义
{
    key: "spell_cast",
    build: (el) => gsap.timeline({ paused: true })
        .to(el, { scale: 1.5, duration: 0.3 })
        .to(el, { opacity: 0, duration: 0.3 }),
    callbacks: [
        { at: 300, action: "peak" },        // 0.3s 时触发
        { at: 600, action: "vanish" },      // 0.6s 时触发
    ],
},

// 使用
play("spell_cast", {
    onAction: (actionKey) => {
        if (actionKey === "peak") playSound("thud")
        if (actionKey === "vanish") emitParticles()
    },
})
```

这个机制让"预设动画的时间轴"跟"业务的时刻响应"解耦——预设作者不需要知道谁会用它。

## 组件如何观察 replaceComponent / appendItems

`useAnimation` 暴露的这两个是 computed，读的是内部的 `stateRef`。组件用 `<component :is="replaceComponent">` / `v-for="item in appendItems"` 即可自动响应。

这里有个曾经踩过的时序坑，改动前务必理解：state 是 `bind()` 创建的，而 `bind` 发生在 `onMounted`，比 composable 里几个 computed 的首次求值**晚**。如果 computed 直接调 `getState(bindingId)`，首次会拿到 `undefined`，而 `states` 是普通 Map 追踪不到变化，此后**再也不会重算**——appendItems 永远是空的，append 模式看上去完全不工作。所以 `useAnimation` 用一个 `shallowRef` 把 state 接出来，`bind` 之后赋值，computed 才会重新求值。

# 常见坑与排查

## 1. bindingId 重复导致后绑覆盖前绑
症状：两个组件都用同一个 id，第二个挂载时前一个的动画就打不到 DOM 了
排查：`animationManager.bindings` 表里同一个 key 只能有一条；给每个 Entity 用 `"chara_" + entity.__id` 这种带唯一 id 的形式

## 2. onMounted 里立刻 play 但 animRef 还没 bind
症状：play 报 warn"未绑定 bindingId"
排查：useAnimation 的 bind 也在 onMounted 里；顺序上通常是先 bind 再 play。但如果 play 在同一个 onMounted 的更前面执行（先 play 后 mount ref），会踩到；改用 `nextTick(() => play(…))`

## 3. 卡在动画结束不清理 style
症状：淡出动画播完，元素 opacity 一直是 0
排查：见"overlay 结束不清理 style 的坑"——加 v-if 隐藏 / clearProps 手动清 / 让动画首尾闭合

## 4. unmount 时未 cancel 导致 timeline 悬挂
症状：组件卸载后动画还在跑，GSAP 报"target is null"
排查：useAnimation 的 onBeforeUnmount 会 unbind 并 cancelAll，正常不会踩；手动 bind 的场景要成对 unbind

## 5. 多阶段演出中弹窗被外部关闭
症状：`await handle.promise` 后继续走的代码在已卸载组件上出错
排查：可能的话在 onBeforeUnmount 里 cancel；对可能被中断的场景，在每段 await 后加 `if (unmounted) return` 守卫
现状：RandomCardShowcase 是"演完自己关"，不存在中途关闭；能规避这个坑

## 6. interruptible: false + priority 低的死锁
症状：一个 priority=0 的动画设了 interruptible: false，别的高优先级动画播不了
排查：interruptible: false 会让此段动画完整播完，才让位；如果你希望"关键的东西能覆盖"，把关键动画的 priority 也拉高，同时接受本段动画的"占用时间"

## 7. watch 高频字段触发大量播放
症状：血条从 100 掉到 50 时触发了 50 次动画
排查：不要 watch 每帧变化的中间值；watch 数据的语义性变化（如 `isAlive`、`isHit` 布尔标记）；或做 debounce

## 8. queue 排队没触发下一个
症状：设置了 queue 的动画播了第一次，队列里的第二次没动
排查：只有 onComplete 触发时才会取下一个——如果第一次动画被 cancel 而不是完整播完，队列可能没走通；这是当前 AnimationManager 实现的一个限制

## 9. append 注册了但组件里没渲染
症状：play 调了、没报错，DOM 里什么都没多出来
排查：使用侧组件必须用 `v-for="item in appendItems"` 显式渲染，仅有 preset 定义不会自动出现在 DOM 里；确认 preset 写了 `appendComponent`（没写的话 manager 只跑计时器，不塞 appendItems）

## 10. append 动画飘走的是角色本体
症状：跳字没动，整个角色缓缓上移/淡出
排查：给 append 写了 `animate` 或 `build`——它们的目标是宿主元素。append 的视觉必须写在 appendComponent 内部，时长写顶层 `duration`

## 11. 连击时跳字只剩一个 / 前面的被吃掉
症状：多段攻击只看到最后一个数字，或者第一个播完其余全部消失
排查：这两条在当前实现里已经修掉（append 不占 channel、按 appendId 精确摘除）。如果自定义 manager 逻辑时重新引入，检查有没有让 append 走 channel 互斥、有没有按 key 前缀批量清理 appendItems

## 12. 跳字最后几个被截断
症状：连击的后几个数字刚出来就没了
排查：用了组件内的 `animation-delay` 来错开出场。manager 的计时器从 play 那刻起算，不认 CSS 延迟；改成延迟调用 play

## 13. 关掉动画后游戏流程卡住
症状：玩家开了「跳过全部动画」或关了某个类别，某个环节不再推进
排查：把游戏逻辑写进动画回调、或依赖动画残留 style 了。空转路径会 resolve promise 并补触发 callbacks，但**不会**产生任何 DOM 变化——如果某处靠动画结束后残留的 `opacity: 0` 把元素藏起来（见"overlay 结束不清理 style 的坑"），关掉动画后它会一直可见。正确做法是业务层用 v-if 自己控制显隐
