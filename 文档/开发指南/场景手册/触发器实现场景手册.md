# 触发器实现场景手册

面向 AI 与 Mod 开发者的场景式教程。想在数据里挂一个「监听 X 事件，做 Y 反应」的行为，先在本手册里找相似场景，复制模板，改数值和描述。

本手册与其他文档的分工
    参考/触发器系统.md — when × how × key 三轴的字段规格
    参考/反应系统详解.md — reaction 与 action 的完整语义
    参考/条件系统.md — condition 表达式语法
    本手册 — 我要实现「监听 X 事件执行 Y 行为」，数据长什么样

---

## 使用方法

每个场景包含
    目标 — 一句话说清楚要监听什么、响应什么
    涉及机制 — 用到哪些字段、依赖哪些 EffectFunc
    数据模板 — 完整可复制的 triggers + reaction 定义
    常见变体 — 数值 / 条件小改
    要点 — 与相邻场景的分界线，容易踩的坑

数据模板一律采用**声明式**（triggers + reaction）。命令式 `appendTrigger` 只在场景 9 出现，属于兜底方案。

## 场景 1：事件发生后响应（最基础）

目标
    「战斗结束时回复 5 生命」「回合结束时获得 3 点护甲」——事件已经发生了，我方响应做一件事。

涉及机制
    triggers 单条：`when: "after"`, `how` = owner 在事件中的角色, `key` = 事件名
    reaction 单条：`targetType` 指定效果作用于谁, `effect` 是 EffectUnit 数组

数据模板：回血石（战斗结束回 5 血）

```typescript
{
    label: "回血石",
    describe: ["战斗结束时", "回复", { key: ["status", "heal"] }, "生命"],
    key: "original_relic_00001",
    rarity: "common",
    pool: ["common"],
    status: { "heal": 5 },
    interaction: {
        possess: {
            target: { key: "self" },
            triggers: [{
                when: "after",
                how: "make",
                key: "battleEnd",
                action: "healOwner"
            }]
        }
    },
    reaction: {
        healOwner: [{
            targetType: "owner",
            key: "heal",
            effect: [{ key: "heal", params: { value: 5 } }]
        }]
    }
}
```

常见变体
    回合开始 / 回合结束触发：`key` 改 `turnStart` / `turnEnd`
    响应"我方受伤"："after take damage"（详见场景 4，还会用到 `$triggerEffect`）
    响应"抽到卡"："after take drawCard"
    响应"打出卡"："after make useCard"

要点
    触发器的挂载**目标是 owner**（这里 target: `self`, self 即 relic 本身；真正挂到玩家上由 possess 交互本身决定）——不需要写"挂到谁"，遗物 = 玩家、器官 = 敌人是约定
    `how` 选择：owner 在事件中扮演 source/medium/target 中的哪一方，就写哪一个
    `action` 字符串在 reaction 里必须能找到同名 key，否则触发器像"哑弹"一样静默失败

## 场景 2：事件执行前修改参数（before 拦截）

目标
    「受伤时减免 2 点伤害」「造成伤害时 +1 点」——事件还没执行，我方改它的参数。

涉及机制
    triggers 单条：`when: "before"`，其他同场景 1
    reaction 里目标是**触发这次事件的 Effect**，用 `targetType: "triggerEffect"`
    效果直接改 Effect 的 `params`，一般用专用 EffectFunc（例如 `modifyDamage`），也可以就地改数值

数据模板：护心镜（受伤减 2）

```typescript
{
    label: "护心镜",
    describe: ["受到伤害时", "减少", { key: ["status", "reduce"] }, "点"],
    key: "example_relic_heart_mirror",
    rarity: "uncommon",
    pool: ["common"],
    status: { "reduce": 2 },
    interaction: {
        possess: {
            target: { key: "self" },
            triggers: [{
                when: "before",
                how: "take",
                key: "damage",
                action: "reduceDamage"
            }]
        }
    },
    reaction: {
        reduceDamage: [{
            targetType: "triggerEffect",
            key: "modifyDamage",
            effect: [{ key: "modifyDamage", params: { value: -2 } }]
        }]
    }
}
```

常见变体
    造成伤害 +N（不是自己受伤）：`how` 改 `make`（自己是伤害来源），effect value 换正数
    只减免超过 X 点的伤害：加 condition `"$triggerEffect.params(value) > 10"`
    读取原始伤害值：`$triggerEffect.params(value)`——见场景 4 的详细说明

要点
    `before` 只有一个用途：在事件真正跑之前**改它的 params**。想在事件跑完再做别的事情用 `after`
    `targetType: "triggerEffect"` 是这个场景的固定写法——把效果作用于「引发这次触发的那个 Effect 对象」而不是某个 Entity
    别用 `after` + 想改 params——那时候 params 已经被消费，改了没用
    减免伤害的对比方案：状态 buff（`applyState armorPlus`）通常更适合可叠加、可交互的场合；触发器 before 适合"恒定"的减免

## 场景 3：一个 action 挂多个响应事件（连锁）

目标
    「战斗开始时同时 +1 力量、+3 护甲、抽 1 张牌」——一次触发做多件事。

涉及机制
    reaction 里每个 action key 对应的是**数组**，往数组里塞多份 `{ key, targetType, effect }`
    每份 event 都会依次执行；也可以让每份 event 用不同 targetType

数据模板：开战准备

```typescript
{
    label: "开战准备",
    describe: ["战斗开始时", "+1 力量, +3 护甲, 抽 1 张牌"],
    key: "example_relic_ready_for_battle",
    rarity: "rare",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "self" },
            triggers: [{
                when: "after",
                how: "take",
                key: "battleStart",
                disableUntil: "battleEnd",
                action: "readyForBattle"
            }]
        }
    },
    reaction: {
        readyForBattle: [
            {
                targetType: "owner",
                key: "applyPower",
                effect: [{ key: "applyState", params: { stateKey: "power", stacks: 1 } }]
            },
            {
                targetType: "owner",
                key: "gainArmor",
                effect: [{ key: "gainArmor", params: { value: 3 } }]
            },
            {
                targetType: "owner",
                key: "drawFromDrawPile",
                effect: [{ key: "drawFromDrawPile", params: { value: 1 } }]
            }
        ]
    }
}
```

常见变体
    同一 effect 数组塞多个 EffectUnit：也行，但 event 语义混在一起，Log 会难读——除非几个 EffectUnit 是"复合动作的组成部件"（例如 gainArmor 里内部先加 base 再 recompute），否则拆成多个 event 更清晰
    有的 event 要作用到别的 target：改各自的 targetType（见场景 4）

要点
    多 event 是**顺序执行**，不是并行——如果第 2 个 event 依赖第 1 个改完的状态，可以按序放
    每个 event 都单独走一次 doEvent、独立可被别的触发器再监听（可能导致意外级联，注意）
    condition 可以放在**外层**（整批不满足就整批不响应）也可以放在**单个 event 上**（只跳过其中某个）

## 场景 4：从事件里取用别的对象（跨方引用）

目标
    「受伤时，对打伤我的那家伙施加 2 层流血」「反击伤害的数值取当前受到的伤害」——响应里要用到原事件里的 source/medium/target，或者原 Effect 的参数。

涉及机制
    reaction 里三个引用字段
        `targetType` — 决定这个 event 打给谁（这个 event 自己的 target）
        `sourceTargetType` — 决定这个 event 的 source 是谁（默认是 item 自己）
        `mediumTargetType` — 决定这个 event 的 medium 是谁（默认是 item）
    可选值：`eventSource / eventMedium / eventTarget / triggerSource / triggerOwner / owner / triggerEffect / randomEnemy`
    数值级引用用 `$` 表达式：`$triggerEffect.params(value)` `$owner.status(strength)` 等，写在 effect 的 params 里

数据模板：荆棘反噬（对方打你，你给对方流血 2）

```typescript
{
    label: "荆棘反噬",
    describe: ["受到伤害时", "对来源施加 2 层流血"],
    key: "example_relic_thorn_curse",
    rarity: "uncommon",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "self" },
            triggers: [{
                when: "after",
                how: "take",
                key: "damage",
                action: "bleedAttacker"
            }]
        }
    },
    reaction: {
        bleedAttacker: [{
            targetType: "eventSource",
            key: "applyBleed",
            effect: [{
                key: "applyState",
                params: { stateKey: "bleed", stacks: 2 }
            }]
        }]
    }
}
```

数据模板：反射护甲（反击伤害 = 你受到的伤害数值）

```typescript
reaction: {
    reflectDamage: [{
        targetType: "eventSource",
        key: "damage",
        effect: [{
            key: "damage",
            params: { value: "$triggerEffect.params(value)" }
        }]
    }]
}
```

常见变体
    对 event 的 medium 做点什么（比如打伤自己的那张卡）：`targetType: "eventMedium"`
    响应"敌人的死亡事件"，把击杀奖励给到自己：`sourceTargetType: "triggerOwner"` + `targetType: "owner"`
    读取受伤时的护甲量：`$owner.status(armor)`——完整 `$` 表达式列表见 `参考/实现参考手册.md`

要点
    默认（不写 sourceTargetType/mediumTargetType）时，event 的 source 和 medium 都是 **item 自身**（遗物/器官）
    `$triggerEffect.params(value)` 是引用"引发本次触发的 Effect 的参数"——注意是 Effect 不是 Event，两者的 params 结构可能不同
    引用别方对象后，别忘 `targetType` 语义变了——填给 doEvent 的 target 也换了，被它触发的下一层触发器（例如"这个流血是我的谁给的"）会看到新的 source/target

## 场景 5：condition 只在特定情况响应

目标
    「生命低于 30% 才触发」「持有某状态才响应」「第 N 回合才触发」「原伤害超过 10 才回血」——加一个前置条件过滤。

涉及机制
    triggers 里的 `condition` 字段（外层，触发器级别，整批 reaction 跳过）
    或 reaction event 里的 `condition` 字段（内层，只跳过某个 event）
    字符串表达式：`"目标.访问器(参数) 操作符 值"`
    支持的操作符：`== != > >= < <=`（**只有这 6 个**）
    右值：数字直接写；字符串字面量**不加引号**；`X%` 是百分比（对 current 有效）
    组合：数组默认 AND，或用 `{ or: [...] }` `{ and: [...] }` `{ not: "..." }`

数据模板：临危一击（生命 <= 30% 时打伤害 +50%）

```typescript
{
    label: "临危一击",
    describe: ["生命 <= 30% 时，造成伤害提升 50%"],
    key: "example_relic_desperate_strike",
    rarity: "rare",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "self" },
            triggers: [{
                when: "before",
                how: "make",
                key: "damage",
                action: "boostDamage",
                condition: "$owner.current(health) <= 30%"
            }]
        }
    },
    reaction: {
        boostDamage: [{
            targetType: "triggerEffect",
            key: "modifyDamage",
            effect: [{
                key: "modifyDamage",
                params: { value: "$triggerEffect.params(value) * 0.5" }
            }]
        }]
    }
}
```

常见变体
    第 N 回合才触发：`condition: "$battle.turn == 3"`
    持有某状态时才触发：`condition: "$owner.hasState(rage)"`（返回布尔）
    原伤害超过 10：`condition: "$triggerEffect.params(value) > 10"`
    多个条件 AND：`condition: ["...", "..."]`
    只在 combat 场景响应：`condition: "$scene == combat"`（右值 combat 不加引号）
    施加特定 category 状态时才触发（读 Effect 参数）：`condition: "$triggerEffect.stateCategory() == debuff"`
    只在药水对己作用时触发：`condition: "$medium.itemType() == potion"`

要点（condition 常见坑）
    **操作符只有 `==` `!=`**——写 `===` 会被识别失败，条件退化成"表达式为真"的布尔判定，几乎肯定错
    右值字符串**不加引号**：`== potion` 不是 `== "potion"`；加引号会把引号也参与比较，永远不匹配
    百分比只对 current 有意义：`<= 30%` 会自动换算成 `current.options.maxBy` 的 30%，不是 status 的百分比
    condition 放在 triggers 上就整批 reaction 都跳过，放在单条 event 上只跳过那一条——按语义选
    condition 里的 `$owner` = 触发器所有者；`$item` = 触发器所在的物品；`$source` `$medium` `$target` = **原事件**的三方；`$triggerEffect` = 引发本次触发的 Effect

## 场景 6：一场战斗只触发一次（disableUntil）

目标
    「战斗开始时 +3 力量（只发一次）」「本战首次受伤时回 8 血」——避免多次意外触发。

涉及机制
    triggers 里加 `disableUntil: "battleEnd"`
    触发一次后自动禁用，战斗结束后自动恢复
    与 condition 的区别：condition 是"这次不满足就跳过"，disableUntil 是"这次触发了就锁住"

数据模板：战前仪式（战斗开始 +3 力量，一场一次）

```typescript
{
    label: "战前仪式",
    describe: ["战斗开始时", "获得 3 层力量"],
    key: "original_relic_pre_battle_ritual",
    rarity: "uncommon",
    pool: ["common"],
    interaction: {
        possess: {
            target: { key: "owner" },
            triggers: [{
                when: "after",
                how: "take",
                key: "battleStart",
                disableUntil: "battleEnd",
                action: "gainPower3"
            }]
        }
    },
    reaction: {
        gainPower3: [{
            targetType: "owner",
            key: "applyPower",
            effect: [{ key: "applyState", params: { stateKey: "power", stacks: 3 } }]
        }]
    }
}
```

常见变体
    本战首次受伤才触发：`when: "after"`, `how: "take"`, `key: "damage"`, `disableUntil: "battleEnd"`
    每回合首次触发（不是一整场）：**不用 disableUntil**，改成累计触发（场景 7）用 `maxTriggerPerBattle` 或用 turn 计数
    永久用掉：需要专门 status 记录 usedKey，参考"过载电池"的 usedKey 用法

要点
    `battleStart` 事件如果不加 disableUntil，理论上不会重复（一场只有一次）——但**每回合触发的效果不能加 disableUntil**（那就锁死了），battleStart 才需要
    disableUntil 只支持 `"battleEnd"`，没有 `"turnEnd"` 这种

## 场景 7：累计 N 次才触发（accumulateAndTrigger）

目标
    「每受 10 点伤害回 1 血」「每打出 5 张牌抽 1 张」「一战最多触发 X 次」——数值型累计效果。

涉及机制
    不是 triggers + reaction 结构，而是在 `possess.effects` 里用 `accumulateAndTrigger` 效果
    参数
        `pointKey` — 记录累计的 status key
        `on` — 累计触发的事件（同 triggers 三轴写法）
        `gain` — 每次累计增加多少（数字或 `$` 表达式）
        `threshold` — 累计到多少触发
        `consume` — 触发一次消耗多少（数字或 `"all"`）
        `targetType` `effects` — 触发后做什么
        `minGain` — 一次累计的最小值（低于则不算，用于"受到超过 X 才算"）
        `usedKey` `maxTriggerPerBattle` — 一场战斗最多几次
        `repeat` — 累计一次爆表能不能连续触发多次（默认 true）
        `triggerTarget` — 触发挂到别的对象上（见场景 8）

数据模板：过载电池（受伤 10+ 才算、回 8 血、一战一次）

```typescript
{
    label: "过载电池",
    describe: ["每场战斗一次", "受到超过", { key: ["status", "minDamage"] }, "点伤害时", "回复", { key: ["status", "healAmount"] }, "生命"],
    key: "original_relic_overload_battery",
    rarity: "uncommon",
    pool: ["common"],
    status: {
        "point": 0,
        "used": 0,
        "maxUse": 1,
        "minDamage": 10,
        "healAmount": 8
    },
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "accumulateAndTrigger",
                params: {
                    pointKey: "point",
                    usedKey: "used",
                    on: { when: "after", how: "take", key: "damage" },
                    gain: "$triggerEffect.params(value)",
                    minGain: 10,
                    threshold: 1,
                    consume: "all",
                    repeat: false,
                    maxTriggerPerBattle: 1,
                    targetType: "owner",
                    effects: [{ key: "heal", params: { value: 8 } }]
                }
            }]
        }
    }
}
```

数据模板：学者笔记（每打 5 张牌抽 1 张）

```typescript
possess: {
    target: { key: "owner" },
    effects: [{
        key: "accumulateAndTrigger",
        params: {
            pointKey: "point",
            on: { when: "after", how: "make", key: "useCard" },
            gain: 1,
            threshold: 5,
            consume: 5,
            targetType: "owner",
            effects: [{ key: "drawFromDrawPile", params: { value: 1 } }]
        }
    }]
}
```

常见变体
    伤害类累计：`gain: "$triggerEffect.params(value)"`（拿这次伤害数值）
    次数类累计（每 X 次）：`gain: 1`
    每次爆表只触发一次：`repeat: false`（默认 true，"一次伤害 30 点 + threshold 10"会触发 3 次）
    一战限次：加 `usedKey` 和 `maxTriggerPerBattle`
    加计数徽章：在遗物顶层加 `badges: [{ type: "counter", status: "point", maxStatus: "maxPoint" }]`

要点
    `pointKey` `usedKey` 需要**在 status 里预先声明**（`status: { "point": 0, "used": 0 }`），不然读不到
    `consume: "all"` = 触发一次直接清零；`consume: 5` = 减 5，剩余留下；配合 `repeat: true` 可以"一次输入触发多次"
    accumulateAndTrigger 内部自己挂 triggers，你**不用**再写 triggers/reaction
    如果监听的事件三方特殊（比如敌人身上的印记响应玩家伤害），配合 `triggerTarget` 见场景 8

## 场景 8：触发器挂到别的对象（triggerTarget）

目标
    「敌人身上的印记，效果是对手每受 8 点伤害就回 2 血」——触发器不挂在自己身上，而是挂在对手身上。

涉及机制
    accumulateAndTrigger 或 triggers 里加 `triggerTarget` 字段
    值可以是 `"allOpponents"` `"randomEnemy"` 等，或指定 Entity
    真实内部逻辑：把触发器挂到 triggerTarget 指定的对象身上，所以监听的是**那个对象**发起/承受的事件

数据模板：寄生菌根（敌人器官，对手每累计受 8 伤，回本敌人 2 血）

```typescript
{
    label: "寄生菌根",
    key: "enemy_organ_parasitic_root",
    describe: ["对手每累计受到 8 点伤害，回复 2 点生命"],
    rarity: OrganRarity.Uncommon,
    part: OrganPartEnum.Nerve,
    status: { "max-mass": 40, "lifeDrainAccum": 0 },
    current: ["mass"],
    interaction: {
        possess: {
            target: { key: "owner" },
            effects: [{
                key: "accumulateAndTrigger",
                params: {
                    pointKey: "lifeDrainAccum",
                    on: { when: "after", how: "take", key: "damage" },
                    triggerTarget: "allOpponents",
                    gain: "$triggerEffect.params(value)",
                    threshold: 8,
                    consume: 8,
                    targetType: "owner",
                    effects: [{ key: "heal", params: { value: 2 } }]
                }
            }]
        }
    }
}
```

常见变体
    每次任意敌人受伤都算：`triggerTarget: "allOpponents"`（多敌人时共享一份计数）
    只有特定敌人身上装了这个印记时才算他自己：默认（不填 triggerTarget，挂在 self 上）
    随机敌人：`triggerTarget: "randomEnemy"`

要点
    `triggerTarget` 改变的是**监听方**，`targetType` 改变的是**响应方**——两者独立
    如果没有 triggerTarget，累计触发默认挂在**器官/遗物的 owner** 上——也就是"我自己"
    accumulateAndTrigger + triggerTarget: allOpponents，实现"我影响所有对手，但结算落到我"——常用于敌人器官对玩家的反馈机制

## 场景 9：命令式底层写法（appendTrigger 兜底）

目标
    「声明式 triggers + reaction 不够用，需要在触发时读取运行时状态做复杂判断」——极少数场景才用。

涉及机制
    `entity.trigger.appendTrigger({...})` 直接注册回调
    `callback(event, effect, triggerLevel)` 参数：原事件、原效果、触发级别
    返回 `{ remove, id }`，`remove()` 卸载
    可以在 callback 里直接改 `event.effects[0].params`（before 阶段）或发起新事件（`doEvent(...)`）

数据模板：受伤时按当前手牌数减免伤害

```typescript
// 在某 Entity 初始化时（不是数据里，是运行时代码）
const { remove } = player.trigger.appendTrigger({
    when: "before",
    how: "take",
    key: "damage",
    callback: (event, effect, triggerLevel) => {
        const handCount = player.cardPiles.handPile.length
        const reduce = Math.min(handCount, 5)
        effect.params.value = Math.max(0, effect.params.value - reduce)
    },
    level: 0
})

// 想卸载时
remove()
```

要点
    **数据里能写声明式就别写命令式**——命令式版本不进 Mod 数据、Vue 响应式追踪不到、Log 会缺少 action 名字，是最后的兜底
    命令式的适用场景：需要访问一个 accessor 里没有的运行时数据（比如 handPile 长度可以走 `pileCount(hand)` accessor，但如果有更奇怪的判断就命令式）
    命令式改 `effect.params` 直接生效，不走 modifyDamage 那种专用 EffectFunc——这也是它的风险，改错了没有 Log 追溯

## 附录 A：常见事件的三方与推荐 how

| 事件 key | source | medium | target | 常用 how |
|---|---|---|---|---|
| turnStart / turnEnd | 玩家自己 | 玩家自己 | 玩家自己 | make（惯例） |
| battleStart / battleEnd | 玩家自己 | 玩家自己 | 玩家自己 | make / take 均可 |
| roomEnter | 玩家 | 玩家 | 玩家 | make / take 均可（惯例 make） |
| damage | 攻击方 | 卡牌/器官 | 受击方 | make / take |
| heal | 治疗方 | 卡牌/道具 | 被治疗方 | make / take |
| applyState | 施加方 | 卡牌/道具 | 被施加方 | make / via / take |
| drawCard | 玩家 | - | 卡牌 | make（玩家做的动作） |
| discard | 触发者 | 玩家 | 卡牌数组 | via（响应"哪些卡被弃"） |
| retain | 玩家 | 玩家 | 保留的卡数组 | via（响应"哪些卡被保留"）；仅由 discardHandOnTurnEnd 发起 |
| useCard | 玩家 | 卡牌 | 目标 | make / via（响应打出者/卡本身） |
| useItem | 使用者 | 物品 | 被作用对象 | make / take |
| organLose | 拥有者 | 器官 | 拥有者 | make / take |
| breakOrgan | 拥有者 | 被摧毁的器官 | 拥有者（或 break 交互配的 target） | make / take |
| gainEnergy | 玩家 | 玩家 | 玩家 | take |
| loseEnergy | 玩家 | 玩家 | 玩家 | take（覆盖打牌/主动能力/直接扣能量所有路径） |
| refillEnergy / emptyEnergy | 玩家 | 玩家 | 玩家 | take |
| payEnergy | 玩家 | 卡牌/物品 | 玩家 | 一般不监听，用 loseEnergy 更完整 |

当三方都是同一个对象（turnStart/battleStart）时，make/via/take 三种 how 都能命中——**惯例用 make**，保持数据风格一致。

## 附录 B：常见坑速查

    condition 用 `===`：不识别，静默失效 → 用 `==`
    condition 右值字符串加引号：`== "potion"` 永远不匹配 → 写 `== potion`
    `action` 名字写错：触发器像哑弹一样静默不响应 → 检查 reaction 里 key 拼写
    忘了 `key` 字段：reaction event 缺 key 会报错 → 每个 event 都要有 key
    `after` 想改 params：来不及了，改了没用 → 改 params 用 `before`
    disableUntil 用在每回合触发上：锁死变成一场只触发一次 → 每回合触发的**不要**加 disableUntil
    accumulateAndTrigger 忘声明 pointKey / usedKey 到 status：读不到，累计无效 → status 里预设为 0
    triggerTarget 混同 targetType：前者是"监听谁"，后者是"响应给谁" → 两者独立
    多 reaction event 依赖顺序：event 是顺序执行，靠前的 event 里改的状态在后面可见——但**级联触发**在中间可能插进来，别过度依赖
    命令式 callback 改 event.effects：before 阶段还能改，after 阶段改了没意义 → after 想做事请发新事件
    想过滤 debuff/buff 类型的施加：走 accessor `$triggerEffect.stateCategory() == debuff`，别在 EffectFunc 里命令式 `stateList.find`
