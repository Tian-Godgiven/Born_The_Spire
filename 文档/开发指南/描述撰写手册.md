# 描述撰写手册

写给加内容、改文案的人。遗物整理时沉淀，卡牌 / 器官 / 事件 / 药水同一套约定。

本手册答「玩家看见的那句话怎么写」。浮层怎么挂、卡名怎么解析，见文末相关文档。

---

## 谁看见哪一段

`effect` 是效果正文。悬停、列表、商店始终显示它。

`describe` 是可选风味。只有同时写了 `effect` 和 `describe` 时，才出现在详情弹窗里、效果下面。

没写 `effect` 的旧数据：`getEffectDescribe` 会把 `describe` 当效果。新内容把机制写进 `effect`。

器官被动写在 `effect`。提供卡那一句由引擎按 `cards` 生成，不要手写「提供 1 张 `{ "@": 0 }`」。

药水写 `effect`，悬停走 `DescribeText`（现行：`Potion.vue`）。数值用 `{ key: ["status", "xxx"] }`，术语打 `$`。

渲染统一走 `DescribeText`（遗物用 `RelicHoverContent`）。不要自己 `Teleport` + 手算坐标。

---

## 效果正文

只写机制。短句，能一行就一行。玩家悬停要立刻知道「现在会怎样」。

进度写进正文，用 `{ key: ["status", "xxx"] }` 读当前值。角标只是辅助，不要只藏在角标里。

```typescript
effect: [
    "每累计受到（", { key: ["status", "point"] }, "/", { key: ["status", "maxPoint"] }, "）点未被格挡的伤害，回复1生命",
    "<br>",
    "触发（", { key: ["status", "used"] }, "/", { key: ["status", "maxUse"] }, "）次后转变为",
    { relic: "original_relic_blood_donor_cert" }
]
```

现行：献血徽章。

换行必须是单独一段 `"<br>"`。字符串里的 `\n` 不会断行（命运之轮曾踩过）。

选择界面、弹窗里已经列出的选项，不要再抄进 `effect` 或 `describe`。现行：预言之骰只写「战斗开始时从 4 个预言中选择 1 个立即生效」。

机制还没落地的内容先停用、不注册，不要编一套假说明撑场面。现行：血偿棱镜（器官血量未做）。

## 风味

只写气氛，不复述机制。现行：口香糖 `describe: ["伸缩自如的爱❤️"]`，小兽伙伴 `describe: ["一只跟着你走的肮脏小兽"]`。

没有值得说的风味就别写 `describe`。悬停不会因此变空，因为走的是 `effect`。

---

## 术语 `{$:"…"}`

玩家需要解释的词打 `$`。悬停锚点出术语板，说明只写一份。

```
状态          写在 stateList 该条的 describe；`{$:"力量"}` / `{$:"虚弱"}` 都能命中
词条          写在 CardEntry / OrganEntry 的 describe
没有注册表的名词  写 glossaryMap（护甲、格挡）
一次性名词      用 extraGlossaries 传入 { label, describe }
```

`{$:"临时"}` 是状态：回合结束失去层数。现行：热血腰带「每回合开始时获得3层临时力量」。

`{$:"临时器官"}` 是器官：战斗结束消失。现行：鹫发「你的非临时器官被摧毁时…」。

不要混用。不要把同一段说明再抄进 glossaryMap。

---

## 点名卡、器官、遗物

按「玩家能不能摸到那张实体」选占位符。

```
{ "#": "cardKey" }              按 key 出临时卡面，不绑牌组。现行：饥饿之种塞寄生
{ "@": 索引或实例id }           已经在牌组里、或器官即将提供的那张
{ markedCard: "storeKey" }      遗物 status 里记下的那张。未选显示「一张牌」，选完才变成可预览。现行：口香糖
{ organ: "organKey" }           按 key 预览器官
{ relic: "relicKey" }           按 key 预览遗物。现行：献血徽章变成献血证
```

遗物选中的运行时实例不要手写 `"@"`，用 `{ markedCard }`。

卡组反标（`chooseAndMarkCard` 的 `markRelics`）只在卡组悬停那张牌时弹出遗物，不要改卡面正文。现行：口香糖。

饥饿之种那种「获得时塞一张固定卡」用 `#`，不必和卡组联动。

## 进度写成（已完成 / 上限）

Describe 不能做减法。跨战斗场数用向上累的 `battles-done` / `maxBattles`，正文写成 `接下来（0/3）场战斗…`。现行：无常之神的祝福、浅尝辄止、孵化中的胚胎。

不要倒计时 `battles-remaining`（「还剩 N 场」）。那会逼着描述做减法，也和角标对不上。

计数机制用 `incrementStatus` 改原始基础值，不要用 `addStatusBase`（那是修饰器，战斗结束会清）。失效拆成另一条 trigger。写法见遗物场景 13。

## 按阈值追加的行：`effectTiers`

好感度、层数到了才出现的效果，不要一上来把整棵树写进 `effect`。

```typescript
effect: [
    "战斗结束时，小兽伙伴会渴望一份战利品（🐕），你可以不领取该战利品以喂食给它。喂食将提供小兽伙伴的好感度。"
],
effectTiers: [
    { statusKey: "hungry-beast-favor", min: 3, describe: ["陪睡：每次休息治疗额外 +10 HP"] },
    { statusKey: "hungry-beast-favor", min: 6, describe: ["共战：每回合结束对随机敌人造成 5 伤害"] },
    { statusKey: "hungry-beast-favor", min: 9, describe: ["挡刀：替你挡下一次致命伤并留 1 点生命，随后该遗物失效"] }
],
describe: ["一只跟着你走的肮脏小兽"]
```

现行：小兽伙伴。`min` 达标才拼进 hover / 列表，每档一行。没达标的档位不出现。

一次性打完就失效的，正文写清「随后该遗物失效」。`disabled` 要在每条 trigger（以及命令式拦截器回调）上自己短路，栏位变灰看 `status.disabled`。

## 现行对照

献血徽章
    进度（point / maxPoint）（used / maxUse）写进 effect，转变目标用 `{ relic }`

口香糖
    `{ markedCard }`；风味单独一条；卡面不改

饥饿之种
    `{ "#": "original_card_parasite" }` 预览寄生

预言之骰
    只写「从 4 个预言中选 1 个」，选项不进 describe

无常之神的祝福 / 浅尝辄止
    `接下来（battles-done / maxBattles）场战斗…`

热血腰带
    `{$:"临时"}` + `{$:"力量"}`

鹫发
    `{$:"临时器官"}`

小兽伙伴
    effect 只讲喂食；档位走 effectTiers；风味走 describe

命运之轮
    奇数 / 偶数两段用 `"<br>"` 分开

## 常见坑

`\n` 当换行
    必须写 `"<br>"`

`$` 表达式夹算术
    必须整段是 `$xxx(...)`。`" $triggerEffect.params(amount) * 0.25"` 整句进不了解析。百分比走 effect 自己的参数。

访问器没有括号
    `$target.status(drawThreshold)` 对；`$target.status.drawThreshold` 错。

进度倒着数
    正文用（已完成 / 上限），机制用 `incrementStatus`。

把遗物说明拼进卡面
    口香糖那种反标只在卡组悬停弹出，卡面描述本身不变。

把未解锁档位写进 effect
    用 `effectTiers`。

风味里再列一遍机制
    详情会重复；选择界面有的更不要抄。

硬编码会变的数字
    用 `{ key: ["status", "xxx"] }`，和 status 字段名一致。
