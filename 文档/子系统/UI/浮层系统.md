# 浮层系统

贴着界面「看一眼」的说明——卡名预览、器官介绍、术语板、意图、商品说明——都由 `Popover` 承载。它不是弹窗：不抢操作、不 `await`、没有 `showPopover()`。不要自己写 Teleport + `getBoundingClientRect` + `setTimeout`。

组件：`src/ui/components/global/Popover.vue`
常量与宿主查询：`src/ui/hooks/interaction/popoverHost.ts`

检视卡牌、等玩家选择、功能页（卡组/设置）见文末「游戏弹窗三条路」，那些不是 Popover。

## 作者怎么用

你要用的是我们已经做好的说明，不是自己去 import `Popover`。做法是：数据里打标，界面上用 `DescribeText` 渲染这段描述。卡名预览和术语板都绑在 `DescribeText` 上，不要在外面再挂一块 `GlossaryPanel`。

卡牌、器官、遗物的 `describe` 里这样写：

```typescript
describe: [
    "造成", { key: ["status", "damage"] }, "点伤害，使目标获得2层", {$:"易伤"}
]
```

`{$:"易伤"}` 是术语。悬停这段描述的锚点（卡面是整张卡，器官介绍是介绍框，默认是 `DescribeText` 的父节点），右侧出现术语板，内容和状态「易伤」的 `describe` 相同。不是单独点「易伤」两个字才出。

`{"#": "original_card_00001"}` 或 `{"@": 0}` 是卡名。悬停卡名出卡面，点击打开锻造对照。

词条写在 `entry` 里（如 `"card_exhaust"`）。卡面上会画出「消耗」标签，正文里不必再写一遍。调用方把词条 key 传给 `DescribeText` 的 `extraGlossaries`，术语板里就会有它。卡面、器官介绍已经这么接了。不要让 `DescribeText` 自己去翻 `target.entry`。

术语说明只写一份：

```
状态     写在 stateList 该条的 describe；卡面上 {$:"易伤"} 或 {$:"vulnerable"} 都能命中
词条     写在 CardEntry / OrganEntry 的 describe
护甲、格挡这类没有自己注册表的名词     写 glossaryMap，或 registerGlossary
一次性、没有注册表的名词     用 extraGlossaries 传入 { label, describe }
```

新状态：注册进 `stateList`（或你们的状态注册 API），`describe` 里标 `$`。不要把同一段说明再抄进 `glossaryMap`。

自己的界面上要显示一段别人的 `describe`（事件文本里引用某张卡、某个术语）时，用 `DescribeText`，不要自己拆。卡名会带上现成的卡面预览；`$` 会带下划线，悬停锚点会出术语板。需要把词条或一次性名词也放进板上，传 `extraGlossaries`。默认锚点是这段文字的父节点；想让整张卡、整个介绍框都能唤出术语板，把那个节点传给 `glossaryAnchor`。

遗物栏、药水、黑市目前还用 `getDescribe` 铺成纯文字，还没有术语板。要接上就改成 `DescribeText`。

只有说明对象是你自己画的新东西（试剂瓶、特殊按钮），核心没有对应组件，才自己写 `Popover`，见下方「例子」后半。

## 例子

你做了一张会出现在手里的牌，希望「易伤」和我们的牌一样能出术语板。只改数据：

```typescript
{
    label: "破甲打击",
    key: "mod_card_sunder",
    describe: ["造成", { key: ["status", "damage"] }, "点伤害，施加2层", {$:"易伤"}],
    status: { damage: 8, cost: 1 },
    interaction: {
        use: {
            target: { faction: "opponent" },
            effects: [
                { key: "attack", params: { value: "$medium.status(damage)" } },
                { key: "applyState", params: { stateKey: "vulnerable", stacks: 2 } }
            ]
        }
    }
}
```

注册进卡牌列表之后，玩家悬停这张卡，术语板会列出易伤。`$` 去 `stateList` 里找，说明不用你再写一遍。

只有你自己画了一块界面，上面的东西核心没有现成浮层（事件页上的试剂瓶），才自己写 `Popover`。事件配了 `component: LabEvent.vue`：

```vue
<script setup>
import Popover from "@/ui/components/global/Popover.vue"
</script>

<template>
<div class="lab">
    <Popover placement="bottom">
        <div class="vial">试剂瓶</div>
        <template #content>
            <div class="tip">悬停时看到的话，白底黑框自己画</div>
        </template>
    </Popover>
</div>
</template>

<style scoped>
.vial { border: 2px solid #000; padding: 8px; cursor: default; }
.tip { background: #fff; border: 2px solid #000; padding: 8px; }
</style>
```

玩家进这个事件房间，才会看到瓶子；指针放上去，旁边出现 `.tip`。这就是 `Popover` 的用法：触发区在默认插槽，说明在 `#content`。

如果说明文字来自器官/遗物的 `describe`，把 `#content` 换成 `<DescribeText :describe="..." :target="..." />`，卡名和术语板都不用你再包一层。

## 最小用法

默认悬停触发。默认插槽是触发区，`#content` 是浮层内容。import 路径和上面例子相同。

浮层会被 Teleport 出去，外层的 `overflow: hidden` / `transform` 裁不到它。指针可以移进浮层里点东西（例如点卡名）。

## 属性

```typescript
trigger?: "hover" | "click" | "manual"   // 默认 hover；click 会点外部关闭；manual 只听 show
placement?: "left" | "right" | "top" | "bottom"   // 默认 right，放不下自动翻到对面
align?: "start" | "center" | "trigger" | number   // 交叉轴对齐，横向默认 start、纵向默认 center
offset?: number          // 与基准的间距，默认 8
openDelay?: number       // 指针停多久才弹出；不传用全局 `$popover-hover-open-delay`（现在 0.4s）
closeDelay?: number      // 指针离开后延迟关闭的毫秒数，默认 200
anchor?: HTMLElement | null          // 定位基准，不传见下方「定位基准怎么选」
triggerElement?: HTMLElement | null  // 改用外部元素当触发区
disabled?: boolean       // 置为 true 会立刻收起；转回 false 时指针若还在触发区会自动补上
maxWidth?: number        // 内容最大宽度，默认 300
inline?: boolean         // 触发区嵌在文字流里时打开
show?: boolean           // manual 模式的开关
order?: number           // 同一锚点、同一侧的外侧序号，见下方「同一锚点排队」
```

作用域插槽给了 `open` / `close` / `toggle` / `shown`，`defineExpose` 也暴露同一组，需要外部控制时用 ref 拿。

## 定位基准怎么选

不传 `anchor` 时按这个顺序取基准：

```
触发区在另一个浮层里     以那个外层浮层为基准，新浮层落在它外侧
否则                    以触发区自身为基准
```

第一条是治「器官介绍里的卡名闪烁」的关键：卡名浮层如果贴着卡名本身弹，会盖住卡名，指针一动就 leave→enter→leave 来回抖。改成贴着整个介绍面板的外边缘弹，浮层永远不会压住触发它的文字。

器官提供的卡牌默认 `placement="bottom"`，贴在介绍面板下方。右边经常不够摆下一张完整卡面。想让它横向跟着卡名那一行，加 `align="trigger"`。下方也放不下时 Popover 会翻到上方。介绍和角色状态并排装在同一块浮层里时，卡名预览必须把 `anchor` 指到介绍框（`DescribeText` 的 `glossaryAnchor`），不能以外层整块为基准，否则会被旁边更高的状态栏顶下去。

卡面术语板也要加 `align="trigger"`。卡名预览向下弹时，外层浮层顶部有 8px 间隙 padding；术语板默认会以外层顶边对齐，看起来比卡面高一截。`align="trigger"` 交叉轴跟卡面对齐。不要给术语板加 `margin-top`：向下弹看起来齐了，向上弹会整块被推下去。以前并排画在同一层内容里之所以没有这个问题，是因为术语板和卡面共用内层、不吃那 8px padding。

`anchor` 显式传元素的场景：一个浮层被多处共用（黑市商品说明），或者触发区尺寸不适合当基准。

## 同一锚点排队

同一锚点、同一侧的已显示浮层按 `order` 往外排。数字小的贴着锚点，大的在更外侧。朝右是 `0 → 1 → 2`，外层翻到左边时 `0` 仍贴着方块。指针落在同一排任一浮层上，最内侧那层不会关。

一块内容里的几列（器官介绍 + 里程碑、介绍 + 角色状态）仍装在同一个 `#content` 里用 flex，不要为此拆成两个 Popover。空间不够、要靠悬停才出介绍时用 `OrganHoverContent`（介绍 + 可选里程碑）。选器官网格、洗涤、战斗角色悬停走这一套；战斗默认不带里程碑，除非该器官写了 `upgrade.combatUpgrade`。战利品选择器官空间够，介绍常驻在卡片上，悬停只出里程碑。朝右弹时 DOM 顺序就是阅读顺序：先介绍、后里程碑。朝左弹时给 `OrganHoverContent` 传 `reverse`，让介绍仍贴着触发它的方块。初始选器官的网格在屏幕左侧，就是为了给右侧的介绍和里程碑留空。

要再往这同一侧接一块、但又不是常驻内容时，另开一个 Popover，写更大的 `order`。嵌套浮层写了 `order` 就会加入外层那一排，不再单独贴着外层浮层的外边缘。

器官介绍里的 `DescribeText` 就是这样：`glossaryAnchor` 指到介绍框，`glossaryOrder={1}`，悬停介绍框才出术语板，排在里程碑外侧。介绍正文里的 `$` 和 `extraGlossaries`（词条）进这块板。里程碑列自己的 `DescribeText` 只解释该列的 `$`，悬停那一列才出。卡名预览、卡面术语板不要写 `order`，它们要贴着自己那层的外边缘，不能挤进器官这一排。卡面把 `glossaryAlign` 设成 `"trigger"`，避免卡名预览向下弹时吃外层 8px 间隙。

术语板始终悬停才出，不要并排常驻。手牌悬停卡面、器官悬停介绍框、卡名预览里再悬停那张卡，都走这一套。卡名预览只出卡面，器官悬停只出介绍（和里程碑）。

## 三种触发模式

hover 是默认。出现要等指针停满 `$popover-hover-open-delay`（`src/ui/styles/_variables.scss`，现在 0.4s），划过触发区不会弹。已经显示之后，指针在触发区和浮层之间移动不再等这段时间。离开后仍用 `closeDelay`（默认 200ms），指针可以移进浮层里点东西。

click 用于要留驻的菜单，点浮层外部自动关。

manual 用于「一个浮层多处触发」或「开关由业务状态决定」，此时必须自己维护 `show` 和 `anchor`：

```vue
<Popover inline trigger="manual" :show="tooltipVisible" :anchor="tooltipAnchor" placement="bottom" align="start">
    <template #content>
        <div @mouseenter="cancelHide" @mouseleave="startHide">…</div>
    </template>
</Popover>
```

manual 模式下 Popover 不接管指针，浮层自身的「移进来别关」要自己在内容上挂 `mouseenter` / `mouseleave`。

## triggerElement：不想被包一层的时候

`Popover` 默认会给触发区套一个包裹 div。卡牌、遗物、药水这类本身有尺寸和布局行为的东西，被套一层会在 flex 里变成另一个盒子，把手牌区挤乱。这时把浮层单独声明、用 `triggerElement` 指过去：

```vue
<div class="vial" ref="vialRef">试剂瓶</div>

<Popover inline :trigger-element="vialRef" placement="right">
    <template #content>
        <div class="tip">悬停整瓶时看到的话</div>
    </template>
</Popover>
```

悬停监听会直接挂到那个元素上，包裹层只留作 Teleport 宿主查询用。术语板不要再用这一套自己挂，交给 `DescribeText` 的 `glossaryAnchor`。

## 描述文本里的卡牌与术语

不要自己遍历 `getDescribeStructured` 再手写 hover，也不要在外面再挂 `GlossaryPanel`。用 `DescribeText`：卡牌片段交给 `CardRefText`（内部就是一个 `Popover`），`$` 和 `extraGlossaries` 组成术语板。悬停卡名出卡面，点击打开 `showCardDetail` 详情弹窗（可对照锻造）。悬停锚点出术语板。

```vue
<DescribeText :describe="organ.describe" :target="organ" />
```

卡面、器官介绍会把锚点指到更大的一块：

```vue
<DescribeText
    :describe="describeToShow"
    :target="card"
    :glossary-anchor="cardRef"
    glossary-align="trigger"
    :extra-glossaries="entries"
/>
```

```typescript
describe?: Describe        // 结构化描述
target?: object            // 求值上下文；带 cards / cardsByOwner 时同时作为卡牌解析的器官上下文
bracketCards?: boolean     // 卡名加【】，用于器官详情这类需要强调的地方
hoverTarget?: Entity | Entity[]   // 传给卡面做数值预览
preferPlayerCards?: boolean       // 器官同时有敌人版和玩家版卡牌时优先预览玩家版
glossaryAnchor?: "parent" | "self" | HTMLElement
                              // 术语板触发区。默认 parent（这段文字的父节点）
                              // self 是文字根节点；传入节点则整块区域都能唤出
glossaryPlacement?: "left" | "right" | "top" | "bottom"   // 默认 right
glossaryAlign?: "start" | "center" | "trigger" | number      // 卡面用 trigger
glossaryOrder?: number        // 同一锚点排队。器官介绍用 1，卡面不要写
glossaryDisabled?: boolean    // 卡面禁用时关掉术语板
extraGlossaries?: Array<string | { label: string, describe: Describe }>
                              // 词条 key，或没有注册表的一次性名词。extra 在前，$ 在后
```

`preferPlayerCards` 目前只有奖励界面用：玩家在奖励里看到的应该是拿到手之后的那张，不是敌人身上那张。

板上的顺序：`extraGlossaries` 先，这段 `describe` 里的 `$` 后。解析不到的 key 不占空行。可见的词条标签仍由调用方自己画，不要把标签并进 describe 正文。

## 层级

层级写整档数字，不要 `10000 - 1` 这种减法。常量都在 `popoverHost.ts`，z-index 写在元素 `style` 上，不要只写在 scoped CSS 里。

```
11000  开发者控制台         DEV_CONSOLE_Z_INDEX
10000  悬停说明 Popover     POPOVER_Z_INDEX
9999   检视 showPopUp       SHOW_POPUP_Z_INDEX
9500   战斗飞牌             CARD_FLIGHT_Z_INDEX
8999   选择 showComponent   SHOW_COMPONENT_Z_INDEX
```

悬停必须盖过检视，所以比 9999 再高一档到 10000。其它游戏弹窗不超过检视（≤9999）。不要为了压过某个弹窗把 Popover 临时调大。弹窗里的卡面、术语板仍是 Popover，会盖在弹窗上面。开发者控制台 11000，盖过飞牌，避免抽牌动画挡命令。

## 游戏弹窗三条路

不必把所有挡住画面的东西都塞进 `showPopUp`。先看它是哪一类：

```
检视一件东西     showPopUp          居中、可叠层、打开时收掉悬停浮层
等玩家选完再继续 showComponent       一次一块，Promise 等到选完
功能界面         自己画 overlay     卡组、设置、地图、战利品、器官大图
```

共同约定只有层级：自己的壳 ≤9999，需要的话 Teleport 到 `body`。Mod 和核心同一套。

### 检视：showPopUp

看一张卡、一件遗物、一摞牌。容器 `PopUpContainer` 用 `SHOW_POPUP_Z_INDEX`。打开时 `dismissAllPopovers()`，避免卡名预览盖住弹窗。

```typescript
import { showPopUp, closePopUp } from "@/ui/hooks/global/popUp"
import { shallowRef } from "vue"
import MyPopup from "./MyPopup.vue"

showPopUp({
    mask: true,
    vue: shallowRef(MyPopup),
    props: { /* 组件里用 props.props 接 */ }
})
```

组件收到 `popUp` 和 `props`。关掉用 `closePopUp(popUp)`。可以叠：牌堆上再开卡牌详情，关上面那层回到牌堆。

卡牌详情不必自己组壳，调 `showCardDetail(card)`（`src/ui/hooks/interaction/cardDetail.ts`）。未锻造默认不勾「显示锻造后的卡牌」，勾上预览 +1；已经锻造过则默认勾上，取消勾选看 0 级。预览用临时牌，不改手里那张。

### 等选择：showComponent

选卡、洗涤升级、事件里「选完才往下走」。同时只显示一块，新的会顶掉旧的。容器 `DynamicComponentContainer`，用 `SHOW_COMPONENT_Z_INDEX`，Teleport 到 `body`。比检视低，升级界面点卡名时 `showCardDetail` 能盖在上面。

```typescript
import { showComponent, registerComponent } from "@/core/hooks/componentManager"

registerComponent("myChoice", MyChoiceVue)   // Mod 先注册，之后可以用名字

const result = await showComponent({
    component: "myChoice",   // 或直接传组件对象
    data: { /* 作为 props 传给组件 */ },
    layout: "modal"          // fullscreen | modal | inline
})
```

组件 `$emit("complete", result)` 或调 `closeComponent(result)`；取消走 `cancel` / `cancelComponent`。现成例子：`showCardChoice`（`src/ui/hooks/interaction/cardChoice.ts`）。

### 功能界面：自己画

卡组网格、设置、地图、战利品、器官详情这种有自己宽高和按钮栏的，不要塞进 `showPopUp` 那个全屏居中壳。核心里 `CardGroupModal`、`OrganDetail`、`SettingsModal` 都是自己的 overlay。Mod 同样可以。

只要 z-index ≤ 9999。里面的说明框仍用 `Popover`，不要再手写一套悬停定位。需要从功能界面里检视一张卡，调 `showCardDetail`，它会叠在你的界面上面。

## 踩过的坑

间距不能留空。触发区和浮层之间那段 `offset` 做成了浮层自己的 padding，指针横穿间隙时始终落在浮层内；如果改成真的留白，指针中途会落空，浮层被判定为「指针离开」而关掉。

首帧必须先隐藏。浮层要先渲染出来才能量到尺寸，量完才知道摆哪。所以没测到位置前 `visibility: hidden`，否则会先在原点画一帧再跳过去。

内容异步变化要重新收边。卡牌是异步解析的，词条数量也会变，所以浮层上挂了 ResizeObserver，尺寸一变就重新贴一次。自己写内容时不用管，但别在浮层里做会改尺寸又不触发 resize 的事（比如只改 transform）。

继承样式会漏进来。浮层内容虽然 Teleport 走了，但 scoped 样式和 `font-size` / `white-space` 这类可继承属性来自声明它的组件。意图浮层就因为外层为小徽章设了 `font-size: 12px; white-space: nowrap`，导致里面的卡牌字变小且不换行——在内容根节点上显式重置回去。卡面 `.describe` 自己也要允许断行（`overflow-wrap: anywhere`），斜杠连在一起的长句（如不稳定充能）否则会在 130px 卡里顶出横向滚动条。
