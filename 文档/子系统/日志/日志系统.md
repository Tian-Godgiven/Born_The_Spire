# 日志系统 Log

日志系统记录事件与操作，在 UI 右侧 LogPane 面板呈现给玩家和开发者。核心设计：**默认无需手写日志**，事件系统和修饰器已在关键位置自动记录；嵌套结构自动反映事件调用层级。

源文件：
    核心：`src/ui/hooks/global/log.ts`
    错误弹窗（姊妹 API）：`src/ui/hooks/global/alert.ts`
    ActionEvent 的日志方法：`src/core/objects/system/ActionEvent.ts` (`addChildLog`)
    UI 面板：`src/ui/components/display/LogPane.vue`

## LogUnit 结构

```typescript
type LogUnit = {
    text:      string          // 主内容，日志栏直接显示
    detail:    string          // 详情，点击"展开详情"后显示
    time:      number          // 时间戳
    children?: LogUnit[]       // 子日志
    level?:    number          // 缩进层级（0 = 顶层）
}
```

`logList: Ref<LogUnit[]>` 是全局响应式导出，UI 侧 LogPane 直接 v-for 渲染。

## 主 API

```typescript
newLog(logData: LogData | any[], parent?: LogUnit) → LogUnit
```

两种签名：

```typescript
// 数组式：主内容片段列表
newLog(["玩家", player, "受到", damage, "点伤害"])

// LogData 式：分别指定 main / detail
newLog({
    main:   ["玩家抽牌", card],
    detail: ["从抽牌堆", "数量: 3"]
})
```

**返回 LogUnit 是关键设计**——想嵌入子日志就保留返回值，二次调用传 parent：

```typescript
const parent = newLog(["失去器官", organ])
newLog(["移除触发器: damage"], parent)
newLog(["移除修饰器: 防御+2"], parent)
```

子日志自动：加入 `parent.children`、`level = parent.level + 1`、UI 缩进展示。

## 数据格式化 handleLogData

`newLog` 内部按类型转字符串：

```
null            → "无(null)"
undefined       → "未定义(undefined)"
空字符串         → "空内容"
带 label 或 key  → 用 label 优先，其次 key         ← Entity 走这里
Array           → 递归处理，逗号拼接
string / number → 直接 toString
boolean         → "成功(true)" / "失败(false)"
其他对象         → "<无法识别对象>"
```

对 Entity 传对象引用即可，格式化会读 `label` 或 `key`。

## ActionEvent.addChildLog

```typescript
event.addChildLog(logData) → LogUnit
```

自动挂到该事件已生成的 `logUnit` 下；若事件尚未生成 logUnit，退化为顶层日志。用于效果/子事件内部追加日志。

## newError 姊妹 API

`newError(info: (string | Object | undefined)[]) → never` 打红色错误弹窗，用于开发期报错。写法与 `newLog(array)` 一致，但会中断执行流。

```typescript
newError(["尝试在", entity, "上获取当前值", key, "但不存在。"])
```

## 系统自动日志覆盖点

**你在写自定义 effect 时不需要手动加日志**——以下位置系统已自动记录：

```
ActionEvent.happen()          发生事件 [eventKey]
applyEffect() (2 处)          造成效果 + 执行效果（带返回结果）
OrganModifier.acquireOrgan    parentLog: [owner] 获得了器官 [organ]
OrganModifier.loseOrgan       parentLog: [owner] 失去了器官 [organ]（下挂副作用清理）
OrganModifier.useOrgan        使用了器官 [organ] / 错误提示
OrganModifier.breakOrgan      [organ] 已损坏
OrganModifier.repairOrgan     [organ] 已修复
ItemModifierUnit.cleanup      挂在 parentLog 下的所有触发器/修饰器移除记录
```

只有在**绕过事件系统的自定义操作**或**调试专用逻辑**时才需要手写 `newLog`。绝大部分效果实现里都不该出现 `newLog`。

## 使用规范

```
优先用系统接口        doEvent / getOrgan / 修饰器 API 自带日志
避免重复日志          在已有 parentLog 的操作里不要再顶层加相同信息
保持简洁              主内容一句话；长细节走 detail
嵌套不要太深           2-3 层即可，超过影响阅读
```

## UI 展示

LogPane 侧栏：

```
▶ / ▼          展开/收起 children
△ / ▽          展开/收起 detail
时间复选框      按时间戳排列 & 显示
清空按钮        重置 logList
```

## 调试技巧

浏览器控制台查看 logList：

```javascript
logList.value.forEach(log => {
    console.log(`${log.text} (level: ${log.level}, children: ${log.children?.length ?? 0})`)
})
```

事件链追踪示例：

```
发生了事件 getOrgan
    发生了事件 possessOrgan
        添加触发器: damage
        添加修饰器: 防御+2
    发生了事件 getOrgan效果
        获得 3 点最大生命
```
