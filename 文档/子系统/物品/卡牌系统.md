# 卡牌系统

卡牌是玩家（以及某些敌人）的行动媒介，需要消耗**能量**才能打出产生效果。每回合开始抽固定张数，回合结束时未打出的手牌被弃入弃牌堆。

源文件：
    类：`src/core/objects/item/Subclass/Card.ts`
    效果目录：`src/core/effects/card/`
    卡牌注册：`src/static/list/card/`
    修饰器：`src/core/objects/system/modifier/CardModifier.ts`

## 三层数据结构：器官 / 牌组 / 牌堆

卡牌数据从静态到动态分三层，每层各有明确边界：

```
器官层（归属源）    ContentModifier              器官持有的卡 key 列表；跨战斗、跨楼层持久
                                                器官损坏 → 卡 disabled；器官失去 → 卡从牌组移除

牌组层（持有集合）  CardModifier.getAllCards()   玩家当前持有的所有 Card 实例
                                                = 所有器官提供的卡的合集
                                                跨战斗、跨楼层持久
                                                addCardToDeck / removeCardFromDeck 直接改这一层

牌堆层（战斗态）    Player.cardPiles              drawPile / handPile / discardPile / exhaustPile
                                                仅战斗内有意义
                                                战斗开始 initCardPile：清空四 pile，getAllCards() → 全塞 drawPile 洗牌
                                                战斗结束：清空四 pile（不需要"回归"动作）
```

转移时机：

```
战斗开始   牌组 → drawPile（所有卡整体导入）
战斗中     drawPile ↔ handPile ↔ discardPile ↔ exhaustPile 之间流转
战斗结束   清空四 pile（牌组层不变，下场战斗重新 initCardPile）
永久移除   removeCardFromDeck 直接改牌组层（战斗外也可发生，如事件/休息点效果）
```

常见误区：

```
✗ "战斗结束时卡回到器官"
   错。战斗结束就是清 pile，牌组层始终不变；下场战斗从牌组重新导入才是"回归"

✗ "ability/power 词条战斗结束回牌堆"
   错。词条只管使用时"不进任何 pile"；"回归"是下场战斗 initCardPile 干的事，与词条无关

✗ "本作没有牌组"
   错。牌组存在（CardModifier.getAllCards()），只是不能玩家手动编辑，而是器官提供的合集自动汇总
```

## 卡牌本质

`Card extends Item`，主要字段：

```typescript
class Card extends Item {
    itemType: "card"                          // 类型守卫用
    source?:  Entity                          // 来源（器官/遗物/事件等）
    owner?:   Entity                          // 持有者，通常是 Player
    tags?:    string[]                        // 分类标签，用于筛选（详见 [[card-tag-selector]]）
    level:    number                          // 当前等级（升级系统）
    isTemporary: boolean                      // 是否临时卡
    temporaryRemoveOn?: "battleEnd" | "turnEnd" | "floorEnd"
}
```

## 交互 interaction

CardMap 支持以下 interaction key。每个 interaction 内部可含 `effects` / `triggers` / `modifiers`（参见 [[reaction-system-detail]]）。

```
use     使用卡牌时触发（必需，否则 useCard 会报错）
inHand  卡牌在手时挂载（进入手牌 mountInHand → 离开手牌 unmountInHand）
get     获得卡牌时（非临时）
lost    失去卡牌时（非临时）
```

`inHand` 交互三种子域都会自动挂载：

```typescript
inHand.triggers   → 挂到 owner 的 trigger 系统（离开手牌自动清理）
inHand.modifiers  → 通过 status.addByJSON 挂 modifier（离开手牌自动 remover）
inHand.effects    → 立即执行为一个 "inHandCard" 事件，副作用清理函数注册到 _inHandCleanups
```

**注意**：旧文档提到的 `drawFromPile` / `drawToHand` / `discardCard` 是**事件 key**（不是 interaction），代码中实际事件 key 为 `drawFromDrawPile` / `drawCard` / `discard`。这些事件走的是普通触发器体系，需要在触发器上响应而不是在 interaction 上定义。

## 使用流程

`useCard(card, fromPile, source, targets)` 五步：

```
1. canPlayCard 检查
   通过 CardModifier.canPlayCard 检查词条限制/来源限制等
   失败 → newError 弹窗、直接返回

2. 支付能量事件（payEnergy）
   key: "payEnergy"，medium 是卡牌本身
   effectUnit: payEnergy（value = getStatusValue(card, "cost")）
   resultStoreAs: "payEnergyResult"
   等待事务结算后读结果
   失败（如能量不足） → 直接返回
   注：payEnergy 内部委派到 loseEnergy 子事件完成扣减，触发器监听 loseEnergy 可拦截所有能量流失路径

3. useCard 触发器事件
   key: "useCard"，target 是选中的目标
   effectUnits 为空（只用于触发器）
   info.repeat 默认 1，before 触发器可修改（如"双发"改成 2）

4. cardEffect 事件 × repeat 次
   key: "cardEffect"，effectUnits 是 use interaction 的 effects
   按 useCardInfo.repeat 循环执行

5. afterUseCard 事件
   key: "afterUseCard"，medium/target 均为卡牌自身
   effectUnit 由 card.getAfterUseEffect(fromPile) 决定
   默认: pay_discard（移入弃牌堆）
   词条可覆盖此方法改变卡牌去向（消耗词条 → 消耗堆等）
```

打出后的默认位置由 `getAfterUseEffect` 决定，词条通过覆盖此方法即可改变去向，不需要监听单独事件。

## 目标选择

卡牌配置里的 `targetType` 字段（详见 [[choose-target-system]]）驱动 UI 的目标选择：

```
targetType.faction  可选阵营（player / enemy / all / opponent）
targetType.number   选择次数（数字 or "all"）
targetType.key      指定固定目标（如 "self"）
```

代码中**没有 aim 方法**——目标选择完全由 targetType 声明式解析（`resolveTargetTypeRules`）。

## 获取

新增卡牌到牌组的渠道：

```
器官 organ 提供             器官被拥有时自动加卡；器官损坏时卡牌被 disabled；器官失去时卡牌被移除
事件 event 选项              事件效果 addCardToDeck 等
效果类                      addCardToHand（临时进手牌）
                            addRandomCardsToPile（随机加牌）
                            retrieveCards（回收）
                            addTemporaryEffect / giveTemporaryEffectToRandomCards（临时效果）
```

临时卡牌通过 `isTemporary + temporaryRemoveOn` 控制生命周期。

## 移除

三层：

```
选择移除 chooseCardRemove       弹卡牌选择界面，玩家选（如净化泉水事件），支持 min/max 张数
                                 src/core/effects/card/cardChoice.ts:144
直接移除 removeCardEffect        removeCard 事件对每张选中卡触发；由效果或触发器发起
                                 src/core/effects/card/cardRemoveEffect.ts
底层移除 removeCardFromDeck      CardModifier.removeCard(card) 按 key 匹配从 cardsFromSources 移除
                                 src/core/effects/card/cardRemove.ts
                                 src/core/objects/system/modifier/CardModifier.ts
```

## 升级

在 CardMap 上通过 `upgradeConfig` 声明：

```typescript
upgradeConfig: {
    maxLevel?: number                    // 最大等级，不设即无限升级
    levelConfigs?: {
        [level: number]: {
            status?: Record<string, number>       // 该等级的属性覆盖（cost/damage 等）
            entries?: string[]                    // 该等级的词条覆盖
            describe?: any[]                      // 该等级的描述覆盖
            interaction?: Record<string, any>     // 该等级的 interaction 覆盖
        }
    }
}
```

升级三种入口：

```
选择升级 chooseCardUpgrade      玩家选（如休息点）
随机升级 upgradeRandomCards     可指定 tag 筛选（如只升级攻击牌），常见于事件奖励
直接升级 upgradeCard            对特定卡实例升级
```

升级机制：

```
属性升级       走 originalBaseValue 系统：改原始基础值，保留所有已有 modifier
              例：伤害 base=5，有 +3 modifier，current=8；升级 base→8 后 current=11
词条升级       旧等级 entries 全部撤销，新等级 entries 全部添加（EntryModifier 自动管理）
交互升级       interaction 字段可整块覆盖（Level>0 时）
显示名         锻造后 `displayName` 为 `label+`（多数牌 maxLevel 1，只加一次 +）
```

相关：`src/core/effects/card/cardUpgrade.ts` `src/core/effects/card/cardUpgradeEffect.ts`。

## 词条

词条本质是挂在卡牌上的装饰器，通过 `EntryModifier`（`src/core/objects/system/modifier/EntryModifier.ts`）管理。

Card 提供 `hasEntry(key)` 直接查询。

词条影响卡牌行为的常见方式：

```
覆盖 getAfterUseEffect          消耗词条改变卡牌打出后去向（弃牌堆 → 消耗堆）
挂 trigger                      虚无词条挂 turnEnd 触发器，回合结束前移入消耗堆
挂 modifier                     调整卡牌 status（cost/damage 等）
```

因词条产生的事件，medium 通常是持有词条的卡牌自身。
