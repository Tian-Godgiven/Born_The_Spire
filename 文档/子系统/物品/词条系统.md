# 词条系统 Entry

词条（Entry）是可复用的**特殊效果模板**，声明在卡牌/器官的 `entry: string[]` 字段里。持有者获得该实体时，词条会自动挂载相应的触发器/方法覆盖；失去实体时，副作用一并撤销——由 EntryModifier 统一管理生命周期。

源文件：
    定义汇总：`src/core/objects/system/Entry.ts`
    卡牌词条：`src/core/objects/system/entry/CardEntry.ts`
    器官词条：`src/core/objects/system/entry/OrganEntry.ts`
    管理器：`src/core/objects/system/modifier/EntryModifier.ts`
    相关效果函数：`src/core/effects/card/entryEffects.ts`

## 与相邻概念的差异

```
Entry    卡牌/器官声明的特殊效果模板     entry: string[]        自带 onApply/生命周期
Tag      纯分类标识                    tags: string[]          无副作用，仅供筛选
Trigger  底层响应机制                   entity.trigger        Entry 内部产物
State    战斗中动态附加的状态           StateModifier          可堆叠、可清除
```

一句话：**Tag 是标签，Entry 是效果**。同一张卡两者可并存。

## EntryDefinition 结构

```typescript
type EntryDefinition = {
    label?:         string
    describe:       Describe
    conflictsWith?: string[]                          // 冲突词条列表
    onApply: (owner: Entity, ownersOwner?: Entity)   // 返回移除函数数组
             => Array<() => void>
}
```

**参数**：

```
owner        持有该词条的实体（Card / Organ）
ownersOwner  owner 的 owner（通常是 Player 或 Enemy）
             通过鸭子类型判定；owner 若无 owner 字段则 undefined
```

**返回**：一定要返回移除函数数组，即使为空。这些函数在词条被 removeEntry 时自动调用——**这就是"失去时自动清理"的根本机制**。

## 触发器挂载位置的选择

`onApply` 内你可以自由选：

```
挂到 owner        监听卡牌/器官自身的事件（受伤、被使用）
挂到 ownersOwner  监听持有者的事件（回合、战斗、抽牌）
```

例如 `card_void` 挂到 Player：监听回合结束——这是 Player 的事件，不是卡的。

## 已注册词条

汇总在 `entryDefinitions`——由 `cardEntryDefinitions` 与 `organEntryDefinitions` 合并。**key 有 `card_` / `organ_` 前缀**，别落写。

### 卡牌词条（5 个）

```
card_exhaust        消耗   使用后移入消耗堆          与 card_void 冲突
card_power          能力   使用后从本场战斗移除      与 card_exhaust / card_void 冲突
card_void           虚无   回合结束时若在手牌则消耗   与 card_exhaust 冲突
card_inherent       固有   战斗开始必抽到
card_cannot_play    不可使用   无法主动打出
```

### 器官词条（3 个）

```
organ_fragile       脆弱     持有者受伤时 50% 概率损坏该器官
organ_sturdy        坚固     该器官不会损坏
organ_regenerative  再生     （详见源文件）
```

**注意**：仓库里 `cardList.ts` 有过一处旧写法 `entry: ["exhaust"]`（无前缀）——这是遗留数据 bug，不会被识别。新数据一律用 `card_exhaust`。

## 声明式使用

在卡牌/器官数据里写：

```typescript
{
    key:   "card_001",
    label: "打击",
    entry: ["card_exhaust"],
    // ...
}
```

多个词条并列 `entry: ["card_inherent", "card_exhaust"]`——EntryModifier 逐个 addEntry，遇冲突返回失败字符串。

## EntryModifier

```typescript
addEntry(entryKey)     → boolean | string     // true=成功，string=失败原因
removeEntry(entryKey)  → boolean
hasEntry(entryKey)     → boolean
getEntries()           → string[]
```

**冲突检测**：`addEntry` 依次检查
```
1. 词条是否已存在（返回 "词条已存在"）
2. 是否与已有词条 conflictsWith 命中（返回 "与 xxx 冲突"）
成功 → 调 onApply → 保存返回的 removers 数组
```

`removeEntry` → 逐个执行 removers → 从 store 移除。

## Vue 响应式陷阱

EntryModifier 用 **WeakMap** 存储（不污染 Entity 基类）。存取时必须 `toRaw`：

```typescript
export function getEntryModifier(entity: Entity): EntryModifier {
    const rawEntity = toRaw(entity)          // Vue reactive 的 Proxy 对象与 raw 不是同一 key
    let modifier = entryModifierMap.get(rawEntity)
    if (!modifier) modifier = initEntryModifier(rawEntity)
    return modifier
}
```

否则同一实体每次都会 miss 而重新初始化，缓存失效。

## 词条与效果函数

词条的 `onApply` 常搭配专属 effect（在 `src/core/effects/card/entryEffects.ts` 中注册）：

```
pay_exhaust             card_exhaust 用；把卡移入消耗堆
pay_removePower         card_power 用；把卡从战斗中移除
voidExhaust             card_void 用；回合结束将手牌中的 void 卡消耗
moveInherentToHand      card_inherent 用；战斗开始把固有卡拉到手牌
fragileBreak            organ_fragile 用；50% 概率损坏器官
```

这些 effect 在 `effectMap.ts` 注册，通过普通 effect 系统执行——词条自身不直接调副作用，而是**声明触发器**由效果系统落地。

## 新词条开发流程

```
1. 在 entry/CardEntry.ts 或 entry/OrganEntry.ts 的定义表里加一项 EntryDefinition
   起 key 时用 card_ / organ_ 前缀

2. 若需要新的 effect（例如"移入某堆"），在 effects/card/entryEffects.ts 写函数，
   并在 static/list/system/effectMap.ts 注册

3. 数据里 entry 字段引用即可，无需第三步注册表
```

**不需要**改 `entryMap.ts` 或 `Entry.ts` 主表——两个子表通过 spread 合并进 `entryDefinitions`。

## 完整示例：card_void

```typescript
card_void: {
    label: "虚无",
    describe: ["若回合结束时仍在手牌中，会移入消耗堆而非弃牌堆"],
    conflictsWith: ["card_exhaust"],
    onApply: (owner, ownersOwner) => {
        if (!(owner instanceof Card))       return []
        if (!(ownersOwner instanceof Player)) return []

        const trigger = createTriggerByTriggerMap(ownersOwner, ownersOwner, {
            when: "before", how: "make", key: "turnEnd",
            event: [{
                key: "voidExhaust",
                targetType: owner,
                effect: [{
                    key: "voidExhaust",
                    describe: ["虚无：将卡牌移入消耗堆"],
                    params: {}
                }]
            }]
        })
        const { remove } = ownersOwner.trigger.appendTrigger(trigger)
        return [remove]           // ← 撤销回路
    }
}
```
