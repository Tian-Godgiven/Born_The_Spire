# 当前值系统 Current

Current 用于管理**高频变化、不撤销、不走乘区**的即时数值，如角色 HP、玩家能量、存活标志等。与 Status（属性）互补：Status 是 "永久基础值 + 可撤销修饰"，Current 是 "此刻的数字"。

源文件：
    类：`src/core/objects/system/Current/current.ts`
    已注册：`src/static/list/system/currents/`
    注册表：`src/static/list/system/currents/currentMap.ts`

## 与相邻概念的差异

```
Status  可由 modifier 增减，撤销/清理是常态；乘区独立计算；不能"直接改" — 只能改 base 或加 modifier
Current 单一数值，变化频繁，无撤销需求；改法就是"直接改数字"
Item    也不关心过程，但表达的是"对象/装备"而不是数字
Reserve 类似 Current 但走 ReserveModifier（物质/金钱），有专门的库存管理
```

一句话：当前值只关心"现在多少"。

## 类结构

```typescript
class Current {
    key:     string
    label?:  string
    _value:  Ref<number>              // Vue ref，读写走 getRefValue/setRefValue
    value:   number                    // getter/setter 代理 _value
    owner:   Entity                    // 持有者
    options: CurrentOption             // 见下
    triggers: { id, remove }[]         // 与此 current 关联的触发器，挂在 owner 上
}
```

**注意**：Current 对象存入 `entity.current[key]` 时用 `markRaw` 保护，避免 Vue 响应式破坏内部 ref。

## 选项 CurrentOption

```typescript
interface CurrentOption {
    maxBy?:        string | number
        // 上限；string 时取 owner.status[X].value；默认 Infinity
    minBy?:        string | number
        // 下限；同上；默认 0
    allowOverMax?: boolean | "breakdown"
        // 尝试超过上限时的行为；默认 true
    allowOverMin?: boolean | "breakdown"
        // 尝试低于下限时的行为；默认 true
    reachMax?:     (event, owner, current) => void
        // 达到上限时回调（含"正好等于"）
    reachMin?:     (event, owner, current) => void
        // 达到下限时回调
    onShow?:       string | number | ((owner, current) => number | string)
        // 显示值覆写；不影响实际计算，只影响 UI 数字
}
```

`allowOverMax` / `allowOverMin` 三态语义（以下限为例，当前 3，尝试改到 -100，下限 0）：

```
false        拒绝修改，返回 false
true         夹到下限 0；返回 3（实际变化量）
"breakdown"  夹到下限 0；返回 103（预期变化量）
```

`reachMax` / `reachMin` 回调不区分"造成达到上下限的原因"——只知道达到了。要区分原因需自行读 `event.source` / `event.medium`。

## 已注册的当前值

### health 生命
```
所在：src/static/list/system/currents/health.ts
用于：所有 Chara（Player / Enemy） + Organ
startValue: "max"        起始值等于上限
maxBy:      "max-health"  跟随 max-health 属性
minBy:      0
reachMin:   触发 healthReachMin 事件（不是死亡事件本身，死亡走 isAlive）
```

### energy 能量
```
所在：src/static/list/system/currents/energy.ts
用于：Player、Enemy
startValue: 0
maxBy:      未设（无上限；回满读的是 max-energy 属性）
minBy:      0（默认，不允许负数）
敌人默认 max-energy 为 3（构造时补上）；写了就用写的值
触发器：
    turnStart / make / before / recoverEnergy
        回合开始时回满至能量上限
    turnEnd / take / after / emptyEnergy
        回合结束后清空
```

### isAlive 存活
```
所在：src/static/list/system/currents/isAlive.ts
用于：Chara
startValue: 1                    1 = 存活；0 = 死亡
maxBy: 1  minBy: 0
allowOverMax / allowOverMin: false   死了不能再"更死"，活着不能"更活"
reachMin: 触发 death 事件         死亡的入口
reachMax: 触发 revived 事件       复活的入口
```

生命值归 0 → `healthReachMin` 事件；死亡逻辑（比如判定挂掉、通知玩家）不在 health 里，走 isAlive.reachMin 触发的 `death` 事件。这是**故意分层**：允许"生命归 0 但仍存活"（护盾/免疫等机制）与"生命 > 0 但被强制杀死"（instakill 类效果）分别表达。

## API

```typescript
initCurrentFromMap(owner, mapData)
    根据 mapData 从 currentMap 找 meta，创建 Current 对象并挂到 owner
    entity 类构造时自动调用

appendCurrent(entity, current, force = false)
    低层挂载；重复 key 时 force=false 会 newError，force=true 覆盖

ifHaveCurrent(entity, key)
    是否具备某 current

getCurrentValue(entity, key, defaultValue?)
    读值；不存在时若传了 defaultValue（**包括 0**）则返回它，否则 newError

getCurrentRefValue(entity, key, defaultValue?)
    读到 ref 本身（用于响应式场景），不存在时若传了 defaultValue（**包括 0**）则返回它，否则 newError

setCurrentValue(entity, key, value)
    直接改值，不走上下限检查、不触发 reachMax/reachMin
    仅用于系统级别（如初始化、强制同步）

changeCurrentValue(target, key, newValue, event) → false | number
    正规修改路径，走上下限检查与 reach 回调
    返回值：false 表示被拒；数字表示实际变化量（按 allowOverX 语义）
```

**规则**：正常的效果代码走 `changeCurrentValue`；`setCurrentValue` 只用于绕过所有限制的场景（例如初始化、迁移）。
