# 属性系统 Status

Status 用于管理实体的**长期/可撤销数值属性**（最大生命、伤害、防御倍率等）。特点：变化不频繁、变化通常可撤销、需要按来源追踪、需要独立乘区计算。与 [[当前值系统]]（Current）互补。

源文件：
    类：`src/core/objects/system/status/Status.ts`
    修饰器：`src/core/objects/system/status/StatusModifier.ts`
    类型：`src/core/objects/system/status/type.d.ts`
    属性注册表：`src/static/list/system/statusMap.ts`

## 与相邻概念的差异

```
Status   有 base/current 双层 + 修饰器管理    可撤销、可追踪来源、独立乘区
Current  单一即时值                          高频变化、不撤销、直接改
Reserve  资源/库存类（物质/金钱）             走 ReserveModifier
State    战斗中的动态效果层                   通过 StateModifier 挂载 + 触发器
```

一句话：Status 记录"这个实体某属性经过所有加成后是多少"。

## 三层数值结构

Status 内部维护三个值：

```
originalBaseValue   原始基础值      不受修饰器影响；卡牌升级等场景通过 setOriginalBaseValue 修改
baseValue           基础值          originalBaseValue + 所有 base 层修饰器结果；长期保留
value               当前值          baseValue + 所有 current 层修饰器结果；战斗内可临时变化
```

### notNegative 下限钳制

注册表里声明 `notNegative: true` 的属性，`refresh()` 算完后会把 `baseValue` 和 `value` 各钳一次
`Math.max(0, ...)`：

```
originalBaseValue   不钳，保留数据声明的原始意图
baseValue / value   钳，防止"减多次跑到负值"
```

钳制发生在整条修饰器链算完之后，不是每个修饰器之后 —— 中间过程允许为负，
否则 "-5 再 +3" 这种组合会被算成 3 而不是 -2。

非数值（string / null）走直通路径提前 return，不受钳制影响。

### 值的类型：number / string / null

三个值的类型都是 `number | string | null`，只有 number 参与修饰器计算：

```
number   正常数值，走 refresh 的完整修饰器计算链
string   直接量，setOriginalBaseValue 与 refresh 都原样复制，跳过计算
null     表示"该实体没有这个属性的概念"，与 string 走同一条直通路径
```

`null` 与 `0` 是两回事，别混用：

```
cost: 0      这张牌有费用，只是免费    → UI 显示 "0"
cost: null   这张牌没有费用这个概念    → UI 整个费用框不画
```

典型用例是无费用的诅咒/状态牌（伤口、悔恨、受伤、疑虑）。注意属性本身照常创建，
只是值为 null —— 不要改成"不定义该属性"，卡牌的 cost 是固有结构。

消费 null 值时的约定：算术场景按 0 处理（`?? 0`），筛选场景要显式排除，
不能依赖 `Number(null) === 0` 这种隐式转换，否则无费用牌会被当成 0 费匹配进去。
参考 `CardSelector.ts` 的 costRange 筛选。

**升级示例**（伤害从 5 到 8，且有器官 +3 修饰器）：

```typescript
// 初始
card.status.damage.originalBaseValue = 5
card.status.damage.baseValue         = 8    // 5 + 3
card.status.damage.value             = 8

// setOriginalBaseValue(8) 触发 refresh
card.status.damage.originalBaseValue = 8
card.status.damage.baseValue         = 11   // 8 + 3（修饰器保留）
card.status.damage.value             = 11
```

## Status 类

```typescript
class Status extends Modifier<StatusModifier> {
    key:          string
    label:        string
    options?:     StatusOptions              // { notNegative?: boolean }（未完成）
    // ---- 显示相关 ----
    calc:         boolean = true             // 是否参与自动计算
    hidden:       boolean = false             // 是否隐藏
    display:      boolean = true             // 是否显示为角标
    displayMap?:  Record<string, string>     // 值到显示文本的映射（如 { "1": "存活" }）
    max?:         number                      // 计数器上限（用于角标 "3/5" 显示）
    maxFrom?:     string                      // 从另一个 status key 读取 max
    // ---- 值层 ----
    originalBaseValue: number | string
    baseValue:         number | string
    value:             number | string
}
```

**支持字符串值**：`setOriginalBaseValue(string)` 会短路 refresh，把三层都设成同一字符串（用于"派系"、"名称"这类非数值属性）。

## StatusModifier

```typescript
class StatusModifier extends ModifierObj {
    statusKey:          string
    targetLayer:        "base" | "current"
    modifierType:       "additive" | "multiplicative" | "function"
    applyMode:          "absolute" | "snapshot"
    timeStamp:          number                  // Date.now()，用于排序
    value:              number                  // 加值、倍率、function 的参数
    snapshotValue?:     number                  // snapshot 时记录添加瞬间的 value
    snapshotBaseValue?: number                  // snapshot 时记录添加瞬间的 baseValue
    clearable:          boolean = true          // 是否可被 clearClearableModifiers 清理
    modifierFunc?:      (owner, current, value) => number   // function 类型专用
}
```

`ModifierType` 有 `function` 而非旧文档说的 `final`——自定义计算函数走 function 类型。

`clearable` 替代了旧的 `duration` 枚举：清理时机由外部代码在合适时机调 `status.clearClearableModifiers()` 决定，不再由修饰器自身声明。战斗结束、回合结束等清理点由业务代码调用。

## refresh 算法

新增/删除/修改修饰器时自动重算：

```
1. base 层：
   base = originalBaseValue
   for m in sortedByTimeStamp(base 层 modifiers):
       switch (m.modifierType, m.applyMode):
           additive + absolute       → base += m.value
           additive + snapshot       → base = m.snapshotBaseValue + m.value
           multiplicative + snapshot → base = base + m.snapshotBaseValue * (m.value - 1)
           function                  → base = m.modifierFunc(owner, base, m.value)

2. current 层：
   current = base
   for m in sortedByTimeStamp(current 层 modifiers):
       switch (m.modifierType, m.applyMode):
           additive + absolute       → current += m.value
           additive + snapshot       → current = m.snapshotValue + m.value
           multiplicative + snapshot → current = base + m.snapshotValue * (m.value - 1)
           function                  → current = m.modifierFunc(owner, current, m.value)

3. 写回 baseValue 与 value
```

**snapshot 差值计算**保持"倍率作用于添加瞬间的值"的直觉：新增的 base 层修饰器不会二次放大乘法。

## 示例流程

初始 base=100，current=100。

```
1) 添加 A：当前值 x2（战斗中）
   current / multiplicative / snapshot / value=2
   记 snapshotValue = 100
   算 current = 100 + 100*(2-1) = 200

2) 添加 B：基础值 +10（永久）
   base / additive / absolute / value=10
   算 base = 100+10 = 110
   算 current = 110 + 100*(2-1) = 210

3) 添加 C：当前值 +10（临时）
   current / additive / snapshot / value=10
   记 snapshotValue = 210
   算 current = 210+10 = 220

4) 移除 C：current 层重算
   current = 110 + 100*(2-1) = 210

5) 移除 A：current 层重算
   current = base = 110
```

## API

```typescript
appendStatus(entity, status)
    添加属性，重复 key 会 newError
    内部用 markRaw 保护 status

createStatusFromMap(owner, key, mapData)   → Status
    从 StatusMap 数据（number 或对象）创建 Status
    自动设 originalBaseValue

ensureStatusExists(entity, key, initialValue = 0)
    不存在则创建；已存在无操作
    initialValue 设为 originalBaseValue

getStatusValue(entity, key, defaultValue?)     → number | string
    读当前值；不存在且无默认时 newError

getStatusRefValue(entity, key)                  → Ref<number | string>
    读 value 的 ref（用于 Vue 组件响应式绑定）

ifHaveStatus(entity, key)                       → boolean

changeStatusValue(entity, key, source, opts)    → () => void
    添加一个 StatusModifier，返回移除函数
    opts: { value, type = "additive", target = "base", clearable?, modifierFunc? }
```

### changeStatusValue 智能默认

```
target = "base"                clearable 默认 false（永久）；applyMode = "absolute"
target = "current" + additive  clearable 默认 true；applyMode = "absolute"
target = "current" + multiplicative  clearable 默认 true；applyMode = "snapshot"
```

**正确用法**（source 是第三个参数）：

```typescript
const remove = changeStatusValue(player, "max-health", organ, {
    value: 10,
    type: "additive",
    target: "base"
})
// 撤销
remove()
```

不要把 source 传成 `{ source, medium }` 对象——直接传 Entity 即可。

## Vue 响应式陷阱

Entity 用 `reactive()` 包装，Vue 会递归转换所有嵌套对象。Status 内部持有 `_baseValue = ref()` / `_value = ref()`——被 reactive 处理后，ref 会被解包为数字，触发：

```
TypeError: Cannot create property 'value' on number '50'
```

**解决**：`appendStatus` 与 `ensureStatusExists` 都用 `markRaw(status)` 保护。写自己代码时把 Status 放进 entity.status 也要 markRaw：

```typescript
entity.status[key] = markRaw(status)   // ✅
entity.status[key] = status            // ❌
```

## 清理临时修饰器

```typescript
status.clearClearableModifiers()   // 移除所有 clearable=true 的 modifier，并 refresh
```

由外部代码在合适时机调用（回合结束、战斗结束等），不由修饰器自身声明。
