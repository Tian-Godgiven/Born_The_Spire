# 属性注册表系统 StatusMap

`statusMap.ts` 是所有可用属性（Status）的**定义中心**：每个 key 在这里登记默认值、类别、显示行为。

实体数据里通常只写一个值（`status:{cost:1}`），行为配置从注册表取：`createStatusFromMap` 用 key
查 `getMap`，把注册表配置套到 Status 实例上，实体自己写成配置对象时同名字段以实体为准。
未登记的 key 也能正常创建 Status，只是拿不到 label / notNegative 这些行为配置。

源文件：
    数据：`src/static/list/system/statusMap.ts`
    类型：`src/core/types/StatusMapData.ts`
    消费方：`src/core/objects/system/Entity.ts` L52 走 `createStatusFromMap`
    Status 类：`src/core/objects/system/status/Status.ts`

### 当前生效的字段

注册表里的字段并非都有消费方，登记时别指望没接线的字段能起作用：

```
label        Status.label，目前 UI 无显示方
value        起始值；实体数据给了值就被覆盖，实际很少生效
notNegative  生效，refresh() 里钳 baseValue / value 的下限
hidden       只赋值到 Status 实例，无读取方
calc         同上
display / displayMap / max / maxFrom   badgeResolver 会读，但注册表里没有条目声明它们
describe / category                    Status 类没有对应字段，纯文档用途
```

## StatusMap 数据类型

```typescript
type StatusMap = number | {
    label:       string
    value:       number | string                   // 起始值，可为字符串（如"存活"）
    describe?:   string
    category?:   "base" | "combat" | "card" | "special"
    notNegative?: boolean                          // 非负，钳制 baseValue / value 的下限
    unstackable?: boolean                          // 不可堆叠
    hidden?:     boolean                           // UI 不显示
    calc?:       boolean                           // 是否参与自动计算（默认 true）
    display?:    boolean                           // 是否显示为角标
    displayMap?: Record<string, string>            // 值到显示文本的映射
    max?:        number                            // 角标 "x/max" 的上限
    maxFrom?:    string                            // 从另一个 status key 动态读 max
}
```

**简写数字形式**——只想要默认值不写其他字段：

```typescript
statusMapList["quickCount"] = 3   // 等价于 { label: "quickCount", value: 3 }
```

`createStatusFromMap` 在 `typeof mapData === "number"` 时用 key 作为 label 走短路径。

## 与相邻概念的关系

```
StatusMap    数据配置          "属性长什么样"        位于 static/list
Status       运行时对象         "此实体的这个属性"    位于 entity.status[key]
Modifier     修饰器             "谁改了此属性"        挂在 Status 上
Current      即时值             与 Status 无关       走 CurrentMap
```

一句话：StatusMap 是模板，Status 是实例，Modifier 修改实例的值。

## 已注册项

### base 基础属性

```
health          生命          当前生命值
max-health      最大生命       生命值上限（非负）
energy          能量          当前能量值（非负）
max-energy      最大能量       每回合恢复上限（非负）
max-potion      最大药水数    可携带的药水数（非负）
```

### combat 战斗属性

```
strength    力量    增加攻击伤害
dexterity   敏捷    增加格挡值
block       格挡    抵挡伤害的护甲（非负）
vulnerable  易伤    受伤 +50%（非负）
weak        虚弱    造伤 -25%（非负）
frail       脆弱    格挡 -25%（非负）
```

### card 卡牌相关

```
cost           消耗            使用该卡消耗的能量（非负）
draw-per-turn  每回合抽牌数    回合开始抽牌数（默认 5，非负）
```

### special 特殊属性

```
action-order  行动顺序      数字越小越先行动
ifBloodMark   染血标记      0=未染血 / 1=已染血（hidden）
```

## 主 API

```typescript
getMap(key)                     → StatusMap | false
    不在注册表返回 false

registerStatus(key, config)     → boolean
    重名返回 false 并 console.warn，不覆盖
    Mod 侧动态追加自定义属性用

getAllStatusKeys()              → string[]
    获取所有已登记 key（UI 遍历用）

getStatusByCategory(category)   → Record<string, StatusMap>
    按分类筛选
```

## 与 Entity 挂载的关系

Entity 构造时遍历自身 `status: Record<string, number | string | StatusMap>` 字段，对每个 key 调 `createStatusFromMap(entity, key, value)` 得到 Status，然后 `appendStatus` 挂到 `entity.status`。

```
value 是 number/string    → 用作 originalBaseValue，label = key
value 是 StatusMap 对象   → 复制 calc/hidden/display/displayMap/max/maxFrom
                             再 setOriginalBaseValue(mapData.value)
```

**注意**：Entity 数据里 `status` 字段的 value 可以是任意 `StatusMap`（含 number 简写），并不强制引用注册表里已登记的项。注册表的价值在于：**统一默认值**、**声明分类**、**给 UI 提示**。数据里定义"某个自定义属性 = 5"也能正常工作。

## fromStatus 动态引用

某些参数需要"从当前实体的某个属性读实时值"，效果参数里可写：

```typescript
{
    key: "drawFromDrawPile",
    params: {
        value: { fromStatus: "draw-per-turn" }   // 从 status 读实时抽牌数
    }
}
```

效果函数内解析：

```typescript
import { getStatusValue } from "@/core/objects/system/status/Status"

export const drawFromDrawPile: EffectFunc = (event, effect) => {
    const p = effect.params.value
    const num = typeof p === "object" && "fromStatus" in p
        ? getStatusValue(player, p.fromStatus, 5)
        : p as number
    // ...
}
```

**位置**：目前仅 `drawFromDrawPile` 与 `addFirstTurnDraw` 支持此模式，在 `playerList.ts` 里作为 `draw-per-turn` 的读取入口使用。想要更通用的运行时引用请用 [[实现参考手册]] 里描述的 `$xxx` 语法。

**注意**：项目为 Vite + ES modules，效果函数**必须用 import 静态引入 getStatusValue**，不得用 `require()`。

## 遗物修改属性的推荐模式

```typescript
// relicList.ts
interaction: {
    possess: {
        target: { key: "owner" },
        effects: [{
            key: "addStatusBase",
            params: { statusKey: "draw-per-turn", value: 2, type: "additive" }
        }]
    }
}
```

获得遗物 → 自动为 `draw-per-turn` 加一个 +2 修饰器 → 抽牌数从 5 变 7；失去遗物 → 修饰器自动移除、抽牌数复原。**不要手动操作触发器去替换抽牌逻辑**——那是老思路。

## 扩展指南

### 什么该登记

只登记**系统会读取的属性**：核心代码按 key 取值的，或者需要 `notNegative` 这类行为配置的。

```
登记      max-health / max-energy / max-potion / cost / draw-per-turn
          cannot-play / retain-on-turn-end / disabled / action-order
          ifBloodMark / hungry-beast-*

不登记    damage / armor / times / weakStacks 等卡牌与器官上的数值参数
```

卡牌参数是内容数据，没有跨内容复用的语义，每张卡自己定义即可。未登记的 key 照样能创建
Status，只是拿不到 label / notNegative —— 不要为了让某个卡牌参数"合法"而来补一条。

`weak` / `vulnerable` / `strength` / `dexterity` / `block` / `frail` / `health` / `energy`
曾经登记在此，已移除：前四个要么零引用、要么实际是 State（力量是 `power`，敏捷是 State
`dexterity`）；`health` / `energy` 实际走 Current；`weak` / `vulnerable` 则是卡牌参数误登记。

### 添加内置属性

确认属于"系统会读取的属性"后，在 `statusMapList` 里加一项：

```typescript
"my-new-stat": {
    label: "我的新属性",
    value: 0,
    describe: "描述",
    category: "special",
    notNegative: true
}
```

### Mod 追加自定义属性

在 Mod 启动阶段调用：

```typescript
import { registerStatus } from "@/static/list/system/statusMap"

registerStatus("mod-custom-stat", {
    label: "Mod 自定义属性",
    value: 10,
    category: "special"
})
```

重名会失败并 warn，不会覆盖内置项。

## 注意事项

```
不要直接修改 status.value       走修饰器系统（addStatusModifier / changeStatusValue）
默认值只在初始化生效            实体加载后就与 statusMap 断开
category 只影响组织与 UI 分组    不影响功能
hidden = true                    不出现在 UI 角标，用于 flag/内部状态（如 ifBloodMark）
displayMap 用于枚举文本          如 { "0": "未染血", "1": "已染血" }
```
