# 死亡状态系统

角色的死亡不硬编码——通过 `isAlive` 当前值 + `healthReachMin` 事件 + 可覆盖的默认触发器分层实现，允许假死、多次复活、条件死亡、不死等设计。

源文件：
    isAlive 配置：`src/static/list/system/currents/isAlive.ts`
    health 配置：`src/static/list/system/currents/health.ts`
    默认触发器：`src/core/objects/target/Target.ts`（Chara 构造）
    kill / revive / loseHp 效果：`src/core/effects/life/lifeControl.ts`
    效果注册：`src/static/list/system/effectMap.ts`（key: `kill` / `revive` / `loseHp`）

## isAlive 当前值

所有 `Chara` 都有 `isAlive`：`1` 存活，`0` 死亡。**独立于生命值**——`health = 0` 不必然等于死亡。

```typescript
isAliveMap: CurrentMap<Chara> = {
    startValue:   1
    maxBy:        1
    minBy:        0
    allowOverMax: false
    allowOverMin: false
    reachMin: (event, owner) => { /* 触发 death 事件 */ }
    reachMax: (event, owner) => { /* 触发 revived 事件 */ }
}
```

## 完整事件链

**关键区分**：`dead` 事件与 `death` 事件是两个不同的事件，分别在死亡流程的不同段位。

```
health = 0
    ↓ health.reachMin
【事件】healthReachMin      仅通知，effectUnits = []
    ↓ Chara 默认触发器 after take healthReachMin
【事件】dead                 携带 effectUnit { key: "kill" }
    ↓ before dead 触发器可拦截
    ↓ kill 效果执行 (killTarget)
        ├─ 检查 isAlive 是否已 0
        ├─ changeCurrentValue(target, "isAlive", 0)
        ├─ 对所有器官 breakOrgan
        ├─ ItemModifier.clearAll()
        └─ nowBattle.checkBattleEnd() → 触发 endBattle
    ↓ isAlive = 0 触发 isAlive.reachMin
【事件】death                死亡后通知，用于死亡动画、掉落、"死亡时"响应
```

**别把 `dead` 写成 `kill`**——`kill` 是效果 key，不是事件 key。老文档把两者混淆过。

## 默认死亡触发器

Chara 构造函数注册的 fallback：

```typescript
this.trigger.appendTrigger({
    when:         "after"
    how:          "take"
    key:          "healthReachMin"
    importantKey: "death_behavior"
    onlyKey:      "default_death_on_health_zero"     // ← 覆盖点
    callback: (event) => doEvent({
        key: "dead", source, medium, target: this,
        info: { reason: "生命值归0" },
        effectUnits: [{ key: "kill", params: {} }]
    })
})
```

**onlyKey 机制**：任何再次注册相同 onlyKey 的触发器会**替换**这个默认。这是自定义死亡行为的正规入口。

## 三层防护

### 第 1 层：改写死亡条件

覆盖 `default_death_on_health_zero` 触发器——生命归 0 时改做别的事（进入假死、扣属性、抽卡等）：

```typescript
{
    when: "after", how: "take", key: "healthReachMin",
    onlyKey: "default_death_on_health_zero",     // 覆盖默认
    event: [{
        targetType: "self",
        key: "enterFakeDeath",
        effect: [{ key: "applyState", params: { stateKey: "fake_death", stacks: 1 } }]
    }]
}
```

角色继续存活（isAlive 未变），进入自定义状态。

### 第 2 层：拦截 kill 效果

在 `dead` 事件的 before 阶段修改或清空 effectUnits：

```typescript
player.trigger.appendTrigger({
    when: "before", how: "take", key: "dead",
    callback: (event) => {
        if (hasImmortalState(player)) {
            event.effects = event.effects.filter(e => e.key !== "kill")   // 清 kill 效果
            doEvent({ key: "heal", target: player, effectUnits: [{ key: "heal", params: { value: 1 } }] })
        }
    }
})
```

kill 效果被清 → isAlive 不变 → 角色继续存活。

### 第 3 层：死后复活

事件 = `revive`，effect key = `revive`：

```typescript
doEvent({
    key: "revive",
    source: reviver, medium: reviveItem, target: deadChar,
    effectUnits: [{ key: "revive", params: { healAmount: 10 } }]
})
```

`reviveTarget` 会：`changeCurrentValue(target, "isAlive", 1)` → isAlive.reachMax 触发 `revived` 事件；若传 `healAmount` 顺带补生命。

**注意**：复活必须补生命，否则 `health` 仍是 0，下一次 refresh 又会触发 `healthReachMin` → 又立即死。

## 存活判定

战斗系统一律**只看 isAlive**，不看 health：

```typescript
battle.getAlivePlayers()      // filter chara.current.isAlive?.value === 1
battle.getAliveEnemies()      // filter chara.current.isAlive?.value === 1
battle.checkBattleEnd()       // 玩家全灭 → "player_lose"；敌人全灭 → "player_win"
```

`killTarget` 内部**自动**调 `checkBattleEnd`，无需手工触发。

## 死亡时的自动清理

`killTarget` 在扣 isAlive 之后连做三件事，不需业务代码手写：

```
1. 对所有未 disable 的器官调 organModifier.breakOrgan
   → 触发器官 break 交互（broken 触发器等）
2. ItemModifier.clearAll()
   → 清所有物品修饰器的副作用
3. checkBattleEnd → endBattle (win/lose)
```

想在死亡时保留某器官？给它加 `organ_sturdy` 词条（不损坏）或 `disable`。

## loseHp 姊妹效果

`lifeControl.ts` 里注册的另一原子效果 `loseHp`：**绕过护甲**直接扣生命。用于 debuff / 状态伤害 / 出血这类"忽略防御"的效果。

```typescript
{ key: "loseHp", params: { value: 5 } }         // 直接 health -= 5，不查 block
```

## 完整示例：假死敌人

数据侧只需两处配置——不用写命令式代码。

```typescript
// 敌人数据
{
    key: "enemy_fake_death",
    trigger: [{
        when: "after", how: "take", key: "healthReachMin",
        onlyKey: "default_death_on_health_zero",   // 覆盖第 1 层
        event: [{
            targetType: "self",
            key: "enterFakeDeath",
            effect: [{ key: "applyState", params: { stateKey: "fake_death", stacks: 1 } }]
        }]
    }]
}

// 状态数据
{
    key: "fake_death",
    label: "假死",
    trigger: [{
        when: "after", how: "take", key: "turnStart",
        event: [{
            targetType: "stateOwner",
            key: "revive",
            effect: [
                { key: "revive", params: { healAmount: 300 } },
                { key: "removeState", params: { stateKey: "fake_death" } }
            ]
        }]
    }]
}
```

假死状态自带触发器——[[状态系统开发指南]] 详细说明这个模式。

## 关键规则

```
永远走事件系统       不直接改 isAlive，用 kill / revive 效果
onlyKey 是覆盖入口   自定义死亡逻辑请用 "default_death_on_health_zero"
复活必补生命        否则 health = 0 立刻二次触发 healthReachMin
事件 key 分清       healthReachMin / dead / death / revive / revived 是五个不同事件
复杂逻辑用状态       假死/濒死保护建议走 State 而不是嵌套触发器
info.reason         死亡原因通过 event.info.reason 传递，用于日志/UI
```
