# 召唤物系统

召唤物是战斗中的临时单位。它们可以加入玩家一方，也可以加入敌人一方；战斗结束后会被清理，不进入局外存档。

## 统一入口

数据效果统一使用 `summon`：

```typescript
{
    key: "summon",
    params: {
        summonKey: "enemy_ant_soldier",
        count: 1,
        duration: 4
    }
}
```

`summon` 根据事件的 `source` 判断阵营：

- `source` 是敌人：从 `enemyList` 创建敌方召唤单位，并加入敌方编队。
- `source` 是玩家或玩家侧单位：从同一份 `enemyList` 定义创建 Companion，并加入该玩家的友方召唤物队伍。

因此，同一个 `summonKey` 不需要维护两份敌人 / Companion 数据。生命值、器官、卡牌和行动逻辑都来自同一份定义，只在实例化时改变阵营和控制者。

## 两种定义来源

### 复用敌人定义

适用于敌我双方都使用同一种单位的情况：

```typescript
params: {
    summonKey: "enemy_ant_soldier"
}
```

例如诱蚁信息素使用的蚁兵。敌人使用时是敌方蚁兵；玩家侧使用同一个效果时，会创建同源的友方 Companion。

### 使用独立 Companion 定义

适用于只存在于玩家一方、没有对应敌人定义的召唤物：

```typescript
params: {
    companionKey: "companion_stone_golem"
}
```

这类定义写在 `src/static/list/target/companionList.ts`。例如小石怪和分化子体。

同一个效果不要同时填写 `summonKey` 和 `companionKey`。前者表示复用敌人定义，后者表示使用独立 Companion 定义。

## 参数

| 参数 | 适用 | 说明 |
| --- | --- | --- |
| `summonKey` | 敌方 / 玩家 | `enemyList` 中的单位 key；玩家侧会转换为同源 Companion |
| `companionKey` | 玩家侧 | `companionList` 中的独立 Companion key |
| `count` | 敌方召唤 | 召唤数量，默认 1 |
| `duration` | 召唤物 | 持续回合数；召唤单位获得 `temporarySummon`，到期后消灭 |
| `successStateKey` | 需要使用标记时 | 召唤成功后给召唤者添加的状态，只在至少召唤成功一个单位时生效 |

示例：

```typescript
{
    key: "summon",
    params: {
        summonKey: "enemy_ant_soldier",
        count: 1,
        duration: 4,
        successStateKey: "pheromoneLureUsed"
    }
}
```

## 召唤物行为

召唤物沿用 `Enemy` 的行动逻辑：卡牌、器官和 `behavior` 都从定义中读取。玩家侧的 Companion 会设置为自动行动，并由战斗系统在玩家单位行动后安排行动。

召唤物是否显示意图、血条尺寸和目标权重属于 Companion 实例配置：

```typescript
{
    targetWeight: 1,
    autoAct: true,
    showIntent: true,
    uiSize: "small"
}
```

敌方召唤单位默认沿用敌人的意图系统；不需要意图的友方召唤物可以在 Companion 定义中关闭 `showIntent`。

## 生命周期

- 友方召唤物和敌方召唤单位都只存在于当前战斗。
- 战斗结束时由战斗系统统一清理，不应把它们写入玩家存档或局外资源。
- `duration` 是回合持续时间，不是战斗数量；召唤单位获得 `temporarySummon`，战斗结束或到期时消灭。
- `removeCompanion` / `removeSummonedCombatant` 用于效果主动消灭召唤物。消灭不会走普通死亡流程。

## 常见错误

### 不要使用旧的独立效果入口

数据中不要再写：

```typescript
{ key: "summonEnemy" }
{ key: "summonCompanion" }
```

统一使用 `summon`，否则同一张卡牌无法根据使用者阵营复用。

### 不要复制同一个单位的两份定义

如果敌人和玩家侧召唤物本质相同，应使用 `summonKey` 复用 `enemyList` 定义。只有行为、卡牌或器官确实不同，才创建独立的 Companion 定义。

### 成功标记必须绑定召唤效果

“本场只能召唤一次”之类的状态应使用 `successStateKey`。不要把 `applyState` 作为召唤效果后的独立步骤，否则召唤失败时仍可能给错误的目标添加标记。
