# 地图系统 Map

地图系统在每层生成一张多路径节点图（类杀戮尖塔），玩家沿有向边前进，节点即房间。核心分工：MapNode 是节点数据，FloorMap 管拓扑与状态，MapGenerator 按 FloorMapConfig 造图，FloorManager 包装成运行时入口。

源文件：
    节点：`src/core/objects/system/map/MapNode.ts`
    地图：`src/core/objects/system/map/FloorMap.ts`
    生成器：`src/core/objects/system/map/MapGenerator.ts`
    统一导出：`src/core/objects/system/map/index.ts`
    配置类型：`src/core/types/FloorMapConfig.ts`
    默认配置：`defaultFloorMapConfig`（同上文件）
    伪随机：`src/core/utils/SeededRandom.ts`
    UI：`src/ui/page/Scene/running/MapView.vue` + `MapOverlay.vue`

## MapNode

```typescript
interface MapNode {
    id:          string          // "{layer}-{index}"
    layer:       number          // 0-based
    roomType:    RoomType
    roomKey:     string          // lazy 类型初始为 ""
    x:           number          // 0.0-1.0，供 UI 定位
    connections: string[]        // 下层节点 id 列表
    state:       "locked" | "available" | "current" | "completed"
}
```

**state 是内联字面量**，不是独立 type export。

工具函数：`createMapNode(config)` / `serializeMapNode(node)` / `deserializeMapNode(data)`。

## FloorMap

```typescript
class FloorMap {
    constructor(totalLayers: number)

    addNode(node)                            // 建图阶段用
    getNode(id)              → MapNode|null
    getLayer(layer)          → MapNode[]
    getAllNodes()            → MapNode[]

    initialize(startId)                       // 设置起点、reset 状态
    getCurrentNode()         → MapNode|null
    getNextNodes()           → MapNode[]      // current 可达的下层节点
    moveToNode(id)           → boolean        // 只允许走 connections 中的节点

    getParentNodes(node)     → MapNode[]      // 上层能到该节点的
    getAllPaths(startId)     → MapNode[][]
    validateConnectivity(id) → boolean

    serialize()              → JSON
    static deserialize(json) → FloorMap
}
```

**移动约束**：`moveToNode(id)` 只在目标节点属于 `getNextNodes()` 或 `devMode` 时成功；成功后旧 current 变 completed、目标变 current、其他 nextNodes 变 locked。

## MapGenerator

```typescript
class MapGenerator {
    constructor(config: FloorMapConfig)

    generate()               → FloorMap
    assignLazyRoomKey(node)  → string          // 玩家进入 lazy 类型节点时调用
}
```

生成失败会重试（`validationStrategy.maxRetries`）；`fixOnFailure: true` 时可对违规节点原地修正。

## FloorMapConfig

四段结构：

```
基础结构
    layers:              number          总层数
    nodesPerLayer:       {min, max, weights?}   每层节点数；有 weights 按权重抽
    nodeCountRules:      { startLayer: number | {min, max}, useDynamicMiddleRange, bossLayer }
    connectionDensity:   {min, max}      每节点向下连接数

房间分配
    roomTypeWeights:       Record<RoomType, number>     默认权重
    layerSpecificWeights:  Record<layer, weights>       层级覆盖
    layerLayouts:          Record<layer, { roomTypes? | roomKeys? | fillType? }>   完全指定；fillType 铺满该层
    roomAssignmentStrategy:
        lazyTypes:          ["battle", "event"]         进入时才分配 roomKey
        eagerTypes:         ["pool", "blackStore"]      生成时立即分配
        exhaustionStrategy: { [roomType]: "reset" | ... }
        trackUsedRooms:     boolean
        easyBattleCount:    number                      前 N 场实际进入的普通战斗走弱池，默认 3

约束规则
    constraints.global:
        minCount:   Record<RoomType, number>
        maxCount:   Record<RoomType, number>
        minSpacing: Record<RoomType, number>            两个同类型节点最小层间距
    constraints.placement:
        parent:  { noSelfFollow: RoomType[] }           不允许接同类型的父节点
        sibling: { uniqueInLayer, maxSameTypeInLayer, requireDiversity }

其他
    validationStrategy: { maxRetries, fixOnFailure, revalidateAfterFix, throwOnFailure }
    nodePositionConfig: 节点水平位置计算
    roomPools:          生成期消费。battles 是普通池，easyBattles 是弱池（前 N 场实际进入的普通战斗），bossBattles 给末层 Boss
    seed:               不要在此处填！走 GameRun.seed
```

## 默认 defaultFloorMapConfig

从 `@/core/types/FloorMapConfig` 直接 import 使用：

```
结构        15 层（0-14），起点层 2~4 个节点，中间层 2/3/4/5 权重 5/45/35/15，Boss 层 1 节点，1-3 条向下连接
第 0 层     只出战斗
前 5 层     不出现精英（`run.ts` 的 layerSpecificWeights 覆盖）
第 7 层     `fillType: "treasure"`，该层每个节点都是宝箱
第 14 层    `fillType: "pool"`，Boss 门前整层水池
末层        roomTypes: ["bossBattle"]，从当前层 bossBattles 抽一个（eager）
约束        至少 3 水池 + 2 商店；至多 5 精英；精英/水池/商店不连续、每层至多 1 个
战斗不重复  已发出的 roomKey 记在 MapGenerator.assignedRoomKeys，池耗尽才按 exhaustionStrategy 重置该池
```

房间池优先用当前 Floor 的 `roomPools`。仍为空的池才从 roomRegistry 填充：`encounterPool: "easy"` 进弱池，其余非 test 的普通战斗进 battles。事件和 Boss 必须在 floorList 里显式列出，不要依赖空池自动灌注册表（会把 STS 事件带进来）。

## FloorManager 集成

```typescript
floorManager.generateMap(configOverride?)  → FloorMap    // 先并当前 Floor.roomPools，再叠 override，空池才从注册表补
floorManager.getCurrentMap()               → FloorMap | null
floorManager.getCurrentMapNode()           → MapNode | null
floorManager.getNextMapNodes()             → MapNode[]
floorManager.moveToMapNode(nodeId)         → boolean
floorManager.getMapGenerator()             → MapGenerator | null   // 用于 assignLazyRoomKey
```

节点进入流程：

```typescript
async function onNodeClick(node: MapNode) {
    nowGameRun.floorManager.moveToMapNode(node.id)
    if (!node.roomKey) {                                  // lazy 类型
        const gen = nowGameRun.floorManager.getMapGenerator()
        node.roomKey = gen.assignLazyRoomKey(node)
    }
    await enterRoom(node.roomKey, node.layer)
}
```

## 种子系统

种子挂在 `GameRun`：

```typescript
class GameRun {
    seed: string                              // 未传就用 Date.now().toString()
    rng:  SeededRandom                        // markRaw 保护
}
```

`SeededRandom` 主要方法：

```
next()              → [0,1) 浮点
nextInt(min, max)   → 含端整数
nextFloat()         → [0,1)
nextFloatRange(min, max)
choice(array)                              // 从数组随机取一个
choices(array, count)                      // 无放回
choicesWithReplacement(array, count)       // 有放回
shuffle(array)                             // Fisher-Yates
derive(suffix)      → SeededRandom         // 派生独立但确定的子生成器
```

派生用法：

```typescript
const battleRng = nowGameRun.rng.derive("battle")
const lootRng   = nowGameRun.rng.derive("loot")
```

**规则**：地图生成走 `nowGameRun.seed`——不要在 `FloorMapConfig.seed` 手动填值。相同 seed 生成相同地图。

## Lazy vs Eager 分配

```
lazy   battle / event         生成时 roomKey = ""，玩家进入时 assignLazyRoomKey 分配
eager  pool / blackStore / bossBattle / treasure
        生成时立即用 seed + nodeId 分配，可提前展示信息
        Boss 节点用战斗 `name` 黑体加粗写成【炙渣王】，不用图标

普通战斗弱池
    战斗数据标 `encounterPool: "easy"` 的进 `easyBattles`，其余非 test 的进 `battles`
    进入房间时才分配。本层已打过的普通战斗（roomType battle）不足 `easyBattleCount`（默认 3）场，从弱池抽
    精英 / Boss 不计次数。没走进去的弱怪节点不算打过
    第 4 场起只用 `battles`，弱池剩余场次不混进去
    弱池抽空则回落到 `battles`
```

## 添加约束或权重规则

```
1. 在 FloorConfig.mapConfig 里覆盖需要变化的字段（不必写全部）
2. floorManager.generateMap() 会合并 defaultFloorMapConfig
3. 如果需要自定义房间布局，用 layerLayouts 完全指定该层
```

## UI 联动

```
setShowMapCallback(cb)  step.ts 提供，让 MapOverlay 在 completeAndGoNext 后自动显示
completeAndGoNext()     完成房间 → 弹地图 → 玩家点节点 → 进入下一房间
```

战利品点「前进」只打开地图，不清空奖励。关掉地图后没领完的还能领。真正点节点进入下一房间时，才自动领走金币等；药水栏满领不走的会跳过并记日志。

地图节点一律灰度。当前和下一个可选节点最深，可选节点轻微放大缩小（hover 圆圈一起放缩）；已经走过的略深灰，其余未走到的浅灰。
