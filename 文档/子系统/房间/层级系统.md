# 层级系统 Floor

层级（Floor）是游戏的一级容器：一次 Run 依次穿越多个 Floor，每个 Floor 有自己的房间池、生成规则、地图配置、难度倍率与解锁条件。房间是 Floor 的组成单元，Floor 之间通过 `nextFloors` 有向连接。

源文件：
    类型：`src/core/types/FloorConfig.ts`
    地图类型：`src/core/types/FloorMapConfig.ts`
    数据：`src/static/list/floor/floorList.ts`
    注册表：`src/static/registry/floorRegistry.ts`
    管理器：`src/core/objects/system/FloorManager.ts`
    单例访问：`nowGameRun.floorManager`（`src/core/objects/game/run.ts`）

## 定位

```
Floor         层级容器           管房间池、地图、难度倍率、解锁条件
Room          房间               战斗/事件/水池等单个游戏节点
FloorMap      本层地图           15 层节点图，玩家沿边走
FloorManager  运行时状态         当前层、房间历史、地图缓存
```

一句话：Floor 是"这一层长什么样"的**数据配置**，FloorManager 是"我现在在哪一层"的**运行时状态**。

## FloorConfig 结构

```typescript
interface FloorConfig {
    key:          string           // "floor_1"
    name:         string           // "底层"
    order:        number           // 用于排序
    description?: string           // 楼层选择界面用

    roomPools: {
        battles:          string[]
        easyBattles?:     string[]   // 弱怪池，前 N 场实际进入的普通战斗
        eliteBattles:     string[]
        elitePlusBattles: string[]
        bossBattles:      string[]
        events:           string[]
        blackStores:      string[]
        pools:            string[]
        treasures:        string[]
    }

    // 新地图系统（推荐）
    mapConfig?:            FloorMapConfig
    selectionRules?:       SelectionRuleConfig[]
    exhaustionStrategies?: { [roomType: string]: ExhaustionStrategy }
    bossStep?:             number             // Boss 步数（如"Boss 前必定水池"用）
    entranceEvent?:        string             // 进入层级触发的事件

    // 旧系统（保留兼容，优先级高于 roomPools 权重生成）
    roomLayout?:          RoomSlotConfig[]
    roomGenerationRules?: RoomGenerationRule[]

    // 层级之间的路径
    nextFloors?:              string[]
    nextFloorSelectionMode?:  "auto" | "random" | "manual"

    // 解锁与难度
    unlockCondition?: (player: Player) => { unlocked: boolean; reason?: string }
    modifiers?: {
        enemyHealthMultiplier?: number
        enemyDamageMultiplier?: number
        rewardMultiplier?:      number
    }
}
```

**注意**：类型定义比老稿多出 `eliteBattles / elitePlusBattles / treasures / mapConfig / selectionRules / exhaustionStrategies / bossStep / roomLayout / entranceEvent / description` 十项。老稿只覆盖旧 4 池方案（battle/event/blackStore/pool），已过时。

## nextFloorSelectionMode 三态

```
"auto"     只有 1 个 → 自动进入；多个 → 显示选择界面   （默认）
"random"   从列表随机选一个自动进入
"manual"   必须显示选择界面，即使只有 1 个
```

## roomLayout 与 RoomSlotConfig

`roomLayout` 优先级最高：在指定步数直接强制某房间。当前 `floor_1` 用这一机制把第 1 步固定为 `init_game_start`：

```typescript
roomLayout: [{
    step: 1,
    roomKey: "init_game_start",
    priority: 100
}]
```

`RoomSlotConfig` 支持 4 种模式，通过字段组合选择：

```
step             number | number[] | "any"        触发的步数

模式 1 固定房间   roomKey: string
模式 2 候选列表   candidates: { roomKeys, selectCount, selectMode, weights, allowDuplicates }
                selectMode: "random" | "all" | "weighted" | "sequential"
模式 3 类型池     type: RoomType [, pool: string[], count: number]
模式 4 自定义     generator: (ctx) => string | string[]
priority          数字越大越优先，多个规则匹配同一步时用
```

## 已注册的 4 层

```
floor_1  底层    精英/Boss/事件已挂第一层内容；走廊战斗仍是 battle_normal_rocker；黑市+水池+宝箱
floor_2  中层    暂复用第一层房间池；敌人生命 x1.2、伤害 x1.1
floor_3  高层    暂复用第一层房间池；敌人生命 x1.5、伤害 x1.3
floor_4  终层    暂复用第一层房间池；unlockCondition: 需 3 个印记；敌人 x2.0/x1.5、奖励 x1.5
```

事件池是显式 12 个核心事件（神秘商人、宝箱、治愈之泉、湖中精灵、机缘之神、胚胎发育、废弃神龛、收藏家、移植手术、饲育者、孵化室、献祭坛），不含 STS 复制事件、不含苏生。

Boss 池是 3 个第一层 Boss：炙渣王、疫孢菌母、废铁战甲。末层地图节点类型是 `bossBattle`，生成时从 `bossBattles` 抽一个。

`generateMap` 会把当前 Floor 的 `roomPools` 并进地图配置；空池才从 roomRegistry 补。事件/Boss 不要留空数组，否则事件会把注册表里所有 event（含 STS）灌进来，Boss 则抽不到房间。

## FloorManager 关键 API

```typescript
floorManager.getCurrentFloor()          → number   （楼层数、递增计数）
floorManager.getCurrentFloorKey()       → string | null
floorManager.getCurrentFloorConfig()    → FloorConfig | null
floorManager.setCurrentFloor(floorKey)  // 切换层级；会重置 roomHistory

floorManager.getRoomHistory()           → RoomType[]
floorManager.getMapGenerator()          → MapGenerator | null   （新地图系统入口）
```

**已弃用**：`generateNextFloorRoomOptions(count, player?)` 标注 `@deprecated`——现在走地图系统（`FloorMap` + `MapGenerator`），不再用"生成 N 个房间选项让玩家选"这套。老稿的用例已过时。

## 层级切换流程

Boss 战胜利后：

```
1. 读 currentFloor.nextFloors 与 nextFloorSelectionMode
2. filter：unlockCondition 未满足的层跳过（同时通过 result.reason 反馈）
3. 剩下 0 个     → 游戏结束
   1 个 + auto  → 自动 setCurrentFloor
   1 个 + manual → 显示选择界面
   多个 + auto  → 显示选择界面
   多个 + random → 随机 setCurrentFloor
   多个 + manual → 显示选择界面
```

`setCurrentFloor` 内部会 reset `roomHistory`——每层的连续战斗次数、连续非战斗次数等指标独立计算。

## 解锁条件示例

```typescript
unlockCondition: (player) => {
    const markCount = countPlayerMarks(player)
    return {
        unlocked: markCount >= 3,
        reason:   markCount < 3
            ? `需要 3 个印记（当前 ${markCount}/3）`
            : undefined
    }
}
```

回调无副作用即可写任意条件：印记数、金币、遗物、器官组合……返回 `reason` 供 UI 展示给玩家。

## 难度倍率状态

`modifiers` 目前**只是配置**，需要业务代码在敌人生成/奖励生成时读取并应用。项目里还没有统一的 modifier 应用点——引用它的地方要自行 `getCurrentFloorConfig().modifiers?.enemyHealthMultiplier` 后 乘算。

## 添加新层级

```
1. 在 floorList.ts 里加一项 FloorConfig
2. 在上一层的 nextFloors 里挂上新 key
3. initAllFloors() 会自动把 floorList 全部注册
```

不需要改任何管理器代码。分支路线（`nextFloors: ["floor_a", "floor_b"]` + `manual`）与解锁条件（`unlockCondition`）都靠数据配置。
