# 印记系统 Mark

印记是玩家永久获得的**特殊标记**，通过挂载 status（0/1 flag）实现，并在左上角 UI 显示。设计目标：轻量级、可 Mod 扩展、UI 自动化。

源文件：
    类型：`src/core/types/MarkConfig.ts`
    注册表：`src/static/registry/markRegistry.ts`
    印记列表：`src/static/list/mark/markList.ts`
    工具函数：`src/core/hooks/mark.ts`
    UI：`src/ui/page/Scene/running/Top/index.vue`

## 定位

印记 ≠ 遗物 ≠ 器官。区别：

```
遗物 Relic    是 Entity，有 interaction，占背包/展示，可撤销
器官 Organ    是 Target，绑定部位，提供卡牌与被动
状态 State    战斗中的动态效果，可堆叠可清除
印记 Mark     跨整个 Run 存在，只有"有 / 无"两态，不撤销
```

一句话：印记是**跨房间生效的永久 flag**，用最小成本实现"某个玩家做过某件事"的记忆。

## MarkConfig 结构

```typescript
interface MarkConfig {
    key:          string          // 唯一 key
    name:         string          // 中文名
    description:  string          // 描述

    displayText:  string          // 左上角显示的文本
    displayColor: string          // 文本颜色（CSS 值）

    statusKey:    string          // 用于存 0/1 flag 的 status key

    onGain?: {                    // 获得时触发的一次性事件
        key:         string           // 事件 key
        effectUnits: EffectUnit[]     // 效果列表
    }

    triggers?:    TriggerMap      // 印记提供的被动触发器
}
```

**说明**：印记的存在与否用 `status[statusKey]` 的值判定（1 = 有，0/未定义 = 无）。这样 status modifier 系统自动带来响应式，UI 与逻辑读同一个源。

## 已注册印记

```
mark_blood      红色印记      已染血    水池染血获得，最大生命 -10
mark_treasure   宝箱印记      已开宝箱   金色 (#D4AF37)，无 onGain 效果（纯标记）
```

宝箱印记目前只是**打过某个宝箱**的记录，没有配 onGain。未来若要加"两次开同类宝箱触发额外效果"这类逻辑，就在宝箱事件里读 `hasMark(player, "mark_treasure")` 分支。

## API

```typescript
gainMark(player, markKey)
    重复调用无效（有印记时打日志退出）
    设 status flag = 1，触发 onGain 事件

hasMark(player, markKey)              → boolean
getPlayerMarks(player)                → string[]
countPlayerMarks(player)              → number
```

## 注册表

```typescript
markRegistry.registerMark(config)         // 单个
markRegistry.registerMarks(configs[])     // 批量
markRegistry.getMark(key)
markRegistry.getAllMarks()
markRegistry.hasMark(key)
markRegistry.clear()                       // 仅测试用
```

主流程注册：`initAllMarks()` 在启动阶段调用一次，把 `markList` 全注册进去。Mod 侧可继续 `registerMark(customConfig)` 追加。

## UI 展示机制

`src/ui/page/Scene/running/Top/index.vue` 的 stateList computed 每次 render 遍历 `markRegistry.getAllMarks()`，读 `getStatusValue(player, mark.statusKey, 0) === 1` 判定是否显示。

```
自动响应        新注册印记不需要改 UI，getAllMarks() 下次求值就带上
自动响应式      status 值变化触发 computed 重算
```

## 加新印记

```
1. 在 markList.ts 里追加一个 MarkConfig 对象
2. 在需要给玩家授予的地方调用 gainMark(player, "mark_xxx")
3. UI 无须改动
```

如果需要被动效果，加 `triggers`：

```typescript
{
    key: "mark_hunter",
    name: "猎手印记",
    description: "对精英伤害 +2",
    displayText: "猎手",
    displayColor: "green",
    statusKey: "ifHunterMark",
    triggers: [{
        key: "damage",
        how: "make",
        when: "before",
        importantKey: "hunter_boostVsElite",
        action: "..."
    }]
}
```

**注意**：目前代码里没有印记 triggers 的挂载路径——`gainMark` 只处理 onGain，不挂 triggers。若要用 triggers 字段，需要先在 gainMark 里补上"将 triggers 挂到 player"的逻辑，或走独立机制。
