# 触发器上下文重命名提案

状态：已实现。Trigger 上下文只保留 `creator`、`host` 与受限 `.owner` 导航；`triggerSource`、`triggerOwner`、`triggerContext.source`、`triggerContext.owner` 已移除。

## 问题

现有 Trigger 上下文里的 `source`、`owner`、`triggerSource`、`triggerOwner` 来自不同历史路径，既可能表示物品及其持有者，也可能表示状态及其附着者，还可能与实际监听事件的实体混在一起。

蟾蜍皮的毒素减伤暴露了这个问题。器官自身的 trigger 监听到中毒造成的 damage 时，必须同时区分四个对象：器官、装备器官的玩家、实际挂载监听器的实体，以及正在被响应的 damage 事件。现有名字无法让内容作者仅凭数据判断该选哪个对象。

## 目标模型

事件与触发器是两套关系，必须分开。

```text
Event
    source / medium / target    被响应的原事件三方

Trigger
    creator                     定义并创建此触发逻辑的对象
    host                        实际 appendTrigger 的实体
```

对象的所属关系不是 Trigger 的字段。任何具有所属关系的参与者都通过 `.owner` 导航：

```text
trigger.creator.owner          Trigger 创建者的持有者
event.source.owner             原事件来源的持有者
```

没有所属关系的对象不伪造 owner。例如普通角色没有 owner；继续读取 `角色.owner.status(...)` 应给出包含对象和上下文的错误。

## 目标 DSL

```typescript
$trigger.creator                         // 定义 trigger 的器官、遗物、卡牌、State 或实体
$trigger.creator.owner                   // creator 的持有者/附着实体
$trigger.host                            // trigger 实际挂载、实际监听事件的实体
$this                                    // 当前声明式数据所属对象
$this.owner                              // 当前声明对象的持有者/附着实体

$event                                   // 当前被响应的原事件
$event.source
$event.medium
$event.target
```

完整读取示例：

```typescript
// 器官 A 挂在敌人 B 身上，响应事件 X
$trigger.creator                         // 器官 A
$trigger.creator.owner                   // 玩家
$trigger.host                            // 敌人 B
$event                                   // 事件 X
$event.source.hasTrait(toxic)            // 事件来源是毒素 State 时成立
```

裸 `$owner`、`$source` 不表示 Trigger 关系。Trigger 条件读取创建者或持有者时，分别写 `$trigger.creator` 与 `$trigger.creator.owner`；reaction 新事件的三方仍使用 `$source`、`$medium`、`$target`。

## 当前实现审计

`Organ.processInteraction()` 先以器官和器官持有者调用 `createTriggerByTriggerMap(this, owner, triggerDef)`，随后把结果挂到 `triggerTarget` 解析出的每个实体。这里的第一个参数是未来的 creator，第二个参数是 creator.owner；挂载循环中的 `mt` 才是未来的 host。

当前实现的关键缺口

    同一个 `triggerObj` 被复用并 append 到多个 `mt`。callback 不知道本次是由哪个 host 调起，因此无法正确实现 `$trigger.host`。
    `createTriggerByTriggerMap(source, target, item)` 的 target 在多数调用点是 creator.owner，但变量名与语义并未被类型约束。
    StateModifier 另行构造 condition context：state 是 creator，StateModifier.owner 是 creator.owner；其实际 host 同样没有成为显式字段。
    预览只接受 item 与 owner，未携带挂载 host。若实战新增 host 而预览不补齐，意图和数值预览会读到不同对象。

旧字段 `triggerSource`、`triggerOwner` 已完成迁移：前者改为 `triggerCreator`，后者改为 targetType 中的 `creatorOwner`。`creatorOwner` 是 `triggerCreator.owner` 的受限目标选择名，不是 Trigger 的运行时字段。

## 运行时契约

未来每一次 appendTrigger 都必须有自己的 TriggerRuntimeContext：

```typescript
type TriggerRuntimeContext = {
    creator: EventParticipant
    host: Entity
    definition: TriggerMapItem
}
```

creator 的 owner 不放入这份对象，由统一对象关系解析器按需读取。这样器官移植、State 移除、卡牌换堆时不会复制一份可能过期的 owner。

同一 creator 对多个 host 注册时，创建多个 TriggerUnit 或为每个 append 绑定独立 context；不得复用一个不含 host 的 callback。

## owner 关系

`owner` 是对象关系，不是 EntityAccessor。它返回参与者对象，允许继续导航：

```typescript
$trigger.creator.owner.current(health)
$event.source.owner.hasState(poison)
```

需要新增受限的对象导航解析，不向数据暴露任意对象字段或方法。允许的路径至少包含：

    `$trigger.creator`
    `$trigger.creator.owner`
    `$trigger.host`
    `$event.source` / `$event.medium` / `$event.target`

每一步都验证 participantType；无 owner、数组 owner 或不支持的后续 accessor 必须报明确错误。

## trait 边界

trait 当前只属于 State。`StateAccessor.hasTrait()` / `trait()` 是唯一合法入口。

`EntityAccessor.hasTrait()` 当前错误地复用了 tags，和 `hasTag()` 重复。实施本提案时删除 EntityAccessor 的 `hasTrait`，并更新错误提示、文档与类型，不为普通 Entity 引入 traits 概念。

## 迁移步骤

第一步
    建立 TriggerRuntimeContext，拆开 createTriggerByTriggerMap 的 creator、creatorOwner、host 参数；补全普通物品、State、Current、词条、预览等所有上下文构造点。

第二步
    在 ReferenceResolver 增加受限的 `$trigger.creator`、`$trigger.host`、对象 `.owner` 导航；为 State、Item 与无 owner 的 Entity 定义统一行为。

第三步
    新数据和手册改用新 DSL。旧 Trigger 字段已移除；触发器关系必须通过 creator、host、creator.owner 或 event 三方表达。

第四步
    审计 Mod API 与外部内容。旧 targetType 会在解析时找不到上下文，Mod 必须迁移为 triggerCreator、creatorOwner、triggerHost 或 eventSource/eventMedium/eventTarget。

## 验收场景

    器官 A 属于玩家、Trigger 挂在敌人 B：creator 为 A，creator.owner 为玩家，host 为 B。
    中毒 State 挂在玩家：creator 为 State，creator.owner 与 host 都为玩家；`$event.source.hasTrait(toxic)` 正常工作。
    一个器官对多个敌人挂 Trigger：每个触发 callback 读取到各自 host，不相互串值。
    预览和实战对同一 Trigger 的 creator、owner、host 解析完全一致。
    对普通角色访问 `.owner` 得到明确错误，而不是默认玩家或自身。
