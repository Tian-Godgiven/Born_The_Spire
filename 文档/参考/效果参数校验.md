# 效果参数校验

一个**可选**的类型/必填校验层，用于在 Effect 构造时严格校验 EffectUnit.params。设计原则：

    可选  未声明 schema 的效果完全跳过，不报警
    严格  声明后严格查，错了只报错，绝不擅自转型
    轻量  只覆盖能真正抓到 Mod 作者错误的类型
    统一  `$xxx` / `random(...)` 引用自动豁免

源文件：
    校验实现：`src/core/effects/validateEffectParams.ts`
    集成位置：`src/core/objects/system/effect/Effect.ts` L53-58
    schema 存放：随各效果声明在 `src/static/list/system/effectMap.ts` 的 EffectData 里

## 当前启用情况

**2026-07-08 状态**：`effectMap` 中 0 个效果声明了 `paramsSchema`——机制已实现但完全未启用。任何 Effect 都不会被校验。要启用某效果的校验，就在该效果的 EffectData 里加 `paramsSchema` 字段。

## Schema 结构

```typescript
interface EffectParamsSchema {
    [paramName: string]: ParamDef
}

interface ParamDef {
    type:         ParamType | ParamType[]         // 允许的类型，可联合
    required?:    boolean                          // 默认 true
    options?:     readonly (string | number)[]     // 枚举值（如 ["handPile", "discardPile"]）
    description?: string                            // 供文档生成
}
```

**注意**：**没有 `default` 字段**——默认值由效果函数内部自己处理，schema 不注入。**没有 `validate` 自定义函数字段**——只做类型与枚举校验。

## 参数类型 ParamType

### 基础类型

```
string / number / boolean / array / object / any
```

### 内容 key 类型（校验字符串是否已在注册表登记）

```
cardKey    → 查 cardList
organKey   → 查 organList
relicKey   → 查 relicList
potionKey  → 查 potionList
enemyKey   → 查 enemyList
eventKey   → 查 eventList
```

内容 key 类型是最有价值的校验——它能抓住"打错 key 名"这类问题，并给相近 key 提示：

```
效果 "addCardToHand" 的参数 "cardKey" 值不合法：
值: "original_card_00007"
（你是否想写 "original_card_0007"？）
```

## $ 引用豁免

值形如 `$xxx` 或 `random(...)`（走 `needsReferenceResolution`）的字符串直接放行——运行时才解析出真实值，编译期不做类型检查。用于：

```typescript
{
    key: "damage",
    params: {
        value: "$eventResult.damageValue"   // 运行时解析，校验豁免
    }
}
```

## 主 API

```typescript
validateEffectParams(effectKey, params, schema?) → { valid, errors }
    未传 schema 则返回 { valid: true, errors: [] }
    有 schema 就逐字段查

validateEffectParamsAndReport(effectKey, params, schema?) → boolean
    上面的封装：失败时通过 newError 弹错误提示
    不抛异常，避免游戏卡死
    Effect 构造函数用的是这个
```

## 使用示例

给某效果声明 schema：

```typescript
// src/static/list/system/effectMap.ts
{
    label: "把卡加入手牌",
    key:   "addCardToHand",
    effect: addCardToHand,
    paramsSchema: {
        cardKey: {
            type: "cardKey",           // 会查 cardList
            required: true,
            description: "要加入手牌的卡牌 key"
        },
        count: {
            type: "number",
            required: false,           // 可选
            description: "加入张数，效果函数内默认 1"
        },
        pile: {
            type: "string",
            required: false,
            options: ["handPile", "discardPile", "drawPile"],  // 枚举
        }
    }
}
```

联合类型：

```typescript
selectCount: {
    type: ["number", "array"],    // 数字或 [min, max]
    required: false
}
```

## 校验流程

```
1. 遍历 schema 每个字段
2. 缺失 → required 就报错，否则跳过
3. 值为 $引用 → 放行
4. 联合类型循环查，命中即通过；全部失败给出建议（内容 key 类型才有 suggestion）
5. 有 options 时校验枚举
6. 收集所有 errors 一次性返回
```

## 关键行为

```
零启用            当前无效果声明 paramsSchema，Effect 构造走 fast path，无开销
不改参数           校验只查不改；类型转换靠效果函数（Number/String 等）
容错              validateEffectParamsAndReport 失败仅报错，不阻断执行
测试环境豁免        懒加载注册表不可用时（例如启动早期），内容 key 类型直接放行
```

## 何时值得写 schema

    效果参数复杂  联合类型、必需字段较多
    面向 Mod 作者  希望抓错更早、提示更友好
    含内容 key    是 modder 最容易打错的字段类型

不必强求所有效果都写——单参数的原子效果（damage、drawCard 等）写 schema 收益低。
