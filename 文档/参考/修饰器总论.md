# 修饰器总论 Modifier

修饰器管理"实体在某时刻拥有什么、其属性/状态从何而来"。核心价值是**自动清理副作用**：给某物挂上后，物失去时它添加的属性变化、卡牌、触发器、状态一起消失，不需要手写"lose 时反向操作"。

源文件：
    基类：`src/core/objects/system/modifier/Modifier.ts`
    9 个子类：同目录下 `ItemModifier.ts` / `OrganModifier.ts` / `PotionModifier.ts` / `RelicModifier.ts` / `CardModifier.ts` / `EntryModifier.ts` / `ReserveModifier.ts` / `StateModifier.ts` / `StatusModifier.ts`
    Entity 挂载：`src/core/objects/system/Entity.ts`
    容器：`src/core/container.ts` 提供 `modifierManager` 单例

## 设计动机

举例：器官【厚皮】数据里只需声明"获得时 max-health +10"。你**不需要**写"失去时 max-health -10"——OrganModifier 会：

```
失去器官 → 找到该器官作为 source 挂上的所有属性修饰器 → 移除 → refresh 触发 Status 重算
```

原则：**修饰器负责撤销自己产生的效果**；数据侧只声明"要什么"，不用管"失去时怎样"。

## Modifier 基类

```typescript
class ModifierObj {                     // 存储在修饰器里的单元
    id:         string      // nanoid，用于按 id 移除
    source:     any         // 来源（Organ / Relic / Card / Event 等）
    ifDisabled: boolean = false
    disable() / able()
}

class Modifier<T extends {id: string}> {  // 修饰器管理器
    protected store: T[]

    add(t)     → () => void   // 返回移除函数，惯用做法
    delete(id) → boolean
    edit(id, newT)
    seach(id)                  // sic，源码拼写
    refresh()                  // 子类覆盖：重算持有者的状态
}
```

**惯用法**：调 `add(...)` 拿到返回的移除函数，等失去时机再调它——比记 id 再找更简单。

## 子类清单

九个具体修饰器，按管理对象分类：

```
Status 层
    StatusModifier      Status 内部持有，改 base/current 值      详见 [[属性系统]]

物品层（都 extends ItemModifier）
    OrganModifier       器官持有/失去/使用/损坏/修复
    RelicModifier       遗物持有/失去
    PotionModifier      药水持有/失去/使用

其他
    CardModifier        Chara 的牌库
    EntryModifier       实体的词条（如 attack / basic）
    ReserveModifier     储备资源（金钱、物质）
    StateModifier       Target 身上的状态（中毒、易伤等）
```

`Modifier.ts` 基类只解决"存储 + 增删改查 + refresh 钩子"，具体修饰器**不严格继承基类**（例如 ItemModifier 自成一套结构），但都遵循"add 返回移除函数"的惯例。

## 主要 API 一览

以下为核心方法真实签名。**注意所有 `acquire/lose` 命名与老稿的 `add/remove` 不同**。

### OrganModifier

```typescript
async acquireOrgan(organ, source, skipConfirm = false)
loseOrgan(organ, triggerLoseEffect = false)
useOrgan(organ, targets)
breakOrgan(organ)                          // 器官损坏（有内部状态的器官）
async repairOrgan(organ)                   // 修复
async upgradeOrgan(organ, options?)        // 升级；options.skipCost / options.lockedCost
```

### RelicModifier

```typescript
acquireRelic(relic, source, parentLog?)
async acquireRelicsFromKeys(keys[], source, parentLog?)
loseRelic(relic, parentLog?)
```

### PotionModifier

```typescript
removePotion(potion, parentLog?)              // acquire 走基类 acquireItem
removePotionByKey(potionKey, parentLog?)
getPotions() → Potion[]
getPotionByKey(potionKey) → Potion | undefined
usePotion(potion, useIndex = 0, targets)      // useIndex 支持一瓶多次使用的药水
```

### CardModifier

```typescript
async addCardsFromSource(source, cardKeys[], parentLog?) → Promise<Card[]>
removeCardsFromSource(source, parentLog?) → boolean          // 移除该 source 挂上的所有卡
removeCard(card) → boolean
getAllCards() → Card[]
getCardsFromSource(source) → Card[]
getAllSourcedCards() → Map<Entity, Card[]>
```

### EntryModifier

```typescript
addEntry(entryKey) → boolean | string
removeEntry(entryKey) → boolean
hasEntry(entryKey) → boolean
getEntries() → string[]
```

### ReserveModifier

```typescript
getReserve(reserveKey) → number
getAllReserves() → Map<string, number>
gainReserve(reserveKey, amount, source?) → number
spendReserve(reserveKey, amount) → boolean       // 返回是否成功；不足则失败
hasReserve(reserveKey, amount) → boolean          // 与老稿 canAfford 对应；spendReserve 不接 source
```

### StateModifier

```typescript
addState(stateData, stacks, source)
    stacks: number | Array<{key, stack}>
removeState(stateKey, triggerRemoveEffect = false)
changeStack(stateKey, stackKey, delta)
    目标没有该状态时返回 false 且不做任何事，只用于改已有层数
getState(stateKey) → State | undefined
hasState(stateKey) → boolean
getAllStates() → State[]
```

从无到有地叠加状态层数走 `gainStateStack`（`src/core/objects/system/State.ts`），
它在目标没有该状态时按 stateList 创建，已有时叠加 default 层。详见 [[实现参考手册]]。

### StatusModifier

不直接被外部调——通过 `Status.add(modifier)` 或 hook `changeStatusValue` 使用。详见 [[属性系统]]。

## 自动清理机制

以器官为例，`loseOrgan` 内部：

```
1. 走每张来自该 organ 的卡：removeCard
2. 找每个 source = organ 的 StatusModifier：调其 remove 回调 → Status.refresh
3. 找每个 organ 挂上的 Trigger：remove
4. 撤 work.grantStates 赠出去的状态层（按差额，不够则不扣成负数）
5. （可选）触发 lose 交互本身的一次性效果
```

`possess.effects` 里的 `applyState` **不会**在失去时自动撤销，那是一次性施加。生效期间要让持有者一直拥有某状态，写 `work.grantStates`。

数据侧的写法：

```typescript
// organ 数据
interaction: {
    possess: {
        target: { key: "owner" },
        effects: [
            { key: "changeStatusValue", params: { statusKey: "max-health", value: 10 } }
        ]
    }
}
// 不需要 lose interaction 去手动 -10；possess 生成的 StatusModifier 会被 loseOrgan 移除
```

**要写 lose 交互的场景**：仅当需要一次性主动效果（如"失去器官时抽 2 张卡"），不是清理副作用。

## markRaw 保护

Modifier 子类被存入 `entity.xxx` 时，若其内部持有 `ref()`（如 `StatusModifier` 的 snapshot 值、`ReserveModifier` 的 reactive reserves），必须 `markRaw`——否则 Vue 会解包 ref。项目中 `appendStatus` / `ensureStatusExists` / 各 Modifier 的构造已经内部处理，用户不常直接遇到。

自写代码若把 Modifier 塞进 reactive 容器：

```typescript
entity.statusModifiers.push(markRaw(modifier))   // 正确
```

## 修饰器与效果

修饰器**不能**直接从游戏逻辑调——所有修饰器变更都应通过 effect（如 `changeStatusValue` / `gainReserve` / `addState` / `getOrgan`）走事件系统。这样修饰器变更会被日志、触发器、事务回滚等系统正确观察。

老稿写"修饰器的内容的变更只能通过 1. 效果添加/移除；2. 添加时返回的移除回调"，仍适用。

## 命名规范

```
acquire / lose        物品类（Organ / Relic / Potion）持有变更
add / remove          非物品类（Card / Entry / State / Reserve）内容变更
gain / spend          Reserve 特化，语义更贴近资源
use                   Potion / Organ 的主动使用
break / repair        有内部状态的器官（如废铁战甲器官）
```
