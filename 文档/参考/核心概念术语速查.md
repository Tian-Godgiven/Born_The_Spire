# 核心概念术语速查

单页快速对齐名词，逐项一句到三句。深入用法见每条末尾指向的详细文档。

## 执行流

### 操作 Operation
玩家的一次输入行为：打出卡牌、使用药水、结束回合、选目标、选事件选项等。每一次操作最多引发一个事务。

### 事务 Transaction
由操作/触发器/系统调用生成，用于组织一批 ActionEvent 的调度容器。状态机：created → gathering → organizing → doing。

### 事件栈 EventStack
Transaction 内部按 LIFO 顺序执行 ActionEvent 的栈。事件级联（`event.spawnEvent(child)`）就是把新事件推进当前栈。

### 过程事件 ActionEvent
一次实际发生的游戏事件。含 `source`（发起者）/ `medium`（媒介，如卡牌/器官）/ `target`（作用目标）/ `effects[]`。每个事件按 before → doing → after 走触发周期。详见 [[过程事件系统]]。

### 效果单元 EffectUnit
数据配置里 JSON 形式的效果描述：`{ key, params, targetSpec? }`。运行时由 EffectUnit 派生出一个 Effect 对象。

### 效果 Effect
运行时的效果执行体，含参数和目标。真正修改状态的是注册在 `effectMap` 的 EffectFunc。EffectFunc 不得绕过事件系统访问状态。详见 [[效果开发指南]]。

## 实体家族

### 实体 Entity
所有游戏对象的基类。字段：`status` / `current` / `trigger` 等。玩家角色、敌人、器官、卡牌、遗物、药水都是 Entity 的子类。

### 目标 Target
Entity 的子集：能被事件 `target` 字段引用的对象。当前有三种：Player / Enemy / Organ。UI 选择目标见 [[choose-target-system]]。

### 玩家 Player / 敌人 Enemy
Target 的两大实战阵营。Enemy 带 AI 决策（[[enemy-ai-system]]），Player 由玩家操作。

### 器官 Organ
既是 Target 也具备 Item 的部分特征。玩家的构建核心：击败敌人 → 选器官 → 器官提供卡牌与被动。见 [[organ-system]]。

### 物品 Item
非目标类实体的父类，衍生出 Card / Potion / Relic 三种子类。

## 属性与状态

### 属性 Status
基于修饰器计算的实体属性，含 `base`（永久）+ `current`（临时）两层。数值型属性用 `Status.value` 读。放入 `entity.status` 时必须 `markRaw()`。

### 当前值 Current
高频变化的即时值（当前 HP / 当前能量 / mass 等）。不走修饰器系统，直接由事件效果改。

### 状态 State
挂在实体上的动态效果单元（易伤、力量、暴怒等）。可含 `stackChange` / 触发器 / modifier。数据格式和管理见 [[状态系统开发指南]]。

### 词条 Entry
挂在卡牌/器官/遗物上的**装饰性属性**。可覆盖方法（如 `getAfterUseEffect`）、挂 trigger 或改 status。EntryModifier 自动管理。见 `[[词条系统]]`。

### 印记 Mark
标签式静态标记，只用作分类/筛选（如卡牌 tag、器官 tag、稀有度）。不带触发器与效果。

## 触发器与响应

### 触发器 Trigger
按 `when × how × key` 三维定位事件的响应回调。`when: before/on/after`；`how: make/via/take`；`key`: 事件 key（如 `damage` `turnStart`）。详见 [[触发器系统]]。

### 反应 reaction / 动作 action
声明式响应写法：在 interaction 里配 `triggers[]`，每个触发器写 `action` + `reaction` 即可，不用手写 callback。见 [[反应系统详解]]。

### 修饰器 Modifier
自动化的属性/内容变更载体。分类：StatusModifier（属性）/ StateModifier（状态）/ CardModifier / EntryModifier / OrganModifier / ContentModifier。**器官/遗物移除时关联 modifier 自动撤销，不需要手工清理**。

## 内容组织

### 交互 Interaction
Card / Organ / Potion / Relic 配置里的行为分组。常见 key：`use` `get` `lost` `inHand` `possess` `work` `broken` 等。每种 key 决定挂载/执行时机，内部可含 `effects` / `triggers` / `modifiers`。

### 注册表 Registry
所有内容类型（卡牌/器官/敌人/效果/状态/事件等）通过注册表管理。加新内容只改 `src/static/list/` 下的数据文件，不动核心逻辑。这是 Mod-First 架构的基础。

### 声明式 Declarative
用数据对象描述内容而不是写命令式函数。TriggerMap / ReactionMap / EffectUnit / TargetSpec 都是典型体现。项目原则：能写声明式就不写 callback。
