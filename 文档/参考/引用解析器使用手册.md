# 引用解析器使用手册

`ReferenceResolver` 是数据中的动态值入口。卡牌、器官、遗物、状态和事件不应为了读取运行时值各自写回调；在受支持的位置写引用字符串，系统会在拥有完整上下文时把它解析为数值、布尔值、字符串或对象。

源文件

    `src/core/utils/ReferenceResolver.ts` — 语法识别、随机数、全局值
    `src/core/types/TargetSpec.ts` — `$source`、`$this` 等参与者从何而来
    `src/core/types/EntityAccessor.ts` — `status()`、`stateStack()` 等实体读取方式
    `src/core/types/StateAccessor.ts` — 当参与者本身是 State 时的读取方式

本手册是引用语法的权威说明。场景手册只保留“要做某种效果该抄哪段数据”。

---

## 先判断是否该用它

引用解析器只负责**读取**或生成一个值，不能直接改游戏状态。

适合

    攻击值等于器官上的属性
    施加状态的层数等于本次受伤数值
    条件判断持有者是否有某个器官
    从随机区间摇一个数

不适合

    数值需要算术组合，例如“本次伤害的 25%”。引用不支持 `* + - /`；优先使用已有 EffectFunc 的 `percent`、`multiplier` 等参数，实在没有再写专属 EffectFunc
    需要修改属性、状态、牌堆或实体。写 EffectUnit，不要在引用里塞命令
    需要在 Effect 真正执行那一刻才读取的普通值。普通引用在 Effect 创建时固定，见“求值时机”

## 能写在哪里

### EffectUnit 的 params

最常见的位置。值必须是字符串：

```typescript
{ key: "attack", params: { value: "$this.status(damage)" } }
{ key: "applyState", params: { stateKey: "poison", stacks: "random(1,3)" } }
```

Effect 创建时会调用 `ReferenceResolver.needsResolution()`。它同时识别 `$...` 和 `random(...)`；不要自行用 `startsWith("$")` 判断，否则会再次遗漏随机表达式。

### condition

条件表达式左右两侧都可引用。推荐使用 `$this` 表示声明对象、`$this.owner` 表示其持有者，见下一节。

```typescript
condition: "$this.owner.hasOrgan(enemy_organ_poison_gland)"
condition: "$this.status(opening-armor) > 0"
condition: "$allEnemies.any.hasState(poison)"
```

### 可解析配置

效果预览、角标和少数系统也会直接调用解析器。只有调用点明确使用 `resolveReference` 或 `needsReferenceResolution` 的字段才可写引用。新字段不能因为“它是字符串”就假定会自动解析。

## 参与者与上下文

先确定你要读的对象，再写 accessor。最容易出错的不是 `status()`，而是对象选错。

### Effect 参数中的对象

`$this`
    当前声明式数据所属的对象。Effect 参数、Trigger、reaction 和 interaction 中通常是定义这些数据的卡牌、器官、遗物或 State。

`$source` / `$medium` / `$target`
    当前 reaction 生成的新事件的三方。它们由 `sourceTargetType`、`mediumTargetType`、`targetType` 决定；想读持有者，先把对应一方指向持有者。

`$triggerEffect`
    刚刚触发本 reaction 的 Effect。通常用于读取这一次攻击、施加状态或抽牌的参数。

`$event.source` / `$event.medium` / `$event.target`
    当前事件原始三方。仅在确实需要跳过 reaction 新事件、回看原事件时使用。

`$event.source` 可能是 State。State 只能使用 `hasTrait()`、`trait()`、`stateStack()`、`key()`、`label()` 等 StateAccessor；普通 Entity 使用 `status()`、`current()`、`hasTag()` 等 EntityAccessor。毒素类判断的现行写法是 `$event.source.hasTrait(toxic)`。

`$trigger.creator` / `$trigger.host`
    `creator` 是定义此 Trigger 行为的物品、State 或实体；`host` 是实际 `appendTrigger`、监听事件的实体。Trigger 关系只使用这两个名字。
    `creator.owner` 是 creator 的持有者或附着实体。仅支持一层受限导航，随后必须调用对应对象的 accessor：`$trigger.creator.owner.current(health)`、`$trigger.host.hasState(poison)`、`$event.source.owner.hasState(poison)`。
    没有 `owner` 的对象不会被默认映射到自身或玩家，解析会给出上下文错误。`$trigger.creator`、`$trigger.host`、`$event.source`、`$event.medium`、`$event.target` 本身也可作为对象引用传给支持对象参数的位置。

`$this`
    当前声明式数据所属的对象。物品的 trigger、reaction 与 interaction 中是该物品；State 的声明中是该 State。它不从事件三方推断，而由声明入口显式传递；普通事件没有指定时才以 `medium` 作为默认声明对象。
    普通内容优先使用 `$this.status(x)` 与 `$this.owner.current(health)`；需要区分 Trigger 的定义者和实际挂载者时才使用 `$trigger.creator` / `$trigger.host`。

### condition 中的对象

条件中也使用同一套 `$this` 语法：

    `$this` — 定义该条件的声明对象
    `$this.owner` — 声明对象的持有者，即玩家或敌人（对象确实有 owner 时才可用）
    `$event.source` / `$event.target` — 原始事件参与者

判断“玩家装备了毒腺”写 `$this.owner.hasOrgan(...)`；读取“毒腺本身的 poison-gain”写 `$this.status(poison-gain)`。

### 真实例子：蟾蜍皮受击施毒

要把“本次攻击伤害”作为中毒层数，读的是触发 Effect，不是器官属性：

```typescript
interaction: {
    work: {
        target: { key: "self" },
        effects: [],
        triggers: [{
            when: "after",
            how: "take",
            key: "attack",
            action: "toadSkinPoison"
        }]
    }
},
reaction: {
    toadSkinPoison: [{
        targetType: "eventSource",
        key: "applyState",
        effect: [{
            key: "applyState",
            params: {
                stateKey: "poison",
                stacks: "$triggerEffect.params(value)"
            }
        }]
    }]
}
```

`targetType` 决定新事件施加给谁；`$triggerEffect.params(value)` 读取触发它的原攻击数值。两者是独立选择，不能用一个代替另一个。

## 语法速查

### 读取事件与 Effect

```typescript
$eventResult(key)                  // 当前事件先前保存的结果
$event.info(key)                   // 当前事件 info 中的字段
$triggerEffect.params(key)         // 触发本 reaction 的 Effect 参数
$triggerEffect.target.current(health) // 该 Effect 所在事件的目标实体
$triggerCard.hasTag(attack)        // 触发事件的 medium 是卡时读取；非卡返回 false
```

`$triggerEffect.params(value)` 在 Effect 构造时会延迟保留，在真正执行这个 reaction 时才取值。它专门解决“这一次触发的参数”问题；不要把它当作任意延迟读取工具。

### 读取实体

语法总是 `$参与者.accessor(参数)`。函数式 accessor 必须带括号；少量稳定的基础属性允许使用无括号语法，例如 `$this.level`。

### 直接属性访问

实体只开放明确的基础属性白名单，当前包括：`level`、`rarity`、`itemType`、`key`、`label`。

```typescript
condition: "$this.level >= 2"
condition: "$this.rarity == rare"
```

这不是通用的 JavaScript 属性读取：对象、数组、方法和未列入白名单的字段都不能通过引用表达式访问。动态状态请继续使用 `$this.status(key)` 或 `$this.current(key)`；不要写成 `$this.level()`。

```typescript
$this.status(armor-gain)
$target.current(health)
$source.stateStack(poison)
$event.source.hasRelic(relic_x)
$trigger.creator.owner.hasState(poison)
$trigger.host.current(health)
$this.status(used)
$this.owner.reserve(gold)
$trigger.creator.owner.organCount()
```

内置 accessor

    `status(key)` — Status 值
    `current(key)` — Current 值，如 health、energy、armor
    `hasStatus(key)` / `hasState(key)` — 是否存在且有效
    `stateStack(stateKey?)` — 状态层数；`stateStack(poison.duration)` 读指定 stack
    `hasOrgan(key)` / `hasRelic(key)` / `hasCard(key)` / `hasTag(key)`
    `pileCount(pile)` — `hand` / `draw` / `discard` / `exhaust`
    `reserve(key)`、`itemType()`、`isTemporary()`、`stateCategory()`
    `organCount()`、`removableOrganCount()`、`cardCount()`、`organsWithCardsCount()`

`state(key)` 返回 State 对象本身，绝不是层数；绝大多数数据应使用 `stateStack(key)`。

### 集合、全局与随机

```typescript
$allEnemies.any.hasState(poison)   // 至少一个敌人满足
$allEnemies.all.hasState(poison)   // 所有敌人满足
$scene                              // combat 或当前 room.type
$battle.turn                        // 当前战斗回合数
random(5,10)                        // 两端为整数时返回整数，否则返回浮点数
```

集合不能直接写 `$allEnemies.status(...)`。布尔判断用 `.any` 或 `.all`；需要挑选实体则使用 reaction 的 `targetType: "allEnemies.random"`，那是 `TargetSpec` 的目标管道，不是引用表达式。

`random(min,max)` 不带 `$`，必须完整写在一个参数值中。它不能写成 `random($x, 5)`，参数目前只能是数字字面量。

## 求值时机与错误处理

普通 Effect 参数在 `new Effect()` 时解析一次。后续 Effect、触发器改变了场上数值，已创建的 Effect 不会重新读取。

    要读当前触发的 Effect 参数：`$triggerEffect.params(key)`，它会延迟到执行时解析
    要每次触发都随机：每次创建一个 Effect 并写 `random(min,max)`
    要在执行瞬间按最新状态算复杂值：写 EffectFunc，在函数内读取状态

解析失败会记录带上下文的错误。不要把 `undefined` 当作 0；先确认参与者是否在该调用点存在、它是否为数组、accessor 的 key 是否真实注册。

## 扩展系统

先分清需要扩展的层。绝大多数新需求只需新增 accessor，不需要改 `ReferenceResolver`。

### 新增实体 accessor

适用：想让数据能读取任意实体的某个可复用值。

```typescript
import { registerAccessor } from "@/core/types/EntityAccessor"

registerAccessor("myMod_markCount", (_arg, entity) => {
    return Number((entity as any).status["mark-count"]?.value ?? 0)
})

// 数据中使用
"$this.myMod_markCount()"
```

名称必须带 Mod 前缀，避免覆盖内置或其他 Mod。返回值只能是 number、string 或 boolean；不要返回可变对象，也不要在 accessor 中修改游戏状态。

### 新增可引用参与者

适用：已有 accessor，但需要 `$myContextObject.status(x)` 这种新对象名。

调用方创建 context 时放入该字段，并在 `TargetSpec.ts` 的 `TargetContext` 和相关类型/解析逻辑中补齐。只有该调用点真的提供 `myContextObject` 时，引用才可用。不要把全局单例偷偷塞进解析器，避免同一数据在预览、事件和战斗中读到不同对象。

### 新增特殊语法

适用：语法不是“参与者 + accessor”，例如现有的 `$event.info(key)`、`$battle.turn`、`random(min,max)`。

修改 `ReferenceResolver.ts`：

    在 `resolve()` 或 `parseReference()` 增加完整匹配
    在 `needsResolution()` 同步识别该语法
    明确返回类型、缺少上下文时的错误与求值时机
    增加真实数据示例，并更新本手册和字段类型 `EffectParams`

新语法是底层能力，先提案确认再改。能通过 accessor 或 EffectFunc 表达时，不增加语法。

## 写数据前的检查

    这是读值还是改状态？改状态写 Effect，不写引用
    此位置是 condition 还是 Effect params？先确认 `$this` 是声明对象，再按需导航 `$this.owner`
    目标是物品、持有者、当前事件三方，还是触发 Effect？先选对象再选 accessor
    值会在创建时读取还是执行时读取？只有 `$triggerEffect.params()` 是内建延迟读取
    是否选中了 Entity[]？布尔判断加 `.any/.all`，选目标改 `targetType`
    是否已有 accessor 或 Effect 参数能表达？有则不新增语法
