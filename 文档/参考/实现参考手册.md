# 实现参考手册

本文档记录实现新卡牌/器官/效果时需要了解的关键机制，基于代码实际调查结果。

---

## Effect 拦截机制

每个 ActionEvent 的每个 Effect 在执行前后各有一个触发周期。

源文件：`src/core/objects/game/transaction.ts`

```typescript
private async _applyEffects(event: ActionEvent) {
    for (let effect of event.effects) {
        await effect.trigger("before", 0)  // before 阶段：可以修改 effect.params
        await effect.apply()               // 执行效果函数
        await effect.trigger("after", 0)   // after 阶段：响应已发生的效果
    }
}
```

结论：
  useCard 事件中的 damage effect 执行前，`before make damage` 触发器会触发
  applyState effect 执行前，`before make applyState` 触发器会触发
  不需要显式 doEvent 包装，每个 effectUnit 的执行都有完整触发周期

## $ 引用语法

源文件：
  `src/core/utils/ReferenceResolver.ts`（引用解析主逻辑）
  `src/core/types/EntityAccessor.ts`（accessor 实现表）
  `src/core/types/TargetSpec.ts`（participant/target 键名表）

`$` 是全局统一的引用语法，表示"引用对象/属性"。所有 effect params、condition、triggers.event 定义等含 `$...` 字符串的字段在执行前都会被解析。

### 语法形式全表

```
$eventResult(key)                      → 从当前事件的结果中读取（event.getEventResult(key)）
$event.info(key)                       → 从触发事件的 info 字段读取（event.info[key]）
$triggerEffect.params(key)             → 读取"触发该反应的 Effect"的 params[key]
$triggerEffect.target.<accessor>       → 触发 Effect 对应事件的目标实体上调用 accessor
$triggerCard.<accessor>                → 触发事件的 medium 作为卡牌解读；非卡时静默返回 false
$owner.<accessor>                      → 定义该 EffectUnit 的物品（卡/器官/遗物）自身
$<participant>.<accessor>              → 从任意参与者取值（见下表）
$scene                                 → 当前场景（战斗中返回 "combat"，否则读 room.type）
$battle.turn / $battle.turnCount       → 当前战斗回合数
$<collection>.any.<accessor>           → 集合中至少一个满足（返回 boolean）
$<collection>.all.<accessor>           → 集合中全部满足（返回 boolean）
random(min,max)                        → 随机数（不带 $；整数区间返回整数，否则浮点）
```

注意：语法一律用 **括号** 传参，不是点访问。`status(health)` 正确，`status.health` 错误。

### participant 键名（从 TargetContext 取实体）

单个 Entity：
```
item / owner / source / target
player / enemy / battle / turnNumber
triggerSource / triggerOwner / triggerEffect
eventSource / eventMedium / eventTarget
eventTriggerSource / eventTriggerOwner
```

Entity[] 数组（必须配 `.any` / `.all` 或修饰符 `.random`/`.first`/`.last`）：
```
allEnemies / allAllies / allEntities
```

特殊：`allCardsByKey(cardKey)` 从所有牌堆搜索指定 key 的卡牌，返回 Entity[]。

### accessor 全表（EntityAccessor.ts）

```
status(key)         → entity.status[key].value（永久属性）
current(key)        → entity.current[key].value（当前值，如 currentHp/energy）
hasStatus(key)      → status[key] 存在且 > 0
state(key)          → 返回 State 对象本身（不是层数）
stateStack(key?)    → State 的层数，括号里填的是「状态 key」不是「层 key」
                      stateStack()                  实体本身就是 State 时（如状态自己的 reaction 里 $source 指该状态），读第一个 stack
                      stateStack(charge)            读该实体身上 charge 状态的 default 层
                      stateStack(poison.duration)   点语法读指定层
hasState(key)       → 是否拥有指定状态
hasOrgan(key)       → 是否持有指定器官
hasRelic(key)       → 是否持有指定遗物
hasCard(key)        → 手牌中是否有指定卡
hasTag(key)         → 卡/实体 tags 中含指定 tag
pileCount(pile)     → 牌堆卡数；pile ∈ hand/draw/discard/exhaust
reserve(key)        → ReserveModifier 中的储备资源（如 material）
itemType()          → 物品的 itemType 字符串（potion/relic/card/organ）
isTemporary()       → 实体的 isTemporary 字段是否为 true（临时器官/临时卡等）
stateCategory()     → 用于 Effect：从其 params.stateKey 查 stateList 拿 category（debuff/buff/...）；用于 State：读自身的 category
```

Mod 可通过 `registerAccessor(name, fn)` 注册自定义 accessor。

### lazyResolve 与延迟解析

`$triggerEffect.params(key)` 支持 `lazyResolve`：在 context 中带 `lazyResolve: true` 时，值会**原样返回**（不解析），供 `doEffectFunc` 在真正执行时再解析。用于 accumulateAndTrigger 等"值必须在触发瞬间求"的场景。

### 使用示例

```typescript
// 反应中读取原始伤害值
{ key: "damage", params: { value: "$triggerEffect.params(value)" } }

// 读取自身器官的属性作为伤害
{ key: "damage", params: { value: "$owner.status(atkPower)" } }

// 读取事件目标（如被打的敌人）的当前血量
condition: "$triggerEffect.target.current(health) < 10"

// 条件：所有敌人都持有毒状态
condition: "$allEnemies.all.hasState(poison)"

// 随机数值范围
{ key: "gainArmor", params: { value: "random(3,7)" } }

// 读取遗物身上存的字符串型 status（例如获得时记录的卡牌 __id）
{ key: "retrieveCardsToHand", params: { cardId: "$owner.status(markedCardId)" } }
```

Status 值天然支持 number 或 string（见 `Status._originalBaseValue: ref<number | string>`）。想在物品/器官/遗物身上存一个「后续要读回来」的标识符（卡 __id、目标 id、玩家的选择等），走 status 路径：在 map 里声明 `key: { value: "", hidden: true, display: false, calc: false }`，效果里用 `setOriginalBaseValue(str)` 写入，reaction 里用 `$owner.status(key)` 读回。不要直接给 Entity 加普通字段——那绕过了 Status 系统。

## targetType 选项

在 reaction 的事件定义中使用，由统一解析系统（TargetSpec.ts + resolveTriggerEventTarget）处理：

```
targetType: "triggerOwner"     → 触发该反应的实体（例如有状态的角色）
targetType: "triggerEffect"    → 触发该反应的 Effect 对象本身（用于修改 effect.params）
targetType: "triggerSource"    → 触发来源物品（器官/遗物自身）
targetType: "eventTarget"      → 原始事件的 target
targetType: "eventSource"      → 原始事件的 source
targetType: "owner"            → 拥有该物品（卡牌/器官/遗物）的角色
targetType: "self"             → 物品自身
targetType: { faction: "enemy" }  → 所有敌方存活单位
targetType: { faction: "player" } → 所有玩家存活单位
```

统一解析函数：`resolveTriggerEventTarget(targetType, triggerEvent, triggerEffect, item, owner)`
源文件：`src/core/objects/system/trigger/resolveTriggerEventTarget.ts`

reaction 系统、accumulateAndTrigger 均通过此函数解析 targetType，不要在新效果中手写 switch。

## EffectUnit 的 target（单个效果改打别人）

一次 `use` / `work` 交互里的所有 effect 默认共用同一个事件目标。当其中某个效果要打到别的对象上时，给那条 EffectUnit 加 `target` 字段，它会被当作 targetSpec 解析并作为独立子事件执行。

```typescript
// 放电：伤害打对手，但消耗的充能在使用者自己身上
interaction: {
    use: {
        target: { faction: "opponent" },
        effects: [
            { key: "damage", params: { value: 3, multiplier: "$source.stateStack(charge)" } },
            { key: "removeState", params: { stateKey: "charge" }, target: "source" }
        ]
    }
}
```

可用值同 TargetSpec：`"source"` / `"target"` / `"owner"` / `"player"` / `"allEnemies"` / `"allCardsByKey(xxx)"` 等，
见 `src/core/types/TargetSpec.ts` 的 `TargetTypeString`。

漏写会静默打错人：`removeState` / `applyState` / `gainArmor` 这些都不校验目标身上有没有对应东西，
打空了就是什么都不发生，没有报错。凡是「攻击敌人 + 操作自己身上的状态/资源」的卡，都要检查这一项。

## triggerTarget（触发器挂载目标）

控制触发器挂载到哪个实体上（而非效果目标），用于器官/遗物 possess 交互中。

```
triggerTarget: "player"          → 玩家队伍第一个成员
triggerTarget: "opponent"        → 对手队伍第一个成员
triggerTarget: "allOpponents"    → 所有对手
triggerTarget: "allPlayers"      → 所有存活玩家
triggerTarget: "allEnemies"      → 所有存活敌人
triggerTarget: "randomOpponents" → 随机 count 个对手（需提供 count）
```

统一解析函数：`resolveTriggerMountTargets(spec, owner)`
源文件：`src/core/utils/resolveTriggerMountTargets.ts`

在 TriggerMap（ItemModifier / Organ）和 accumulateAndTrigger 中均通过此函数解析，
新增挂载目标类型只需修改这一处。

triggerTarget 与 targetType 的区别：
  triggerTarget — 触发器挂载位置（谁来响应事件）
  targetType    — 效果施加目标（谁承受效果）

## 卡牌 inHand 交互

卡牌有三种交互在不同时机触发：

possess
  触发时机：卡牌被添加到 CardModifier（通过器官获得、addCardsFromSource）
  触发事件 key："possessItem"
  使用场景：卡牌进入牌库时的一次性初始化

inHand
  触发时机：卡牌被移入手牌堆（drawCard、enterHand 调用时）
  触发事件 key："inHandCard"
  自动清理：卡牌离开手牌时 unmountInHand() 自动移除所有触发器
  使用场景：卡牌在手牌中的持续效果（如孢子牌：在手牌时回合结束加中毒）

use
  触发时机：卡牌被打出时

临时塞入 drawPile 的卡牌（如孢子牌）：
  possess 不触发（因为未经过 CardModifier）
  inHand 在抽到手牌时触发 ✅
  因此孢子牌的回合结束效果通过 inHand 交互实现

## 器官 possess 交互的 cleanup 机制

源文件：`src/core/objects/system/modifier/OrganModifier.ts`

loseOrgan() 调用流程：
  1. removeWorkTriggers() — 移除 work 触发器
  2. removeByItem(organ) — 触发 ItemModifierUnit.cleanup()
  3. ItemModifierUnit.cleanup() — 清理所有副作用（触发器、修饰器等）

结论：在 possess 的 triggers 中注册的触发器，失去器官时自动清理，不需要手动管理。

## StateModifier 公开 API

源文件：`src/core/objects/system/modifier/StateModifier.ts`

```typescript
stateModifier.addState(stateData, stacks, source)
stateModifier.removeState(stateKey, triggerRemoveEffect?)
stateModifier.changeStack(stateKey, stackKey, delta)   // 只改已存在的状态，见下方注意
stateModifier.getState(stateKey): State | undefined
stateModifier.getAllStates(): State[]
stateModifier.hasState(stateKey): boolean
```

注意：`changeStack` 在目标没有该状态时直接返回 false，什么都不做，它只负责改已有层数。
需要「加一个目标可能还没有的状态」时用 `gainStateStack`（`src/core/objects/system/State.ts`）：

```typescript
import { gainStateStack } from "@/core/objects/system/State"

gainStateStack(target, stateKey, delta, source?)   // 没有则按 stateList 创建，有则叠加 default 层
```

它是同步的，加完可以立刻读层数判断阈值。需要被拦截型触发器捕获时改用 `applyState` 效果，
但那是入事务队列异步执行的，同一个 EffectFunc 内后续读到的仍是旧值。

获取 state 的 category（用于判断是否为 debuff）：

```typescript
import { stateList } from "@/static/list/target/stateList"

const state = stateModifier.getState("poison")
// state.key 是状态的 key，在 stateList 中查找 category
const stateData = stateList.find(s => s.key === state.key)
const isDebuff = stateData?.category === "debuff"
```

或直接统计：
```typescript
const debuffCount = stateModifier.getAllStates()
    .filter(s => stateList.find(d => d.key === s.key)?.category === "debuff")
    .filter(s => {
        const stacks = s.stacks.find(st => st.key === "default")?.stack ?? 0
        return stacks > 0
    }).length
```

**在 condition / reference 表达式里判 debuff/buff 走 accessor**：`$triggerEffect.stateCategory() == debuff`（针对触发中的 applyState Effect），不用写命令式 EffectFunc。

```typescript
const actionsStatus = (enemy as any).status["actions-per-turn"]
if (actionsStatus && Number(actionsStatus.value) < 2) {

```

## status 该不该登记进 statusMap

`statusMap` 只登记**系统会读取的属性** —— 核心代码按 key 取值的，或者需要 `notNegative`
这类行为配置的。判断标准不是"重不重要"，而是"有没有跨内容复用的语义"：

```
登记      max-health / max-energy / max-potion    核心代码按 key 读
          cost / draw-per-turn                    同上，且需要 notNegative
          cannot-play / retain-on-turn-end / disabled   系统行为开关
          action-order / ifBloodMark / hungry-beast-*   系统读取的计数与标记

不登记    damage / armor / times / weakStacks     卡牌与器官上的数值参数
```

卡牌参数是内容数据，每张卡自己定义就够了。全塞进注册表只会让它越来越长且永远补不齐 ——
`weak`/`vulnerable` 一度登记了，但同样是卡牌参数的 `armor`/`damage`/`times` 从来没有，
反而制造了"注册表就该收录所有属性"的错觉。

未登记的 key **照样能正常创建 Status**，只是拿不到 label 和 notNegative。不要为了让某个
卡牌参数"合法"而去注册表补一条。

## 卡牌数值参数的命名

按**它是什么**命名，不按**目标 state 叫什么**命名：

```
施加层数   <stateKey>Stacks     weakStacks / vulnerableStacks / forceFieldShieldStacks
伤害       damage
护甲       armor
次数       times
```

不要直接用 state 名当 key（`weak: 2`、`vulnerable: 2`、`forceFieldShield: 2`）：key 与 State key
同名会让人误以为"这张卡自带该状态"，实际它只是"施加几层"的参数。

也不要用无前缀的 `stacks`：一张牌施加两种 debuff 时就不够用了，会退化成"单个用 stacks、
多个用具名"的分叉规则，而且卡牌从单 debuff 改成双 debuff 时还得重命名。

```typescript
// 装甲组装：自己获甲 + 给对手上易伤
status: { cost: 1, armor: 15, vulnerableStacks: 1 }
```

注意现存卡牌尚未统一到这套命名，`weak: 2` / `stacks: 2` / `vulnStacks: 1` 几种写法都还在，
新写的内容按上面这套来。

## cost: null（"这张牌没有费用概念"）

需求：无费用的诅咒/状态牌（伤口、悔恨、受伤、疑虑）不该在卡面上画费用框，但费用为 0 的牌要显示 "0"。

约定：

```
cost: 0      有费用，只是免费     卡面显示 "0"
cost: null   没有费用这个概念     卡面不画费用框
```

不要用 `-1` 之类的哨兵值表达"无费用"。`cost` 在 statusMap 里声明了 `notNegative`，
将来该选项被实现时负值会被钳成 0，哨兵约定当场失效；负费用漏进 `payEnergy` 还会变成加能量。

也不要改成"不定义 cost 属性"：cost 是卡牌的固有结构，属性照常创建，只是值为 null。

```typescript
export const injuryCard: CardMap = {
    label: "受伤",
    tags: ["curse"],
    entry: ["card_cannot_play"],
    status: { cost: null },
    key: "sts_card_injury",
    interaction: {}
}
```

与 `cannot-play` 的分工（两者互相独立，不能互相推导）：

```
cost: null      这张牌本质上没有费用      → 卡面不画费用框
cannot-play > 0  这张牌当前不能被打出      → 走禁用样式，费用照常显示
```

所以「一张 2 费牌被运行时挂上 cannot-play」时费用仍然显示 2，不会因为暂时打不出就把费用藏掉。
无费用的诅咒牌通常两者都有，但那是数据同时声明的结果，不是其中一个推出来的。

判断卡面是否画费用要用 `cost !== null`，**不能用真值判断** —— `v-if="cost"` 会把 0 费牌当成无费用。

## disabled 语法糖（"物品失效但仍占栏位"）

需求：某个遗物/物品在满足某条件后永久失效但不能自动移除（比如次数耗尽、条件破坏、跨战斗持续）时，用通用 status `disabled` 作短路开关，不要新起一个物品专属字段。

约定：

```
statusMap 中已注册 "disabled"：
    category: "special"
    hidden: true       避免在面板显示"已失效: 1"
    notNegative: true  防止减多次跑到负值
```

用法：

```typescript
// relic 数据：初始 disabled=0
status: { "battles-remaining": 3, "disabled": 0 }

// 触发器上加 condition，disabled>0 时短路（触发器仍挂着，但不进入 reaction）
triggers: [
    {
        when: "after", how: "take", key: "battleStart", level: 1,
        condition: "$source.status(disabled) == 0",   // 短路条件
        action: "grantBlessing"
    },
    {
        when: "after", how: "take", key: "battleStart", level: 0,
        condition: "$source.status(battles-remaining) <= 0",  // 满足失效条件
        action: "markDisabled"
    }
]

// reaction 里翻牌
reaction: {
    markDisabled: [{
        targetType: "triggerSource",
        key: "markDisabled",
        effect: [{ key: "setBaseStatus", params: { statusKey: "disabled", value: 1 } }]
    }]
}
```

两个触发器都挂在同一个 key + how 上，用 level 排序（先做主逻辑再检查是否耗尽）。别把"失效判定"塞进主 action 里，那样跨战斗读取时序会混乱。

参考实现：`relic_god_of_chance_blessing`（无常之神的祝福，3 场战斗后失效）
场景手册：`文档/开发指南/场景手册/遗物实现场景手册.md` 场景 13

```typescript
{
```

## Effect 拦截模板（剧毒心核：中毒+1）

```typescript
// 器官 possess 触发器：拦截 applyState effect
triggers: [{
    when: "before",
    how: "make",
    key: "applyState",
    action: "poisonAmplify"
}],
reaction: {
    poisonAmplify: [{
        key: "poisonAmplify",
        label: "剧毒心核：中毒+1",
        targetType: "triggerEffect",  // target 是 applyState Effect 对象
        effect: [{ key: "organ_poisonAmplify", params: {} }]
    }]
}

// EffectFunc
export const organ_poisonAmplify: EffectFunc = (event, _effect) => {
    const target = event.target
    if (Array.isArray(target) || !isEffect(target)) return false
    if (target.key !== "applyState") return false
    if (target.params.stateKey !== "poison") return false
    target.params.stacks = Number(target.params.stacks || 1) + 1
    return true
}
```
