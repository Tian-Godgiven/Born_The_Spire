# 字段值枚举手册

跨内容列表的"魔法字符串"清单。做新内容前先在这里比对，别把已有枚举拼错、也别引入新变体。

调查时间：2026-07-15（Phase 2 完成时快照）

## rarity（稀有度）

只有以下几类内容用了 rarity：

    relicList     37 条带 rarity，取值：common / uncommon / rare
    cardList      5 条带 rarity，取值：uncommon（其余卡牌未设 rarity 字段）
    potionList    0 条带 rarity（所有药水都无 rarity 字段）
    organList     未使用
    enemyList     未使用

推论

    按 rarity 过滤 potion 目前一定空。`gainRandomPotion({rarity})` 已加兜底：过滤空则退回全池并 newLog 警告
    同理 `gainRandomRelic({rarity})` 也有兜底
    等 potion / card 补齐 rarity 字段后，过滤自动生效，无需改代码

新增内容时的约定值

    common / uncommon / rare 三档
    别引入 "normal" "epic" "legendary" 等新词——除非确认要扩展整套体系

显示名字和颜色走 `src/static/list/system/rarityPalette.ts`

    getRarityLabel(rarity)  普通 / 罕见 / 稀有
    getRarityColor(rarity)  #333333 / #2d5016 / #1a3a6b（白底）
    不要在组件里再写一份对照表

## 卡牌 tags

已在 cardList 中出现的 tag：

    attack        攻击卡
    skill         技能卡
    power         能力卡（一次性效果+持续被动）
    curse         诅咒卡（当前只有 1 张：虚弱诅咒）
    status        状态牌（不可打出的负面牌）
    basic         初始牌
    defence       防御类（与 skill 常并列）
    multiHit      多次打击
    enemy         敌人牌（不进玩家卡组）
    fallback      降级牌
    test          测试用

推论

    "curse" 是唯一诅咒标签，`gainRandomCard({tags:["curse"]})` 现在只会给虚弱诅咒
    "enemy" 标签的牌不该被 gainRandomCard 抽到；若未来加"仅玩家可获得"的筛选，考虑在 gainRandomCard 里默认排除 enemy tag

## 器官 tags

统一走 `OrganTags` 常量（`src/static/list/target/organTags.ts`），不要写裸字符串：

    CURSED           "cursed"        诅咒
    CANCER           "cancer"        癌变
    STARTER          "starter"       初始
    UNIQUE           "unique"        唯一
    TEMPORARY        "temporary"     临时
    FRAGILE          "fragile"       脆弱
    INDESTRUCTIBLE   "indestructible" 不朽
    SYNTHETIC        "synthetic"     合成
    MUTATED          "mutated"       变异

## targetType（卡牌/触发效果 target 指向）

按使用场景分为两组：

卡牌内 use.target
    player / enemy / self / all / opponent
    也可用对象形式 `{faction: "player", key: "self"}` 精确指定

触发器 reaction 里的 targetType
    owner           触发器主体自身
    target          事件的 target
    triggerSource   事件的 source
    triggerOwner    触发器所有者
    triggerEffect   触发的 effect 本身
    item            物品/器官/遗物自身
    pickedTargets   同一次 reaction 数组里已经 .random 抽中的实体（未写 as 时的默认袋）
    allEnemies.random  所有敌人中随机一个

管道修饰符（从左到右，except 作用在数组上所以写在 random 前面）
    .except(T)  从数组去掉 T；T 是任意 targetType（owner / pickedTargets / as 的名字）
    .random     从数组随机抽一个，抽中的实体写入 pickedTargets
    .first / .last

    allEntities.except(pickedTargets).random
    场上全体里再抽一个，排除本轮已抽中的

可选 as
    reaction 单条可写 `as: "hurt"`，把解析结果放进本次 context
    后面可以用 targetType: "hurt" 或 except(hurt)
    不需要回头点名时不必写 as，except(pickedTargets) 就够

群体 targetType 分两套，**器官/遗物这类敌我都可能持有的内容必须用相对阵营那套**：

    相对持有者阵营（推荐）
        allOpponents    持有者的对手全体
        allTeammates    持有者的己方全体
        按 context 里的 owner / triggerOwner 判断阵营，同一份数据装在玩家或敌人身上行为一致

    写死玩家视角（只适合确定站在玩家一侧的内容）
        allEnemies      敌人全体
        allAllies       玩家队伍
        allEntities     场上全体
        allAllies 解析成 `battle.getTeam("player")`，与持有者无关。
        敌人器官图省事用它曾经是对的（敌人的对手就是玩家），玩家捡到同一个器官后就会把效果打在自己身上

## faction（阵营）

    player     玩家方
    enemy      敌人方
    opponent   对手方（相对当前实体）
    all        全体（可选阵营不限）。默认仍要点选 1 个；打全体再写 `number: "all"`

    器官 `interaction.break` 的 target.faction 与此相同。要对持有者的对手生效写 `opponent`（现行：孢子囊），不要写死 player / enemy
    卡牌 `target: { faction: "all" }` 是点选任意角色（现行：修复）；`{ faction: "all", number: "all" }` 才是打全体（现行：毒孢）

## 通用系统 status（跨内容常用键）

不属于某个具体物品/器官/遗物专属的、被多个系统或语法糖共用的 status 键。加新内容时想引入类似机制先在这里比对：

    disabled           大于 0 时物品被视为"失效但仍占栏位"；触发器加 condition `$source.status(disabled) == 0` 即可短路
                       定义在 statusMap，category=special / hidden=true / notNegative=true
                       使用示例：无常之神的祝福（`relic_god_of_chance_blessing`），战斗次数用尽后 setBaseStatus 为 1
                       场景参考：`文档/开发指南/场景手册/遗物实现场景手册.md` 场景 13

    cannot-play        大于 0 时该卡无法主动打出；`CardModifier.canPlayCard` 据此拒绝
                       定义在 statusMap，category=card / hidden=true
                       语法糖：卡牌 `entry: ["card_cannot_play"]`
                       只表示"当前打不出"，不表示"没有费用"——见下面 cost 一条

## pool（抽选池）

物品（卡牌 / 遗物 / 药水 / 器官）的 `pool` 字段决定它出现在哪些随机池里。**未定义等于 `["common"]`**，
也就是说不写 pool 的内容会进通用池，能被战斗奖励、商店、收藏家附赠等抽到。

已出现的取值

    common      通用池，未定义 pool 时的默认值
    event       事件专属，只由对应事件给出（现行：合子～神经胚）
    exclusive   器官专属卡，不进任何随机池，只能由对应器官提供
    test        测试用内容，不进随机池（终结一击 / 秒杀 / 永生 / 无敌）
    shop        商店池
    boss        Boss 奖励池

新增内容时的约定

    做测试用卡牌/遗物一定要写 `pool:["test"]`，否则会污染战斗奖励，测试期满屏都是它
    器官专属卡写 `pool:["exclusive"]`
    只由事件给出的器官写 `pool:["event"]`，否则会被收藏家附赠、黑市等当普通货抽到
    正常可获取的内容不写 pool 即可

## 动画 category（动画类别）

`AnimationDefinition.category` 决定这个动画归到设置面板的哪一行开关下。取值来自动画类别注册表
（`src/ui/animation/categories.ts`），内置六类：

    hit       受击表现（白闪、震动）
    hitText   伤害跳字
    heal      治疗表现
    death     死亡演出
    card      卡牌演出
    ui        界面通用（淡入淡出、弹出、脉冲）

不填 category 的动画不受任何开关管辖、永远播放。Mod 可以用 `registerAnimationCategory` 注册新类别，
设置面板会自动多出一行。

## status 值为 null 的语义

status 值除了 number / string，还可以是 `null`，表示"该实体没有这个属性的概念"，与 0 严格区分：

    cost: 0      这张牌有费用，只是免费    卡面显示 "0"
    cost: null   这张牌没有费用这个概念    卡面不画费用框

目前的使用者是无费用的诅咒/状态牌：伤口（`original_card_00100`）、悔恨 / 受伤 / 疑虑
（`mods/slayTheSpire/cards/curse.ts`）。属性本身照常创建，只是值为 null。

不要用 `-1` 之类的哨兵值替代，也不要改成"不定义该属性"。判断时用 `!== null`，不能用真值判断
（`0` 会被误判成无费用）。详见 `文档/参考/实现参考手册.md` 的「cost: null」一节。

新增此类 status 时的约定：

    只有系统会读取的属性才收进 statusMap（卡牌/器官上的数值参数放到内容自身 status 字段就行，
    未登记的 key 照样能创建 Status，只是拿不到 label / notNegative）
    notNegative=true 防止减多次跑到负值，钳 baseValue / value 两层，不动 originalBaseValue
    hidden=true 目前只赋值到 Status 实例、没有读取方，登记了也不会真的隐藏
    category 纯归类用途，Status 类没有对应字段

## 扣血效果 key

三条并列，别混用：

    attack        挨打。攻击卡、器官砸、遗物投。石肤、护甲、力量、虚弱、飞飘、飞行挂这里
    damage        受伤但不是挨打。中毒、自残、爆炸自伤
    loseHealth    付生命。事件扣血、卡牌生命费。护甲 / 石肤 / 受伤触发器都不理它

「受到伤害时」监听 `["attack", "damage"]`。打人不要写 `damage`。不要让 `attack` 再 spawn 一层 `damage`。

## 战斗 encounterPool

    easy      弱怪池。本层前 N 场（默认 3）实际进入的普通战斗从这里抽
    normal    省略或显式 normal，进普通战斗池。第 4 场起只用这个池

精英 / Boss 用 battleType，不要标 encounterPool。测试战斗标 `test: true`，两边自动池都不进。

## uiSize（敌人战斗卡片尺寸）

写在 `battleList` 的 `enemyConfigs` 实例上，不是 enemyList 的物种默认。取值：

    small     140×210。本场需要缩小的那只才写
    normal    200×300。省略字段就是这一档
    big       260×390。Boss / 大体型

别写成 mini / tiny / huge / large。玩家卡片不走这个字段。不要按场上人数自动缩小。

队伍整体垂直居中，成员按血条底边对齐。不要改阵营 gap（固定 66px）。

现行用法：三人场（蚁穴、废堆角落、蚁后阵线）里的蚁兵标 small。三场一层 Boss 标 big。

## rarity 与阶层的补齐建议

如果后续想让所有随机池都能按 rarity 走：

    potionList  给每个 PotionMap 补 rarity 字段（common/uncommon/rare）
    cardList    只有初始牌/非 curse 非 enemy 的可获取牌需要 rarity；补的时候只覆盖玩家可获得的池

## 何时更新本手册

    加入新的 tag / rarity 分类
    引入新的 targetType 值
    某个 pool 的枚举范围扩大
    新增动画类别（category）
    扣血线（attack / damage / loseHealth）语义变化
    战斗 encounterPool（easy / normal）语义变化
    敌人 uiSize（small / normal / big）语义变化

改数据时顺手看一眼这里；新增值直接补，删除的记得从这里去掉。
